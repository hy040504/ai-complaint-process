작성 기준: 2026-10-24 UTC. 이 문서는 다음 작업의 순서와 완료 조건을 정의한다. 아래 미구현 항목의 완료나 추가 모델 선택을 선언하는 문서는 아니다. 기본 작업 규칙은 [AGENTS.md](../AGENTS.md), 상세 계약은 [하네스 문서](../docs/harness/README.md)를 따른다.

## 현재 기준점

원본 두 JSON, 부서 정규화, PostgreSQL/pgvector, 한국어 BM25, RRF, 재정렬, 검색 CLI/API, 기본 테스트와 보고서가 있다. 작업 규칙·구조·데이터 계약·판정 초안·평가·운영 문서를 연결했고, 전체 문서 목차와 변경 이력으로 진입점을 정리했다.

다음 완료 대상은 **FAQ 답변 / 부서 추천 / 담당자 검토를 보여 주는 CLI 챗봇**이다. 웹 목업은 그 다음이다. 실제 접수·이관 연계는 별도 범위로 남긴다.

## 실행 순서와 완료 조건

| 순서 | 작업 | 산출물·완료 조건 | 상태 |
| --- | --- | --- | --- |
| 1 | 기준 데이터·평가 라벨 준비 | 시연용 FAQ의 현행성·적용 조건, 부서 후보의 검증 상태, 한국어 개발/보류 평가셋 기록 | 미구현 |
| 2 | 판정 모델 어댑터 | 동일 입력/출력 계약, 한국어 원문 처리, 스키마 검증, 모델 실패 대체 결과 | 미구현 |
| 3 | 정책 검사·FAQ 응답 연결 | 실제 조치와 안내 구분, 후보 ID 대조, FAQ 출처·조건 유지, 근거 없으면 사람 검토 | 미구현 |
| 4 | CLI 챗봇 | 세 결과와 이유·출처 표시, 종료·오류 처리, 실제 이관과 시연 구분 | 미구현 |
| 5 | 평가 자동화·관측 | 설정별 결과 비교, 요청별 지연·실패·정책 버전 기록, 개인정보 제외 | 미구현 |
| 6 | 웹 목업 | CLI와 같은 판정 로직 사용, 입력·대기·답변·추천·오류 상태 표시 | 미구현 |

순서 1과 2의 준비는 함께 진행할 수 있다. 평가 라벨과 정책 계약 검증은 CLI 완료 전에 필요하다. 문서 초안만으로 특정 판정 모델이나 임계값을 확정하지 않는다.

## 우선 처리할 구체적 과제

**데이터:** 현재 업무분장이 미검증인 127개 부서를 모두 검증했다고 간주하지 않는다. 우선 시연 범위부터 공식 근거를 기록하고, 미래산업과 계열 10건·과거 안전정책과 17건의 대응은 건별로 검토한다. FAQ 현행성 기록은 원문 해시와 연결해 내용 변경 시 다시 확인할 수 있게 설계한다.

**판정 모델:** 무료 후보를 같은 한국어 평가셋·검색 근거로 비교한다. 기존에 검토한 OneJev/OpenJev 등의 이름만으로 호환성·한국어 성능을 가정하지 않는다. 사용할 모델의 정확한 저장소·리비전·라이선스·출력 형식을 선택 시점에 확인한다. 모델별 점수나 confidence를 같은 의미로 강제 변환하지 않는다.

**평가 하네스:** 현재 10개 검색 예제를 유지하며 별도의 판정 평가 러너를 만든다. 특히 FAQ와 단어가 같지만 실제 조치를 요구하는 민원, 구별 관할, 데이터 밖의 민원, 잘못된 구조화 출력과 시간 초과를 포함한다. 목표 오류율·지연·커버리지는 기준 성능을 측정한 뒤 정하고 보류 평가셋으로 확인한다.

**개발 자동화:** 가벼운 코드·격리 DB 검증부터 CI로 연결하고, 모델 다운로드·전체 임베딩·장시간 검색 평가는 별도 작업으로 분리한다. 현재 GitHub Actions는 구성되어 있지 않다. 유료 실행 자원 도입을 전제로 하지 않는다.

**운영 재현성:** 코드·원본 해시·모델·정책·평가셋 버전을 묶어 실행 기록을 남긴다. 현재 Compose는 코드 디렉터리를 읽기 전용으로 마운트하는 개발 방식이다. 공개 서비스 전환 전에는 배포 버전 고정, 접근 제어, 요청 제한, 백업 복원 연습을 별도 과제로 다룬다.

## 결정 기록

| 항목 | 상태 | 내용 |
| --- | --- | --- |
| 데이터 역할 | 확정·구현 | FAQ는 안내, 사례는 부서 추천, directory는 부서 검증 정보 |
| 검색 방식 | 확정·구현 | pgvector + Kiwi BM25 + RRF + 재정렬, 컬렉션별 검색 |
| 검색과 최종 판단 분리 | 확정·검색 계약 구현 | 현재 결과는 `requires_gate`; 후속 판단은 별도 |
| 입력 언어 | 확정 | 한국어 직접 입력 우선, Papago는 추후 비교 |
| 모델 비용 | 선호 확정·모델 미선정 | 무료 로컬 모델 우선 검토 |
| 시연 순서 | 확정 | CLI 챗봇 → 웹 목업 |
| 부서 구분 | 확정·구현 | 확인된 별칭 통합, 구별 동명 과 유지, 미확인 부서는 검토 |
| 판정 출력 스키마 | 이번 문서의 제안 | `faq_answer / department_suggestion / human_handoff` |
| 답변 모델·임계값·시간 제한 | 미정 | 평가와 자원 측정 후 결정 |
| 실제 행정 이관 | 별도 범위 | 초기 MVP에서 완료된 이관으로 표시하지 않음 |

새 결정을 할 때는 날짜, 근거, 바뀌는 계약, 검증 결과를 이 기록과 해당 문서에 남긴다. 기존 방향을 바꾸지 않는 구현 세부 사항은 작업자가 정하고 기록한다. 모델·정책을 확정하는 데 사용자 선택이 필요한 항목만 구체적인 비교 결과와 함께 제시한다.
