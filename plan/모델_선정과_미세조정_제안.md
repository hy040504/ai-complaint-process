# LLM + RAG 모델 선정과 미세조정 제안

[프로젝트 소개](../README.md) · [우선 구현 계획](언어모델과_검색증강생성_우선_구현계획.md) · [판정 정책](../docs/harness/decision-policy.md) · [평가 기준](../docs/harness/evaluation.md)

조사·작성 기준: **2026-10-25 UTC**. **초기에는 Jev 없이 LLM + RAG를 구현한다**는 사용자 요구에 맞춰 이전 모델 제안을 재구성했다. 후보 모델을 설치·실측하거나 최종 선정한 문서가 아니다. 공개 모델 자료에서 확인한 사실과 이 프로젝트를 위한 실험 제안을 구분한다.

## 추천하는 출발점

**Qwen3.5-4B 하나로 구조화 판정과 FAQ 답변을 수행하는 구성을 첫 비교 기준으로 추천한다.** 처음에는 추가 학습 없이 기존 RAG를 연결한다. 같은 모델을 판정과 생성에 따로 호출하고, 그 사이에 코드의 정책 검사를 둔다.

자원을 확보하면 Qwen3.5-9B와 비교한다. 한국어 중심 대안인 Kanana-2-3B-Instruct, 다른 계열인 Gemma 4 E4B-it은 오류 유형과 배포 조건에 따라 비교 범위를 넓힐 후보다. OneJev·OpenJev·공식 Jev는 초기 모델 선정 대상에서 분리해 후속 확장 후보로 둔다.

무료 우선은 외부 추론 API 요금 없이 로컬 모델을 사용하는 방향이다. GPU·전력·운영 비용까지 없어지는 것은 아니다. 모델 선택과 별개로 한국어 직접 입력을 유지하고 Papago는 추후 비교한다.

## 프로젝트 상태가 선택에 미치는 영향

| 확인한 상태 | 모델·학습 선택에 미치는 영향 |
| --- | --- |
| FAQ 94건·사례 5,015건, 관계형/벡터 DB와 검색 CLI/API 구현 | 검색 기반을 재사용하고 판정·응답 연결부터 개발 |
| FAQ 현행성 검증 기록과 부서 127개의 공식 업무분장 검증 미완료 | 큰 모델이나 학습으로 검증된 사실을 대신하지 않음 |
| 현행 부서별 사례 집계에서 61개 부서가 5건 미만, 28개가 1건 | 127개 부서를 직접 분류하도록 학습하기보다 검색 후보를 검토 |
| 현행 부서 불명 27건, 요지 누락 58건, 과거 답변 누락 101건 | 원본 전체를 동일 품질의 학습 정답으로 취급하지 않음 |
| 자동 안내/실제 조치/담당자 검토의 검수 라벨 없음 | 평가셋과 실패 분석을 학습보다 먼저 준비 |
| CPU 검색·재정렬에도 지연 발생 | 검색·판정·생성·대기를 나눠 측정 |
| 시연 웹은 민원 게시판·작성 페이지와 민원 교환 서버까지 구현 예정 | 동일 AI 계층을 재사용하고 등록 저장·AI 처리·담당자 답변 상태를 나눠 검증 |

데이터 건수와 부서별 집계는 2026-10-25 로컬 JSON 및 검색 상태 조회 기준이다. 누락 집합은 겹칠 수 있다. 기존 10개 검색 예제 통과는 LLM 자동 안내 정확도의 평가가 아니다.

웹·민원 서버의 상세 범위는 [구현계획](시연_웹_게시판과_민원_서버_구현계획.md)에 있다. AI 장애에도 저장된 민원을 보존하고 사람 답변을 이어가는 경로를 마련한다. 게시판 저장·답변 기능의 구현 여부와 모델의 자동 안내 정확도를 별도로 확인하며, 새 민원을 자동 학습·RAG 적재하는 범위로 확대하지 않는다.

## 초기 LLM 비교 후보

아래 추천 순서는 프로젝트 적합성에 대한 제안이다. 한국어 청주 민원에서 실측한 성능 순위가 아니다.

| 우선순위 | 정확한 모델 | 제안 역할·선택 이유 | 라이선스·한계 |
| --- | --- | --- | --- |
| 1 | [Qwen/Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B) | 소형 모델 하나로 판정·FAQ 생성을 시험하는 첫 기준 | Apache 2.0. 복합 조건·예외를 별도 평가 |
| 2 | [Qwen/Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B) | 같은 계열에서 모델 크기 증가의 효과 비교 | Apache 2.0. 메모리·지연 증가에 비해 오류가 줄어드는지 확인 |
| 3 | [kakaocorp/kanana-2-3b-instruct](https://huggingface.co/kakaocorp/kanana-2-3b-instruct) | 한국어 토큰화와 한국어 평가를 명시한 소형 대안 | Kanana Open License. 배포 방식에 따른 조건 확인 |
| 4 | [google/gemma-4-E4B-it](https://huggingface.co/google/gemma-4-E4B-it) | 다국어 모델을 다른 계열에서도 비교 | Apache 2.0. E4B는 실효 규모이며 임베딩 포함 약 8B로, 일반 4B와 같은 메모리로 가정하지 않음 |

Qwen 공식 문서는 텍스트 전용 실행과 `enable_thinking=false` 설정을 설명한다. 첫 실험은 긴 추론 생성을 끈 설정을 기준으로 삼고, 필요한 경우 추론 모드와 품질·시간을 비교한다. 실제 옵션 지원은 선택한 엔진 버전에서 검증한다. [Qwen 실행 설명](https://huggingface.co/Qwen/Qwen3.5-9B)

Kanana-2 라이선스는 자체 서비스 사용과 특정 제3자 제공을 구분한다. API 접근 제공, SI·온프레미스 솔루션 등에는 별도 상업 라이선스 조항이 있고 표시 의무도 있다. 향후 기관 납품 형태를 고려해 선택하며, Kanana 1.5의 Apache 2.0 조건을 Kanana-2에 그대로 적용하지 않는다. [현재 라이선스 원문](https://huggingface.co/kakaocorp/kanana-2-3b-instruct/blob/main/LICENSE)

공개 벤치마크나 다국어 지원 표기는 후보 선정의 참고 자료다. 한국어 민원 자동 안내 정확도나 공공 업무 적합성을 증명한 결과로 사용하지 않는다.

## 초기 실행 설정 제안

| 항목 | 제안 |
| --- | --- |
| 모델 수 | 범용 LLM 하나. 기존 BGE-M3·재정렬 모델은 검색 계층에 유지 |
| 호출 방식 | 판정 1회 → 코드 검사 → FAQ 안내가 허용된 경우 같은 LLM으로 생성 1회 |
| 문맥 | FAQ 전체 조건과 사례 요지·후보 부서 상태를 구분해 전달; 전체 JSON을 한 번에 넣지 않음 |
| 후보 범위 | FAQ 상위 1~3건·중복을 줄인 사례 3~5건부터 비교; 정답 누락은 평가에서 확인 |
| 문맥 한도 | 8K 토큰 내외를 초기 실험 예산으로 검토; FAQ 조건을 중간에서 자르지 않고 후보 수를 조정하거나 판단 보류 |
| 출력 | 판정 JSON과 답변을 분리하고 생성 길이에 상한을 둠; 한도 도달·불완전 출력도 실패로 검사 |
| 양자화 | 제한된 자원에서는 지원되는 4비트 실행부터 검토, 여유가 생기면 상위 정밀도와 품질 비교 |
| 실행 환경 | 검색 API 프로세스와 분리한 로컬 LLM 서버; 모델 리비전·엔진·양자화 파일 출처 고정 |
| 신뢰도 | LLM 자기 보고 점수와 검색 유사도를 자동 응답 정답 확률로 해석하지 않음 |

2026-10-25 점검 시 서버는 RTX 3090 24GiB 두 장이며 여유 메모리는 약 6.9GiB·4.6GiB였다. 이는 다른 작업이 실행 중인 시점의 관측값이며 예약된 자원이 아니다. 4비트 모델도 가중치 외에 문맥 캐시·작업 메모리를 사용하므로 실제 적재와 최대 입력의 메모리를 측정해야 한다. 9B 비교와 학습은 충분한 자원을 확보한 뒤 진행한다.

현재 RAG는 `transformers==4.57.3`을 사용한다. 새로운 모델을 연결할 때 검색 환경을 일괄 업그레이드하지 않고, 해당 아키텍처와 구조화 출력을 지원하는 별도 엔진 버전을 확인·고정한다. vLLM 등의 JSON Schema 제한은 형식을 돕지만 판단의 사실성까지 보장하지 않는다. [vLLM 구조화 출력](https://docs.vllm.ai/en/latest/features/structured_outputs/)

## 평가 실험과 선택 기준

첫 비교는 **추가 학습 없는 LLM + 현재 RAG**다. 모델 비교 때는 같은 한국어 질문·검색 결과·근거·출력 계약을 사용하고 모델별 프롬프트 조정은 개발셋에서만 한다. 후보가 모두 같은 프롬프트에 최적이라고 가정하지 않되 조정 범위를 기록한다.

| 실험 | 구성 | 목적 |
| --- | --- | --- |
| 기준 | Qwen3.5-4B + RAG, 추가 학습 없음 | 오류·안내 비중·지연의 출발점 확보 |
| 크기 비교 | Qwen3.5-9B + 같은 RAG | 큰 모델의 실질 개선과 비용 확인 |
| 계열 비교 | Kanana-2 또는 Gemma 4 + 같은 RAG | 한국어 조건 해석·안내 품질 비교 |
| 후속 학습 비교 | 선정 LLM의 LoRA 적용 전/후 | 특정 반복 오류 개선 및 회귀 확인 |
| 후속 Jev 비교 | 선정 LLM + RAG와 Jev 추가 구성을 비교 | 판단 대체·추가 검토의 효과 확인 |

LoRA와 Jev를 동시에 처음 적용하지 않는다. 각각의 변화가 어떤 개선·악화를 만들었는지 알 수 있도록 한 번에 한 축을 비교한다. 평가셋·러너는 아직 없으며 기존 검색 평가와 별도 구축한다.

초기 비교용 **400문항**을 제안한다. 개발용 약 200문항과 보류 평가용 약 200문항으로 나누되 아래 비중과 원문별 그룹 분리를 우선한다. 정확한 최종 수는 검수와 그룹 크기에 맞춰 조정한다.

| 유형 | 제안 수량 |
| --- | ---: |
| FAQ로 충분히 안내 가능한 질문 | 120 |
| FAQ와 주제는 같지만 실제 조치를 요구 | 80 |
| FAQ에 없는 조건·예외 | 60 |
| 부서 후보·지역 구분 | 60 |
| 데이터 범위 밖·불명확·복합 | 80 |

FAQ 현행성과 적용 조건, 허용 부서, 담당자 검토 필요 여부는 사람이 확인한다. 업무분장이 미검증인 사례에 확정 부서 정답을 부여하지 않는다. 같은 원문의 표현 변형·유사 중복은 `group_id`로 묶어 분할하며, 보류 질문·라벨을 학습이나 프롬프트 수정에 사용하지 않는다. 검색 지식베이스에는 정답 근거 문서가 있어도 된다.

핵심 지표는 오답 자동 안내율, 실제 조치 요청을 안내로 끝낸 비율, 출처·조건 보존, 안내 비중, 검증된 부서 후보 Hit@1/3, 전체 응답 p50/p95와 실패율이다. 모든 요청을 담당자에게 넘기는 모델이 유리해지지 않도록 오류율과 안내 비중을 함께 비교한다. 문항 수·오류 건수·분모를 같이 보고하며 소규모 평가로 운영 정확도를 확정하지 않는다. [세부 정의](../docs/harness/evaluation.md)

## LoRA가 필요한지 판단하는 방법

현재 추천은 **추가 학습 보류**다. 다음과 같이 실패 원인을 먼저 분리한다.

| 실패 원인 | 먼저 할 일 | 이후 학습 검토 |
| --- | --- | --- |
| 정답 문서가 검색되지 않음 | 검색 본문·대표 질문·후보 수·재정렬 점검 | 검색용 학습은 별도 평가 후 |
| FAQ의 내용·현행성이 부족 | 공식 자료 보완·검증 기록 | 사실 갱신을 LoRA로 대체하지 않음 |
| 현재 담당 부서·관할 불명 | 부서 사전 검증 | 미검증 부서명을 정답으로 학습하지 않음 |
| 잘못된 JSON·허용되지 않은 값 | 구조화 출력·파싱·코드 검사 | 형식 문제만으로 학습을 시작하지 않음 |
| 정보 문의와 조치 요청을 반복해서 혼동 | 판정 기준·개발셋 예시 보완 | 계속 실패하면 판정 SFT 후보 |
| 근거 없는 단정·조건 누락이 반복 | 근거 제시·필수 조건·보류 기준 개선 | 검수한 근거 포함 예시로 SFT 후보 |
| 말투·길이가 부적절 | 프롬프트·답변 형식·템플릿 수정 | 반복 비용이 클 때 학습 검토 |

LoRA는 기본 가중치를 고정하고 작은 추가 가중치를 학습한다. QLoRA는 4비트로 유지한 기본 모델 위에서 LoRA를 학습해 메모리를 줄이는 방법이다. 추론용 양자화 파일을 설치하는 것과 추가 학습을 수행하는 것은 다르다. [LoRA 논문](https://arxiv.org/abs/2106.09685), [QLoRA 논문](https://arxiv.org/abs/2305.14314)

### 학습을 시작한다면 만들 데이터

두 JSON 원문 전체를 `민원 → 과거 답변`으로 바꾸어 일괄 학습하지 않는다. 94개 FAQ의 표현만 대량 복제하거나, 개편 전 부서·과거 처리 결과를 현재 정답으로 외우게 하는 데이터도 피한다.

학습 단위는 **민원 + 검색된 근거 + 적용 조건·검증 상태 → 처리 경로 + 근거 ID + 필요할 때 검수된 답변**이다. 안내 가능한 예시뿐 아니라 실제 조치, 비관련 근거, 빠진 조건, 잘못된 전제, 불명확한 지역, 복합 요청을 포함한다. 원문 해시·검수 상태·그룹 ID를 보존한다.

| 대비할 예시 | 기대 행동 |
| --- | --- |
| “불법주정차 신고 방법을 알려주세요.” | 검증된 FAQ가 적용되면 안내 |
| “집 앞 차량을 지금 단속해 주세요.” | 실제 조치 경로 |
| “신고 방법도 알려주시고 단속도 해주세요.” | 복합 요청, 전체 해결로 표시하지 않음 |
| “FAQ에 없는 예외 조건에서도 가능한가요?” | 근거가 부족하면 담당자 확인 |

검수된 1,000~3,000건을 첫 학습 실험 규모로 제안한다. 필수 최소량이나 성공 보장은 아니다. 합성 예시는 검수하고, 보류 평가와 원문 그룹이 겹치지 않게 구성한다. 실제 민원의 개인정보를 제거하고 검수되지 않은 모델 출력은 정답으로 자동 채택하지 않는다. 정책 사실은 계속 RAG로 공급한다.

### 첫 학습 설정 예시

| 항목 | 실험 시작값·조건 |
| --- | --- |
| 대상 | 선정된 범용 LLM의 판정 또는 답변 중 반복 오류가 많은 태스크 하나 |
| 방식 | QLoRA, NF4 4비트 기본 가중치, 지원 시 BF16 연산 |
| LoRA | `rank=16`, `alpha=32`, `dropout=0.05`부터 비교 |
| 학습률·epoch | `5e-5~1e-4`, 1~3 epoch 이내 개발셋 비교 |
| 입력 길이 | 4,096토큰부터 메모리 측정; FAQ 조건을 자르지 않고 초과 예시를 별도 처리 |
| 배치 | micro batch 1, gradient accumulation 16부터 메모리·학습 안정성 확인 |
| 장비 | RTX 3090 한 장의 자원 확보 후 짧은 시험으로 실제 메모리 확인 |
| 검증 | 학습 전/후 같은 보류 평가, 일반 한국어 지시 이행·보류 행동 회귀 확인 |

수치는 확정 설정이 아니다. 선택 모델의 학습 지원과 입력 길이에 따라 달라진다. PEFT·TRL 등 지원 버전을 고정하고, 학습 결과는 추가 학습 없는 기준 모델과 비교한다. 개선이 없으면 어댑터를 적용하지 않는다. [PEFT 양자화 학습](https://huggingface.co/docs/peft/developer_guides/quantization), [TRL SFT](https://huggingface.co/docs/trl/sft_trainer)

## Jev 후속 확장 후보

아래 모델은 **초기 설치·CLI 완료 조건에 포함하지 않는다.** LLM + RAG의 기준 성능을 확보한 뒤 평가한다.

| 후보 | 검토 목적 | 확인된 조건 |
| --- | --- | --- |
| [OmniJev/OneJev1.6-4B](https://huggingface.co/OmniJev/OneJev1.6-4B) | 구조화 판정 호출 대체 비교 | Apache 2.0, 한국어 민원 성능 별도 평가 |
| [AlexWortega/openjev](https://huggingface.co/AlexWortega/openjev)의 `qwen3.5-4b-nli-v5` | 근거와 판단의 일치 검토 비교 | 모델 카드 MIT 표기, 선택지별 판정 방식 |
| [TypeSafe 공식 Jev](https://docs.typesafe.ai/models) | 관리형 판단 API 비교 | 확인 시점 `jev-1.14.0`, 입력 100만 토큰당 $0.042·출력 무료; 무료 우선 기준에서는 선택 사항 |

OneJev·OpenJev는 공식 Jev와 별개 프로젝트다. 점수·확률의 의미를 같게 취급하지 않으며 한국어 직접 입력으로 비교한다. 공식 Jev 문서는 영어에서 가장 강하고 다른 언어는 직접 검증해야 한다고 설명한다. [모델·언어 지원](https://docs.typesafe.ai/models)

후속 비교는 같은 검색 근거와 결과 계약을 유지한다. Jev가 판정 호출을 대체하는 실험과 불확실 사례를 추가 확인하는 실험을 구분한다. 기본 LLM + RAG 경로를 유지하고, 개선이 확인된 역할에만 적용한다. 웹 목업과 Jev 실험은 기본 CLI 이후 별도 과제로 진행할 수 있다.
