- **기준일:** 2026-11-21 KST
- **상태:** 7단계 중 5단계 구현, 1단계 일부 구현, 1단계 미구현. 결과 기록은 [CASE-116](../docs/cases/사례-116-프로젝트-폴더-파일-구조-정비-2026-11-21.md).
- **원칙:** 코드 동작을 바꾸지 않고, 한 단계씩 `git mv`로 옮기며 단계마다 테스트(`pytest` 189, `rag` 49)와 링크 검사를 통과시켰다.
- **사용자 결정(2026-11-21):** 스크립트 이름만 영문으로 통일(문서·사례 이름은 한글 유지), 대형 모듈 분리 진행, `db/` 샘플은 유지하되 배치 정돈.

## 1. 정비 전에 확인한 복잡성

| # | 관찰 | 문제 |

| 3 | `scripts/` 66개 평면, 한글 본체 + 영문 `exec` 래퍼 쌍, 일자별 보고서 생성기 혼재 | 운영 도구와 일회성 도구가 구별되지 않음 |
| 4 | `db/`와 `rag/origin/`에 같은 원본 JSON(8.7 MB, 해시 동일) 중복 | 원본 위치 모호, 용량 중복 |
| 5 | `docs/` 루트에 PDF·진행보고, `report`/`test` 이름이 모호, `plan/`에 현행과 초기 자료 혼재 | 기준 문서와 산출물 경계가 흐림 |
| 6 | 대형 모듈: `repository.py` 2,265줄, `service.py` 약 2,100줄, `place_tool.py` 1,668줄, `swagger_page.py` 993줄, `pipeline.py` 960줄 | 변경 범위 파악·리뷰 비용 큼 |
| 7 | 가상환경 2개(`.venv` 모델용, `.venv-web` 웹용) | 문서마다 쓰는 환경이 다름 |

## 2. 단계별 구현 현황

| 단계 | 계획 | 상태 |
| --- | --- | --- |
| 1 | `scripts/`를 `ops`·`run`·`eval`·`reports`로 분류하고 영문 이름 하나로 통합 | **구현됨** |
| 2 | 루트 실행 파일을 `bin/`으로 이동, 프로토타입 HTML을 `ui/mockups/`로 이동 | **구현됨** |
| 3 | `db/`를 `sql`·`samples`·`docs`로 정리, 중복 JSON 제거(`rag/origin/`이 유일한 원본) | **구현됨** |
| 4 | `docs/reports/{daily,analysis}`·`docs/api`, 문서 도구를 `scripts/reports/`로, 초기 기획 자료를 `plan/archive/`로 | **구현됨** |
| 5 | `src/rag`를 `src/search_client`로 이름 변경 | **구현됨** |
| 6 | 대형 모듈 분리 | **일부 구현**: `repository/` 패키지(4개 파일), `service.py`→`staff_reports.py`, `place_tool.py`→`place_words.py`. `swagger_page.py`·`pipeline.py`·AI 워커·`postgres.py` 내부 분리는 **미구현** |

## 3. 정비 후 구조

```text
ai-complaint-process/
├─ README.md · AGENTS.md · CHANGELOG.md · setup.cmd · setup.sh
├─ bin/        사용자 실행 파일 (.cmd/.sh 쌍)            → bin/README.md
├─ src/        complaints(repository/·service·staff_reports) · search_client · llm · assist · lab_web
├─ rag/        검색 엔진·색인. origin/이 FAQ·사례 원본의 유일한 위치
├─ ui/         화면. 목업은 mockups/
├─ scripts/    ops · run · eval · reports               → scripts/README.md
├─ db/         sql · samples · docs · load_samples.py   → db/README.md
├─ docs/       cases · harness · reports(daily·analysis) · api · assets
├─ plan/       현행 계획. 초기 자료는 archive/          → plan/README.md
└─ PACKET/     수집기·부서 정규화
```

## 4. 후속 후보 (미결정)

- `service.py`의 AI 워커·챗봇과 `postgres.py`를 더 나누려면 `self` 의존 메서드를 협력 객체로 바꾸는 설계가 필요하다(믹스인은 `mypy --strict`와 충돌).
- `swagger_page.py`의 HTML·CSS·JS를 정적 파일로 분리할지 결정.
- 가상환경 통합 또는 "무엇을 어디에 쓰는가" 한 표로 고정.
- Linux 셸 스크립트 실행 검증(이 Windows 호스트에는 `bash`가 없어 검증하지 못함).

## 5. 하지 않은 것

- `docs/cases/` 사례 파일의 이름·번호는 바꾸지 않았다.
- RAG 원본·색인과 업무 DB를 합치지 않았다.
- Docker 의존성을 추가하지 않았다.
