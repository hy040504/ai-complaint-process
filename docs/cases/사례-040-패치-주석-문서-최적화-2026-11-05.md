## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: CASE-035~039는 자동 기동·로컬 PG·Codex stdin·`rag/origin` 배치에 집중했고, Windows 포트 확인·새 콘솔 기동·libpq 기본값이 세 스크립트에 반복됐다. README 배지·화면 표는 `start-rag.cmd`와 origin을 약하게 드러냈다. `ingest.cached_vectors` 인자가 SQL 열 `text_hash`와 다른 이름으로 적혀 있었다.
- 기대 동작 또는 요구사항: 한국어 Google 형식 docstring, 패치와 같은 현재 문서, README에서 origin·`start-rag.cmd`가 바로 보이고, 기동 규칙을 한곳으로 모은다.
- 확인 근거와 시점: 2026-11-05 사용자 요청 「주석 점검, readme/docs 업데이트, readme 디자인 개선, 코드 최적화, 깃헙 업로드」.

## 3. 재현·확인 방법

- 비교한 기존 동작: `ask_assist.port_open`과 `windows_rag.port_open`이 각각 TCP를 열고, `CREATE_NEW_CONSOLE`·`cmd.exe /k`를 각각 조합했다. `luna_settings`는 공백 모델명을 그대로 둘 수 있었다.
- 판단 근거: 검색 엔진은 `scripts/`를 import하지 않고, `start-rag.cmd`는 `.venv-web`의 표준 라이브러리만 쓴다. 공유 모듈은 `scripts/console_spawn.py`에 둔다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: CASE-035~039는 동작 수정에 집중했고 주석·현재 문서·중복 기동을 이 작업으로 넘겼다.
- 검토한 선택지와 결정 이유: `rag.store`를 `windows_rag`에서 import하지 않는다. psycopg·토치가 `.venv-web`에 없을 수 있다. libpq 기본값 복제는 주석으로 연결한다.
