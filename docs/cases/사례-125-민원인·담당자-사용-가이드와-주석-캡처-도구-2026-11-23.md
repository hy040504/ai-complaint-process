## 1. 요청

개발 지식이 전혀 없는 **민원인**과 **담당자**가 읽고 따라 할 수 있는 사용 가이드를 만들고, 사진·그림을 넣어 이해하기 쉽게 하며, 가능하면 **사이트를 직접 캡처해 "어디를 누르고, 이 영역은 무슨 기능인지" 표시해** 편집해 넣어 달라는 요청이었다.

## 4. 겪은 문제와 수정

- **번호 배지가 글자를 가렸다**: 작성 화면에서 배지가 "분야", "관할 구" 라벨을 덮었다. 배지를 오른쪽 위로 옮기는 옵션(`badge: right`)을 추가했다.
- **숨은 요소를 잡았다**: 첫 화면의 "로그인 없이 시작해요" 카드를 CSS로 찾았더니 화면에서 숨겨진 모바일용 요소가 먼저 잡혀 엉뚱한 곳에 표시됐다. 좌표 지정(`xy:`)으로 바꿨다.
- **사이드바 메뉴를 잡았다**: "추가 문의" 패널을 글자로 찾았더니 왼쪽 메뉴의 같은 글자가 먼저 잡혔다. 좌표 지정으로 바꿨다.
- **화면이 잘렸다**: 도우미·답변 편집 화면의 입력창과 버튼이 보이는 영역 아래로 밀려 높이를 늘렸다.
- **"미리보기·게시"는 사유 없이는 열리지 않는다**: 빈 칸이면 경고만 떠서, 사유를 입력하는 단계를 캡처 순서에 넣었다.
- **PowerShell이 JSON 앞에 BOM을 붙여** 도구가 설정을 읽지 못했다. 도구가 BOM을 무시하도록 했다.
- **PDF 변환기 정규식 오류**: 자리표시용 `\1`이 역참조로 해석돼 오류가 났다. 제어문자 `\x01`로 바꿨다.
- **시험 데이터가 그림에 남았다**: 첫 캡처에 "가이드 시험 민원 (자동 삭제 예정)"이 두 번 보였다. 실제 같은 제목·내용으로 바꾸고, 캡처 뒤 DB에서 시험 민원을 모두 삭제했다.
- **글 속 사실 확인**: 코드와 대조해 두 군데를 고쳤다. 담당자 계정은 화면이 아니라 시스템 관리자가 만들고, AI 판정 선택지는 "담당자 검토 필요"가 아니라 "담당자 검토"·"분석 전"이다.

## 5. 검증 (`2026-11-23 KST`)

| 항목 | 결과 |
| --- | --- |
| 화면 캡처 | 시연 로그인을 끈 로컬 서버(`:5001`)로 시민(방문자·게스트)·담당자 화면 19장. 저장소의 도구로 **처음부터 다시 실행해 경고 없이 19장 모두 재현**했다 |
| 눈으로 확인 | 모든 그림을 열어 번호 위치·글자 가림·잘림을 확인하고 위 문제를 고쳤다 |
| 글의 사실 확인 | 입력 제한(제목 120자·내용 10~2,000자·추가 문의 500자·사유 200자·첨부 5개/5MB), 상태 이름, 버튼 이름(`게시 답변 철회` 등)을 코드·화면과 대조 |
| PDF | Edge로 두 권 생성(오류 없음). PDF를 그림으로 바꾸는 도구가 없어 같은 HTML의 렌더링으로 모양(제목·표·알림 상자·그림)을 확인했다 |
| 시험 데이터 | 캡처 중 접수한 게스트 시험 민원과 앞선 시험 민원을 모두 삭제, 남은 민원은 원래 3건 |

## 6. 한계

- 그림은 **시연 데이터**로 찍어 실제 화면과 내용·숫자가 다르다. 위치·이름은 같다.
- (해결: [CASE-130](사례-130-가이드-화면-보강과-PDF-쪽나눔-및-서버-PG-테스트-오류-원인-2026-11-23.md)) 로그인한 민원인 화면, 계정 만들기, 추가 문의·게시 답변·AI 작업 모니터, 게시 답변 철회 창 그림을 추가했다.
- 담당자의 **배정 해제**·**CSV 내보내기** 결과 화면은 여전히 그림이 없다.
- 번호와 글이 일치하는지는 사람이 확인했고 자동 검사는 없다(번호를 바꾸면 `screens.json`과 글을 함께 고쳐야 한다).
- (해결: CASE-130) PDF를 쪽 그림으로 바꿔 모든 쪽을 확인했고, 장 제목이 쪽 끝에 홀로 남던 문제를 고쳤다.
- 주소는 글에 넣지 않았다. 안내받은 주소로 접속한다고만 적었다.
