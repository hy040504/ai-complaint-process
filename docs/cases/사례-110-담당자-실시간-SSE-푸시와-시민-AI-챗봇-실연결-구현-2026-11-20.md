## 1. 배경 및 목적

`CASE-093`에서 민원 웹(`:5000`) CRUD와 담당자 콘솔에 RAG+LLM 백그라운드 워커를 통합했지만, 두 가지 핵심 미구현 과제가 남아 있었습니다.

1. **담당자 AI 작업 모니터의 1.5초 폴링 한계 (`BE07` · `UI08`):** 실행 중인 작업 유무를 1.5초 간격 HTTP 폴링으로 조회하던 구조를 `text/event-stream` 실시간 SSE 푸시(`Last-Event-ID` 커서 재전송·`resync_required`·단절 시 3초 폴링 대체 전환)로 전환해야 했습니다.
2. **시민 민원 도우미(`#/citizen/assistant`) 고정 응답 한계:** 기존 고정 안내 문구 대신 실제 RAG + LLM 파이프라인과 연결하되, **미게시 담당자 초안(`PREFIX-03`)·직원 보호 순화(`PREFIX-04`)·내부 프롬프트·과거 사례 원문을 서버 단에서 구조적으로 차단**하고, 감지 관할 구를 민원 작성 화면(`#/citizen/write`)으로 매끄럽게 이어 주어야 했습니다.

## 2. 구현 내용

### 2.1 담당자 실시간 SSE 푸시 (`BE07` · `UI08`)

- **커서 기반 이벤트 브로커 ([`src/complaints/events.py`](../../src/complaints/events.py)):**
  - `StaffEventBroker`에 스레드 안전한 단조 증가 커서(`event_id`)·256건 링 버퍼·구독자별 유한 대기열(`max_queue_size=64`)·15초 하트비트(`: heartbeat`)를 구현했습니다.
  - 이벤트 페이로드는 `eventId`·`type`·`complaintId`·`contextVersion`·`attempt`·`jobStatus`·`stage`·`occurredAt` 메타데이터로 한정하고, **민원 본문·미게시 초안·비밀 키·내부 추론 과정은 일절 담지 않습니다.**
  - `Last-Event-ID` 헤더 또는 `lastEventId` 쿼리로 누락 이벤트를 재전송하고, 보관 만료·서버 재기동·구독자 버퍼 초과 시 `resync_required` 이벤트를 보냅니다.
- **커밋 후 발행 및 담당자 전용 경로 (`service.py` · `api.py` · `models.py` · `http.py`):**
  - `ComplaintService`의 `create`/`update`/`delete_complaint`/`act`/`_run_ai_worker`·`_commit_ai_completion`·`_commit_ai_failure`·`advance_jobs`에서 **DB 커밋 또는 live 상태 갱신 이후에만** 이벤트를 발행합니다. 취소·맥락 변경으로 버려진 늦은 AI 결과는 `_commit_with_retry()`가 `None`을 반환해 오발행을 차단합니다.
  - `StaffWorkspace.event_cursor`로 스냅샷 시점 커서를 제공하고, **`GET /api/v1/staff/events`** 경로에서 미인증(`401`)·시민 세션(`403`, `T04`)을 서버에서 거부합니다(`Cache-Control: no-cache, no-store`, `X-Accel-Buffering: no`).
- **담당자 UI SSE 클라이언트 ([`ui/src/realtime.js`](../../ui/src/realtime.js) · `app.js` · `staff.css` · `themes.css`):**
  - `createStaffEventStream()`이 단일 `EventSource` 연결을 유지하며 `eventId <= lastEventId` 중복 이벤트를 제거하고 `resync_required` 시 전체 스냅샷을 재동기화합니다.
  - `#/staff` 진입 시 연결·이탈 시 즉시 `close()`하며, 연속 오류 또는 `EventSource` 미지원 환경에서는 3초 폴링 대체 모드로 자동 전환하고 복구 시 원복합니다.
  - `#/staff/monitor` 헤더에 `실시간 SSE 연결됨` · `SSE 재연결 중…` · `폴링 대체 연결 (3초)` 배지(`renderSseStatusBadge`)를 라이트·다크 테마로 표시하며, 스냅샷 동기화 시 편집 중인 `#answer-form` 초안을 보호합니다.

### 2.2 시민 AI 챗봇 실연결 (`#/citizen/assistant`)

- **담당자 산출물 생성 생략 최적화 (`src/assist/pipeline.py` · `src/assist/__init__.py`):**
  - `iter_assist`·`run_assist`·`iter_web_assist`·`run_web_assist`에 `include_staff_outputs: bool = True` 옵션을 추가해 시민 챗봇 경로에서는 `PREFIX-03`(담당자 초안)·`PREFIX-04`(직원 보호 순화) 호출 자체를 건너뜁니다(지연 절감 및 비노출 이중 보장).
- **시민 전용 투영 모델 및 스트림 API ([`src/complaints/chat.py`](../../src/complaints/chat.py) · `models.py` · `api.py`):**
  - **`POST /api/v1/citizen/chat`** 및 **`POST /api/v1/citizen/chat/stream`**(NDJSON 진행 안내 + `done`)을 추가하고 OpenAPI 태그 `시민 민원 도우미` 및 [`Swagger PDF`](../api/청주톡톡_민원_업무_API_Swagger.pdf)(25경로·1,163,623바이트)에 반영했습니다.
  - `project_citizen_chat()`이 `CitizenChatResponse`로 변환하며 `staffDraft`·`sanitize`·`codex`·`cases`·`modelRaw`를 구조적으로 배제하고, `automaticTransfer=False`, 검증된 공식 FAQ 출처(`faqSources`), 참고용 부서 후보(`departmentHints`), 감지 자치구(`district`), `faq_generation_failed`/`llm_unavailable`/`out_of_scope` 안내 문구만 반환합니다.
- **시민 UI 챗봇 연동 ([`ui/src/chatbot.js`](../../ui/src/chatbot.js) · `app.js` · `citizen.css` · `themes.css`):**
  - `streamCitizenChat()`으로 NDJSON 진행 문구를 실시간 표시하고, 갈래별(`faq_answer` 공식 출처 카드 · `department_suggestion` 감지 구/참고 부서 칩 · `human_handoff` 관할 외/검토 안내) 카드를 라이트·다크 테마로 렌더링합니다(출처 URL `https?://` 검증 및 XSS 이스케이프 적용).
  - 관할 구 선택(`#chat-district`)·`새 대화` 초기화(`chat-reset`) 및 `이 내용으로 민원 작성` 클릭 시 `buildCitizenDraftPayload()`로 감지된 `district`와 본문을 `#/citizen/write`에 자동 전달합니다.
