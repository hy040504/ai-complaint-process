## 2. 배경·증상과 기대 동작

- **관찰된 사실과 증상:**
  - 시민 민원 본문 `"청주 서원대학교 후문 편의점근처에서 나무가 쓰러짐"` 입력 시, 기존 시스템이 장소('서원대학교')를 인식하지 못하고 `district: None`으로 판정함.
  - 구가 특정되지 않음에 따라 RAG 검색 결과에 `청원구 건설과` 등 타 자치구 소관 부서가 혼입되어 추천됨.
  - 담당자 답변 초안의 `summary_card.missing_info`에 `"정확한 위치와 쓰러진 나무의 소유·관리 주체"`가 누락 항목으로 표시되는 등 위치를 파악하지 못하는 답변이 출력됨.
- **기대 동작:**
  - 장소/시설명이 포함된 민원 문장에서 네이버 지도 비로그인 장소 추적 도구(`lookup_navermap_place`)가 문맥을 분석하여 `충청북도 청주시 서원구 모충동`(`서원구`)을 정확히 특정해야 함.
  - RAG 검색 시 서원구로 필터링되어 타 구 부서가 배제되고 서원구 관할 부서만 추천되어야 함.
  - Codex MCP 환경에서 `lookup_navermap_place` 도구를 안전하게 호출할 수 있고, 생성된 초안에 정확한 위치(`location_or_target`)가 반영되어야 함.

## 3. 원인 분석

1. **지명 추출 정규식의 한계:**
   - `src/assist/district.py`의 `extract_district`가 청주시 4개 구 명칭과 행정/법정동 목록만 정규식으로 대조하여, '서원대학교' 같은 대학교·건물·랜드마크 명칭을 전혀 감지하지 못함.
2. **문장형 검색어 전달 시 인스턴트 검색 미매칭:**
   - `"청주 서원대학교 후문 편의점근처에서 나무가 쓰러짐"` 전체 문장을 네이버 지도 웹 검색에 그대로 넘기면 결과가 반환되지 않음(`found: False`). 반면 조사·서술어를 정제한 핵심 지명(`서원대학교 후문`)은 정확히 일치함.
3. **무관한 일반 상점 오인식 위험:**
   - 반대로 `"시내 도로에 신호등이 고장 났습니다"` 같은 일반 명사 문장을 검색할 경우, 네이버 지도가 '시내' 키워드로 무관한 식당('모모랩 청주시내성안길본점')을 반환하여 잘못된 구('상당구')로 오판하는 결함 존재.
4. **Codex 실행 도구 제한 및 MCP 등록 누락:**
   - `src/llm/complete.py`에서 `CODEX_ALLOWED_TOOLS`와 `codex_mcp_args`의 `enabled_tools`에 `search_complaint_rag`만 등록되어 있어, Codex가 `lookup_navermap_place` 도구를 인식하거나 실행할 수 없었음.
   - `PREFIX-00.txt` 28행에서도 허용 도구를 1개로 제한하여 모델의 도구 호출을 차단하고 있었음.
5. **장소 맥락의 파이프라인 단절:**
   - 추론된 장소 객체(`inferred_place`)가 판정(`decision_payload`) 및 초안(`staff_draft_payload`)의 사용자 프롬프트에 전달되지 않아 모델이 이미 찾은 위치 정보를 알 수 없었음.

## 4. 조치 내용

1. **`src/llm/place_tool.py` 지명 후보 추출 및 관련성 검증 구현:**
   - `_STOP_SUFFIXES`, `_STOP_WORDS` 확장을 통해 조사, 일반 시설물(도로, 신호등, 가로등), 서술어를 정제.
   - `extract_place_candidates(text: str)` 함수 구현: 2단어 조합 및 단일 명사 후보 우선순위 생성.
   - `is_place_relevant(title: str, query: str)` 함수 구현: 검색 결과 장소의 제목과 검색 키워드의 관련성을 교차 검증하여 무관한 상점 필터링.
   - `lookup_navermap_place`: 1차 검색 실패 시 `extract_place_candidates`를 통한 fallback 순차 검색 연동.
2. **`src/assist/district.py` 네이버 지도 fallback 및 장소 추출 함수 연동:**
   - `extract_district`: 1차 정규식(구/동) 매칭 실패 시 `lookup_navermap_place`로 2차 지명 추론.
   - `extract_place_info(text: str)`: 민원 본문에서 청주시 관할 장소 정보를 직접 반환하는 헬퍼 함수 추가.
3. **`src/llm/complete.py` 및 MCP 권한 확장:**
   - `CODEX_ALLOWED_TOOLS = (RAG_TOOL_NAME, PLACE_TOOL_NAME)` 확장.
   - `codex_mcp_args`의 `enabled_tools`에 `lookup_navermap_place` 등록.
   - `codex_tool_instruction`에 `PLACE_TOOL_USAGE` 설명 추가.
4. **프롬프트 지침 갱신 (`PREFIX-00.txt`, `PREFIX-01.txt`):**
   - 시스템 헌법(PREFIX-00) 28행에 `lookup_navermap_place` 도구 권한 명시.
   - 1차 판정 지침(PREFIX-01)에 건물·학교·시설물 확인 시 도구 활용 지침 반영.
5. **`src/assist/pipeline.py`, `policy.py`, `followup.py` 장소 맥락 연계:**
   - `decision_payload` 및 `staff_draft_payload`에 `inferred_place` 매개변수 추가 및 JSON 전달.
   - `build_result` 반환 결과에 `inferred_place`를 포함하여 UI 및 상위 호출자가 장소 상세(지번, 도로명, 동, 좌표)를 즉시 확인 가능하도록 지원.
6. **단위 테스트 보강 (`src/tests/test_place_tool.py`):**
   - 후보 추출, 제목-키워드 관련성 검증, 문장 fallback 모의 검색 테스트 3건 추가.
