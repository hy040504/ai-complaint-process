## 2. 배경·증상과 기대 동작

- **관찰한 사실과 영향:**
  1. 담당자 업무 포털(`#/staff`, `#/staff/detail/<id>`)의 담당자 지정 기능이 `내가 담당` / `담당 해제` 단일 토글(`assigned: bool`)만 제공해 다른 부서로 배정·전달하는 흐름을 시연할 수 없었습니다.
  2. 답변 편집기 상단의 자주 쓰는 문구(`PHRASES` 5건)가 `ui/src/app.js`에 고정 배열로 하드코딩되어 담당자가 현장 상황에 맞는 안내 템플릿을 추가하거나 삭제할 수 없었습니다.
- **기대 동작 또는 요구사항:**
  - `내가 담당`/`담당 해제` 계약을 유지하면서 청주시 현행 부서(127개)를 검색·선택(및 AI 추천 부서 후보 원클릭 선택)하여 시연 업무 포털 내에서 배정·변경·해제하고 처리 이력을 남깁니다. (`AGENTS.md` 경계에 따라 공식 행정 이관 아님·업무분장 확인 필요 표시 유지, 시민 응답 `PublicComplaint`에는 내부 부서 필드 미노출.)
  - 담당자 답변 편집기에서 커스텀 템플릿을 제목+본문으로 추가(작성 중 답변 불러오기 포함)하고 원하는 템플릿을 삭제할 수 있으며, PostgreSQL(`complaint_app.answer_templates`)에 영속 저장해 재기동·새로고침 뒤에도 유지합니다.

## 3. 재현·확인 방법

- **부서 배정 흐름:** `#/staff` 목록 또는 `#/staff/detail/<id>` → `부서 배정`/`다른 부서 배정` 클릭 → `#dept-search` 검색·`#dept-select` 선택(또는 AI 추천 후보 칩 클릭)·메모 입력 후 저장 → 행 배지·상세 프로세스(`담당·부서 지정`) 반영 및 배정 해제 확인.
- **답변 템플릿 CRUD 흐름:** `#/staff/detail/<id>` 우측 편집기에서 작성 중 텍스트 유지 상태에서 `+ 템플릿 추가` → `현재 편집 중 답변 불러오기`·이름 입력 저장 → `.phrase-chip` 삽입 확인 → `×` 삭제 확인 모달 → 새로고침 후 삭제 상태 유지 확인.

## 4. 원인 분석 또는 결정 근거

- **기존 `assigned: bool` 계약 호환 + `department` 검증:** 기존 목록/어댑터/테스트(`test_api.py`, `ui04-adapter.js`)가 `assigned` 불리언을 사용하므로 `Complaint.department: str | None = None`을 담당자 전용 모델에 추가하고 `AssignmentInput`이 `assigned`·`department`·`reason`을 함께 수용하도록 확장했습니다. 허용 부서명은 `:8007/departments`(미연결 시 `rag/origin/공개_민원_사례.json` 정규화 부서 127개 fallback)로 서버에서 검증해 임의 문자열 주입을 차단합니다.
- **템플릿 최초 1회 시드(`app_meta` 플래그):** PostgreSQL `answer_templates` 테이블이 비어 있을 때마다 기본 5종을 다시 넣으면 담당자가 기본 템플릿을 모두 지운 뒤에도 재기동 시 부활하게 됩니다. 이를 막기 위해 `complaint_app.app_meta`의 `default_templates_seeded` 키를 이용해 스키마 최초 초기화 때만 1회 시드하고, 이후 `POST /api/v1/templates/reset` 호출 시에만 삭제된 기본 문구를 복원하도록 설계했습니다.
