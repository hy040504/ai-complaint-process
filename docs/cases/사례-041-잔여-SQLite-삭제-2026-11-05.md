## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 시연 웹은 PostgreSQL `complaint_app`만 쓰고, 검색은 `complaint_rag`다. 그런데 `db/app/complaints.sqlite3`(82 KB), `.web-data/complaints.sqlite3`, CASE-020 audit 백업 두 개, 구 Flask 로그가 남아 검색 DB로 오인될 수 있었다.
- 기대 동작 또는 요구사항: 쓰지 않는 sqlite와 그 안내 폴더를 지운다. `.web-data/session.key`와 로컬 PostgreSQL은 남긴다.
- 확인 근거와 시점: 2026-11-05 사용자 요청 「필요없는 sqlite 파일 같은거 잇음 지우고 안쓰거나 쓸모없는 폴더나 파일도 지울것」. 삭제 전 `psql`에서 `complaint_rag.faq_knowledge` 94, `routing_cases` 5,015, `complaint_app.complaints` 0.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: 저장소 루트. Git 추적 파일과 gitignore sqlite를 구분한다.
- 비교한 기존 동작: CASE-031 이후 코드는 `SQLiteRepository`가 없고 `COMPLAINT_DATABASE` sqlite 경로도 없다. 잔여 파일만 디스크에 있었다.
- 확인: 삭제 후 `*.sqlite3`가 프로젝트 작업 트리에 없고 `.web-data`에는 `session.key`만 남는다. `db/`는 경로 안내 README만 둔다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: CASE-016·020이 sqlite를 기본 업무 DB로 썼고, CASE-031이 PostgreSQL로 바꾼 뒤 자동 이관하지 않기로 했다. CASE-039는 `db/app`을 잔여 경로로 남겼다.
- 아직 확인하지 않은 가설: 없음.
- 검토한 선택지와 결정 이유: 예전 시연 27건 sqlite는 `complaint_app`에 자동 넣지 않는다. 데모는 `seed-demo`로 다시 넣는다. `.web-data/session.key`는 Flask 세션에 필요하므로 유지한다. `.rag-data` PostgreSQL과 `rag/origin` JSON은 검색 실데이터이므로 삭제하지 않는다.

## 7. 완료 조건·후속 작업·복구

- 완료: 시연 sqlite 잔여와 `db/app` 안내 폴더가 없고, 현재 문서는 PostgreSQL만 업무 DB로 적는다.
- 남은 작업: 7테이블 정규화, 시연 민원 seed를 이 호스트 `complaint_app`에 넣을지는 별도 요청.
- 되돌림: Git에서 `db/app/README.md`를 되돌릴 수 있다. sqlite 바이트는 Git에 없었고 로컬에서 삭제했다.
