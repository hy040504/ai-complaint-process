## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향:
  - `:5010` 단독 응대 검사기에서 오른쪽 테스트 기록(`#run-list`) 항목을 클릭하면 결과 패널(`#result`)과 `#sent-json`만 갱신되고 왼쪽 작성 폼(`#title`, `#category`, `#district`, `#provider`/`.llm-choice-btn`, `#body`, `#title-count`, `#body-count`)은 비어 있거나 직전 입력 상태가 그대로 남아 당시 입력 내용을 바로 수정해 재시험하기 불편했음.
  - 업무보고 PDF 중 `업무보고_20261104.pdf`만 `docs/report/`에 있고 이후 `업무보고_20261109.pdf`~`20261111.pdf` 및 새로 작성한 `20261116.pdf`는 `docs/` 루트에 흩어져 있어 보고서 전용 폴더로 일원화할 필요가 있었음.
- 기대 동작:
  - 테스트 기록을 클릭하면 `record.payload`의 모든 입력값·엔진 선택 상태·글자 수가 작성 폼에 그대로 복원되어 `readComplaint(form)` 결과와 일치해야 함.
  - 모든 일자별 업무보고 PDF(11/04·09·10·11·16)는 `docs/report/`에 모여 있어야 하며, 생성 스크립트 4종 출력 경로와 `README.md`/사례 링크가 구 경로 없이 일치해야 함.

## 3. 재현·확인 방법

1. `http://127.0.0.1:5010/` 접속 후 오른쪽 **테스트 기록** 목록에서 `district` 유무와 `provider`(`codex_cli`, `exaone_api`)가 다른 항목을 순차 클릭합니다.
2. `#title`, `#category`, `#district`, `#body`, `#provider`, `.llm-choice-btn.active`, `#title-count`, `#body-count`가 `GET /api/v1/lab/runs/<id>`의 `payload`와 일치하는지 확인합니다.
3. `.venv-web\Scripts\python.exe scripts/업무보고_20261116_pdf_생성.py` 실행 후 [`docs/report/업무보고_20261116.pdf`](../report/업무보고_20261116.pdf)(5쪽)가 생성되고 `docs/` 루트에 낡은 보고서 파일이 남지 않았는지 확인합니다.

## 4. 원인 분석 또는 결정 근거

- `src/lab_web/static/app.js`의 `#run-list` 클릭 핸들러가 `showResult(record.payload, record.received, ...)`만 호출하고 폼 입력란을 채우지 않았음. `fillComplaintForm`, `setSelectValue`, `updateCharCounters`를 분리·내보내어 단위 테스트 가능하게 만들고, 비동기 `loadFields()` 완료 전이나 목록 외 과거 값을 선택해도 복원 값이 사라지지 않게 `option[data-restored='true']` 임시 보존 로직을 적용함.
- 기존 `docs/report/` 폴더가 이미 `업무보고_20261104.pdf`를 포함해 존재하고 `docs/cases/`, `docs/harness/`, `docs/tools/` 등 영문 소문자 하위 폴더 규칙과 맞으므로 `docs/report/`를 공식 보고서 전용 폴더로 통합 확정하고 [`docs/report/README.md`](../report/README.md) 목록 문서를 추가함. (기민 님 `UI_변경_*.pdf` 및 `진행보고-2026-11-05.md`는 기존 `docs/` 위치 유지)
- `scripts/업무보고_20261116_pdf_생성.py`는 430줄 단일 함수의 중복 장면 블록·파일명 중복 나열을 `SCENE_PAGES` 데이터 구조와 `_build_scene_pages_html()`, `_REPORT_CSS`로 분리해 유지보수성과 안전성(`html.escape`)을 개선함.
