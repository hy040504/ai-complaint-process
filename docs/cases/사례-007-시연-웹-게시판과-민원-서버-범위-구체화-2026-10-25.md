## 2. 사용자 요구와 기존 문서의 차이

사용자는 시연 웹에 실제 민원 게시판과 민원 작성 페이지를 만들고, 민원을 주고받는 서버까지 구현할 계획이라고 밝혔다. 기존 웹 단계의 완료 조건은 AI 입력·결과 화면 중심이었고, 접수 완료를 표시하지 말라는 문구는 시연 서버 내 저장까지 제외하는 것으로 읽힐 수 있었다.

이번 요구는 시연 서비스 자체의 등록·조회·답변 교환 서버를 범위에 포함한다. 청주시 공식 접수·외부 부서 이관 연계와는 구별한다. 초기 Jev 없는 LLM + RAG, CLI 이후 웹, Jev는 추후 확장이라는 방향은 유지한다.

## 3. 문서 반영

- 한국어 파일명으로 [시연 웹·민원 서버 구현계획](../../plan/시연_웹_게시판과_민원_서버_구현계획.md)을 추가했다. 사용자 확정 범위와 화면·데이터·API·상태의 세부 구현 제안을 구별했다.
- 민원 목록·작성·상세, 담당자 답변·시민 추가 문의, 처리 상태 저장을 최소 기능안으로 정리했다. 저장된 글이 AI 장애로 유실되지 않는 경로와 기존 RAG 지식·업무 데이터 분리를 제안했다.
- README·작업 지침·문서 목차·우선 구현계획·실행 계획·모델 제안·하네스에 웹·업무 서버 범위와 미구현 상태를 맞췄다.
- 시연 DB 저장에 성공한 경우의 등록 완료와 청주시 공식 접수·외부 이관 완료를 구별하도록 판정 정책을 보완했다.
- 기존 계획서 분석의 안내문에서 최신 웹 계획으로 연결하고 원래 기획 본문은 유지했다.

API 경로·DB 테이블·업무 상태·웹 프레임워크·인증 방식은 구현 완료나 최종 선정으로 표시하지 않는다. 이 문서 변경으로 원본 JSON·색인 재구축이나 서버 구현이 이루어진 것은 아니다.

## 4. 검증 결과

2026-10-25 로컬 문서 28개와 상대 링크·이미지 경로 343개를 검사해 누락 경로·앵커 오류 0건을 확인했다. 사례 번호 7개가 중복 없이 색인에서 연결되고, 기존 계획서 분석의 원래 본문이 보존되는지 대조했다. 변경 파일이 Markdown뿐임을 확인하고 시연 서버의 등록과 공식 접수·이관에 대한 기존 표현을 검토했다.

이는 문서 반영의 완료다. 실제 웹·업무 서버 테스트, 기존 모델 평가, 코드 변경·서비스 재시작·DB 재적재는 수행하지 않았다. 기능 인수 조건은 향후 구현 시 검증한다.
