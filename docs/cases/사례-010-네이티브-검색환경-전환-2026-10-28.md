# CASE-010: 네이티브 검색 환경 전환

- 기준일: 2026-10-28 UTC
- 유형: 운영 환경·데이터 이전
- 상태: 완료

## 배경과 결정

한 컴퓨터에서 공동 작업하므로 Docker 기반 검색 환경을 호스트 PostgreSQL·Python으로 전환한다. 기존 데이터를 삭제하지 않고 논리 백업을 새 PostgreSQL 18 DB에 복원한다.

## 조치와 검증

기존 PostgreSQL 17의 `complaints`를 pg_dump로 백업하고 호스트 PostgreSQL 18의 `complaints_native`에 복원했다. pgvector 확장은 0.8.1이다. Python 3.12 가상환경과 사용자 검색 API 서비스를 설치했다. 부서 사전과 벡터를 재생성하지 않았다.

`rag.verify`로 FAQ 94건, 공개 사례 5,015건, 부서 127개와 원본·벡터·BM25·HNSW를 대조했다. 격리 DB 테스트는 일시적인 관리자 권한으로 실행해 25개 통과 후 권한을 회수했다. 권한 없이 실행하면 확장 설치 권한 부족으로 DB 테스트 3개가 실패하므로 상시 superuser로 운영하지 않는다.

검색 API를 사용자 서비스로 실행해 Docker 컨테이너를 정지한 뒤 상태 조회·FAQ 재정렬 검색·공개 사례 재정렬 검색·부서 조회를 확인했다. FAQ는 대형폐기물 배출 방법이 1위, 버스 사례에서는 건설교통국 대중교통과가 후보로 반환됐다. 검색 전용 계약을 유지했다.

## 한계

자동 응답·웹은 미구현이며 FAQ 현행성과 부서 업무분장은 별도 검증이 필요하다. [네이티브 운영 안내](../harness/네이티브_운영.md)를 따른다. 과거 Docker 데이터와 백업은 복구용으로 보존한다.

## 후속 조치: 실행 구성의 네이티브 통일

2026-10-28 사용자 요청으로 `compose.yaml`, `rag/Dockerfile`, `.dockerignore`, `.env.example`을 제거했다. 프로젝트 전용 컨테이너 2개·네트워크·검색 이미지를 제거했다. 호스트의 다른 서비스와 공용 도구는 정리하지 않았다. 과거 DB 파일과 논리 백업은 복구 자료이며 현재 실행에 사용하지 않는다. 이전 `.env`는 비공개 백업 디렉터리로 옮겼다.

`scripts/검색파이썬_준비.sh`, `scripts/검색DB_준비.sh`, 사용자 서비스 등록·실행 스크립트와 네이티브 운영 절차로 설치·적재·검색·검증·백업·복구를 통일했다. 과거 사례와 당시 보고서의 실행 환경 기록은 유지하되 현재 운영 명령에서 제거된 구성에 의존하지 않는다. 웹·모델 계획도 별도 네이티브 프로세스로 바꾸고 MD/PDF를 함께 갱신했다.

처음에는 임시 DB에 확장을 직접 설치하려던 테스트가 권한 부족으로 실패했다. 확장만 설치한 `complaint_rag_test_template`에서 테스트 DB를 만들도록 수정한 뒤 일반 계정으로 **25개 테스트가 통과**했다. 운영 계정의 superuser는 false다. [실행 결과](../../rag/reports/네이티브_전환_2026-10-28.json)에 현재 무결성·API 상태와 검증 범위를 기록했다. 새 원본 수집과 임베딩 재생성은 수행하지 않았다.
