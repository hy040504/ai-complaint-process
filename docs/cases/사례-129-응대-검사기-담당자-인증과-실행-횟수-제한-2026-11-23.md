## 1. 배경

CASE-128로 응대 검사기를 `/lab/` 단독 페이지로 옮기면서, 검사기 API(`/api/v1/assist*`)가 **로그인 없이** 쓰이도록 열려 있다는 점이 공개 주소에서 문제가 됐다. 링크를 숨겼을 뿐 주소를 아는 누구나 외부 LLM(Codex·EXAONE 등)을 호출해 비용과 사용량을 만들 수 있었다.

## 2. 결정

인증과 횟수 제한을 **둘 다** 적용한다.

| 대상 | 규칙 |
| --- | --- |
| `/lab/` 페이지 | 담당자 세션(`cj_staff` 서명 쿠키)이 없으면 `/staff/`(담당자 로그인)로 302 이동 |
| `/api/v1/assist/fields`·`examples`·`assist`·`assist/stream` | 비로그인 **401**, 시민 계정 **403**, 담당자만 허용 |
| 실행(`POST /assist`, `/assist/stream`) | **담당자 계정별 10분에 20회**. 초과 시 **429**(`rate_limited`) |
| 조회(`fields`·`examples`) | 횟수에 포함하지 않음 |

- 코드: `src/complaints/http.py`(`protect_api`, 공개 함수 `has_staff_session`), `src/complaints/pages.py`, `src/complaints/auth.py`(`assist_limiter`), `src/complaints/api.py`.
- 프런트: `siteHeaders()`가 검사기 페이지에서 `X-Cheongju-Site: staff`를 보내 담당자 세션을 쓰고(이전에는 검사기 스트림 요청에 사이트 헤더가 아예 없었다), 세션이 없으면 "담당자 로그인이 필요합니다" 안내와 담당자 사이트 링크를 보여 준다.
- 횟수 제한은 IP가 아니라 **계정 ID** 기준이다. 공개 주소는 Cloudflare 터널을 거쳐 서버가 보는 IP가 한 곳으로 모일 수 있어 IP 기준은 모두를 함께 막을 위험이 있다.

## 3. 영향

- 담당자 콘솔이 부르던 `/assist/fields`(AI 실행 엔진 목록)는 담당자 세션이라 그대로 동작한다. 시민 사이트는 검사기 API를 쓰지 않는다.
- 로컬에서 `/lab/`을 열려면 먼저 `/staff/`에서 담당자로 들어가야 한다(시연 로그인이 켜져 있으면 자동).
- 별도 서비스 `src/lab_web`(`:5010`)은 이번 규칙과 무관하다.

## 5. 한계

- 제한기는 서버 프로세스의 메모리에 있어 서버를 재시작하면 횟수가 초기화되고, 여러 서버 프로세스를 띄우면 합산되지 않는다(현재 1개).
- 담당자 계정이 약하면(시연 계정 포함) 그 계정으로 검사기를 쓸 수 있다. 계정 정리는 운영자 몫이다.
- `/lab/` 페이지의 세션 확인은 쿠키 서명·역할만 본다. 계정이 이후 비활성화돼도 쿠키 유효 기간 동안 페이지는 열리지만, API는 요청마다 계정을 다시 확인한다.
