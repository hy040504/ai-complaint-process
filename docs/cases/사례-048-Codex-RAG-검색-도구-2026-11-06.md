## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 허용 목록이 비어 있어 Codex가 민원 문장을 RAG에 넘길 수 없었다.
- 기대 동작 또는 요구사항: 개발자가 허용한 검색 도구만 열고, 그 조건을 공통 헌법과 작업 프롬프트에 적는다.
- 확인 근거와 시점: 2026-11-06 사용자 요청.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: 검색 API `127.0.0.1:8007`이 이미 떠 있을 수 있다. 이 변경은 그 프로세스를 재시작하지 않는다.
- 개인정보를 제거한 입력, 단계, 실제 결과: 단위 테스트는 가짜 검색 응답으로 후보 축소와 MCP 목록을 본다.
- 버그가 아닌 설계·개선 기록이라면 비교한 기존 동작과 판단 근거: 파이프라인의 Python 선검색은 유지한다. 후보가 없을 때만 모델이 도구를 한 번 호출한다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: Codex는 에이전트라 도구를 열면 셸과 DB까지 쓸 수 있다. 그래서 MCP 도구를 하나로 제한하고 인자는 민원 문장과 네 개 구 이름으로 고정한다.
- 아직 확인하지 않은 가설: 없음.
- 검토한 선택지와 결정 이유: 원시 SQL이나 샌드박스 해제는 쓰지 않는다. 검색은 기존 `/search`의 `retrieval_only` / `requires_gate`만 통과시킨다.
