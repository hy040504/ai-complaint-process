# CASE-021: Flask 서버 코드 구조 간소화

[사례 색인](README.md) · [서버 안내](../../src/README.md)

## 1. 개요와 상태

기준일·기록일: 2026-10-31. 유형: 리팩터링·문서·검증. 사용자 요청에 따라 Flask 서버를 읽기 쉽고 간결하게 구성했다. 로컬 구현·회귀 검증 완료.

## 2. 배경

앱 팩토리에 인증·오류 처리·정적 파일 경로가 중첩되어 앱 생성 순서가 잘 드러나지 않았다. 업무 서비스의 긴 분기 안에는 답변 버전 저장·게시·철회·시연 작업 변경이 섞여 있었다.

## 3. 변경 내용

- `app.py`: 설정·저장소·서비스 생성 후 공통 처리·API·화면을 등록하는 순서로 정리했다.
- `http.py`: 기존 세션 사용자 확인·JSON 직렬화·입력 오류·인증·동일 출처·공통 오류·헤더 처리를 모았다.
- `web.py`: 기존 UI·정적 파일·Swagger·OpenAPI 진입 경로를 Blueprint로 모았다.
- `api.py`: HTTP 공통 처리와 분리하고 명시적인 타입 기반 API 선언을 유지했다.
- `service.py`: 답변 저장·철회와 시연 시작·취소를 전용 메서드로 나눴다. 권한·기대 버전 검사와 트랜잭션 흐름은 기존 서비스·저장소에 유지한다.
- Python 코드는 Black으로 줄바꿈·들여쓰기를 통일했다. 읽을 코드가 짧은 단위로 나뉘도록 한 변경이며 전체 파일 줄 수 감소를 목표로 하지 않았다.

## 4. 검증

2026-10-31 Windows / Python 3.12 / 별도 웹 가상환경에서 수행했다.

| 방법 | 실제 결과 |
| --- | --- |
| `python -m pytest src/tests -q -p no:cacheprovider` | 기존 API 회귀 18개 통과. 권한·비공개·게시·버전·경쟁·저장·문서 경계 확인 |
| `python -m mypy --config-file src/mypy.ini` | 서버 12개 파일 strict 통과 |
| 전후 `/openapi/openapi.json` 전체 JSON 비교 | 동일. API 메서드·경로 18개와 모델·오류·문서 계약 유지 |
| `python -m black --check src` | 형식 검사 통과 |

테스트는 임시 SQLite로 수행한다. 실제 AI·RAG·외부 API·운영 DB를 호출하지 않았다. 로컬 실행 반영은 서버 재시작 후 상태·Swagger·정적 파일을 확인한다.

## 5. 완료 범위와 후속

실행 방법은 `python -m src`, Swagger는 `/docs`를 그대로 사용한다. 업무 DB·모델·API 입력·응답 규격을 확장하지 않는다. 실제 AI·SSE·운영 인증·PostgreSQL 업무 저장은 [서버 안내](../../src/README.md)의 후속 범위다.
