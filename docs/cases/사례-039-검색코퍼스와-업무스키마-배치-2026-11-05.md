## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 루트 `db/`에는 FAQ·사례 JSON과 검색 스키마뿐 아니라 시연 웹 `complaint_app` DDL과 이전 SQLite 잔여가 같이 있었다. 검색 엔진 `rag/`와 자료가 떨어져 있어 한 모듈로 보기 어려웠다.
- 기대 동작 또는 요구사항: 검색 지식은 `rag/origin/`에 두고, 업무 스키마는 `src/complaints/schema/`에 둔다. `python -m rag` 패키지 이름과 PostgreSQL 스키마 분리(`complaint_rag` / `complaint_app`)는 유지한다.
- 확인 근거와 시점: 2026-11-05 사용자 요청. 권장안을 경로·문서까지 적용.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: 저장소 루트, Git 추적 원본 JSON.
- 비교한 기존 동작: CASE-016이 원본·스키마·덤프를 `db/`로 모았다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: 검색 엔진과 원본 자료는 같은 모듈에 두는 편이 적재·백업 경로가 짧다. 시연 웹 DDL을 검색 패키지에 넣으면 민원 CRUD와 지식 색인이 다시 섞인다.
- 검토한 선택지와 결정 이유: JSON을 `rag/` 루트에 코드와 나란히 두지 않고 `rag/origin/` 하위로 모은다. 루트 `db/`는 이전 링크용 안내와 SQLite 잔여를 남긴다.
