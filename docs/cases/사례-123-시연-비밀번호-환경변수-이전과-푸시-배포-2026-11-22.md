# 사례 123: 시연 비밀번호의 환경변수 이전과 푸시·배포

- **사례 번호:** CASE-123
- **기록일:** 2026-11-22 KST
- **유형:** 보안·운영·배포

- **관련 문서:** [CASE-121](사례-121-글자대비-보정과-홈·모바일-개선-및-README-쉬운-개편-2026-11-22.md) · [원격 서버 배포](../harness/원격_서버_배포.md) · [`demo_accounts.py`](../../src/complaints/demo_accounts.py)

## 1. 문제

두 사이트 공통 시연 계정(아이디 `abcd`)을 추가하면서 비밀번호 값이 **코드 상수·테스트·배포 문서·`src/README`·커밋 메시지**에 들어갔다. 이 저장소는 **공개(public)** 이고 공개 주소(`cheongju.mib.dpdns.org`)도 문서에 있어, 푸시하면 누구나 값을 읽고 담당자 화면(총괄 권한)에 들어갈 수 있었다. 해당 커밋 8개는 아직 푸시 전이었다.

## 2. 결정 근거

사용자는 "푸시하고 서버에도 배포"를 요청했고 시연 로그인은 계속 같은 값으로 쓰길 원했다. 그래서 **로그인 값은 바꾸지 않고, 값만 저장소에서 제거**하는 방법을 택했다(서버 DB의 비밀번호 해시는 그대로이므로 사용자 입장의 변화 없음).

## 3. 조치

1. `demo_accounts.py`: 코드 상수를 없애고 환경변수 `COMPLAINT_DEMO_ACCOUNT_PASSWORD`로만 받는다. 값이 없으면 `422 demo_password_missing`으로 계정을 만들지 않는다(코드에 기본값 없음). CLI(`seed-demo-accounts`)는 이를 안내 메시지로 보여 준다.
2. 테스트: 테스트 전용 값을 환경변수로 주입하고, 환경변수가 없을 때 거부하는 테스트를 추가했다(5건).
3. 문서: `원격_서버_배포.md`·`src/README.md`·CASE-121에서 값을 지우고 환경변수 방식 안내로 바꿨다.
4. 서버: `~/.config/cheongju/web.env`에 같은 환경변수를 두었다(파일은 저장소 밖, 값은 출력·기록하지 않음).
5. **기록 정리:** 푸시 전인 로컬 커밋 8개에서 값이 들어간 문자열과 커밋 메시지(`52f7caf` 제목)를 `git filter-branch`로 치환했다. 아직 아무도 받아 가지 않은 로컬 기록이라 안전하며, 푸시 전 `git log -S`로 값이 남지 않았음을 확인한다.

## 4. 한계

- 비밀번호는 여전히 약한 값이다. 환경변수로 옮겨도 **서버에서 그 값을 쓰는 한 추측 가능한 약한 비밀번호**라는 점은 같다. 시연이 끝나면 `deactivate-user`로 끄거나 `seed-demo-accounts`를 새 값으로 다시 실행해 바꾼다.
- 이 문서를 쓰기 전에 대화·터미널 출력에 값이 한 번 나온 적이 있다(저장소 밖).
- 이미 공개된 문서(`8b5e42c` 등)에는 공개 주소가 있다. 주소 자체는 비밀이 아니다.
