## 2. 배경과 결정

기존에는 Jev가 민원의 범위·응답 가능성을 판정하는 구상을 검토했습니다. 사용자는 **Jev 없는 LLM + RAG로 먼저 구현하고 Jev는 추후 추가**하기로 결정했습니다. 한국어 직접 입력, 무료 모델 우선, CLI 챗봇 다음 웹 목업이라는 순서를 유지합니다.

같은 범용 LLM을 의도·근거 판정과 조건부 FAQ 생성에 각각 호출하고, 그 사이에 코드 정책 검사를 두는 구성은 구현 제안입니다. 최종 모델, 임계값, Jev 적용 위치는 미정이며 LoRA도 기준 성능·실패 분석 후 검토하는 제안입니다.

후속 흐름도는 검색 후보를 받은 Jev가 범위·근거를 먼저 살핀 뒤 LLM과 코드 정책 검사로 넘기는 구상입니다. 데이터 범위를 판단하려면 검색 근거가 필요하며, 불확실한 경우 담당자 검토로 연결합니다. 이 적용 위치 역시 후속 평가 대상입니다.

## 4. 확인 결과와 한계

2026-10-25 사례 정리 시 연결된 계획·README·검색 응답 코드를 대조했습니다. 검색 코드의 `requires_gate`는 후속 판단 필요라는 계약이며 Jev 의존성을 뜻하지 않습니다. 위 커밋은 문서 반영과 원격 이력의 근거입니다. LLM·Jev 한국어 성능 평가와 학습은 아직 수행되지 않았습니다.

## 5. 후속 작업

[MVP 실행 계획](../../plan/harness-roadmap.md)에 따라 기준 데이터·평가셋, LLM 어댑터, 정책 검사, CLI 챗봇을 구현합니다. 모델·판정 계약을 실제로 바꿀 때는 새 구현 사례를 만들고 이 결정을 연결합니다. 결정을 대체하면 기존 기록을 남기고 대체 사례와 날짜를 표시합니다.
