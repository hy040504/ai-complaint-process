## 1. 요청

1. 서비스 이름이 "민원톡톡"(시민 로고·담당자 바닥글·검사기)과 "청주톡톡"(페이지 제목·README)으로 섞여 있어 **청주톡톡으로 통일**한다.
2. CASE-131 점검의 1번: **로그인하지 않은 방문자에게 민원 게시판이 막혀** 공개 민원 대신 로그인 안내만 보이던 문제를 고친다.

## 2. 이름 통일

- 시민 머리글 로고 글자("민원<span>톡톡</span>" → "청주<span>톡톡</span>"), 홈 링크 이름, 담당자 바닥글, 민원 웹의 검사기(`/lab/`) 띠·바닥글, 별도 검사기(`src/lab_web`, `:5010`)의 제목·머리글·바닥글, 아이콘 주석과 안내 문서를 바꿨다.
- 과거 사례·업무 보고서·시안 파일의 "민원톡톡"은 당시 기록이라 그대로 뒀다.

## 3. 비로그인 민원 게시판 열람

**원인:** 시민 화면은 게시판·상세를 `/workspace` 응답 하나로 그리는데, 이 API는 세션이 있어야 한다. 그래서 화면이 방문자에게는 게시판·상세를 막고 로그인 안내를 보여 줬다. README 역할 표는 원래 "게스트도 공개된 민원 보기 가능"이라고 적혀 있었다.

**조치:**

| 위치 | 변경 |
| --- | --- |
| 서버 `GET /api/v1/public/workspace` (새로 추가) | 로그인 없이 **공개(`public`)이고 철회되지 않은 민원만** 반환. 시민 응답과 같은 변환(`project`)을 거쳐 초안·AI 원문·AI 결과·내부 이력을 빼고, 어떤 작성자와도 다른 방문자로 변환해 **첨부 목록은 항상 비움**. 세션을 만들지 않음. 담당자가 게시판에서 내린 민원은 비공개라 빠짐 |
| `protect_api` | 위 경로만 로그인 없이 허용(읽기 전용) |
| 화면 | 세션 없는 방문자가 **민원 게시판·민원 상세**를 열면 이 API로 목록을 채움. "내 민원·알림·내 정보"는 계속 로그인 안내 |
| 화면(함께 고친 결함) | 방문자를 시연 민원인(`citizen-demo`)으로 간주하던 대체값을 없앰. 그대로 두면 방문자가 시연 민원을 열 때 수정·삭제·추가 문의 버튼이 보였다(서버는 막지만 화면이 잘못 안내). 방문자는 이제 어떤 민원의 작성자로도 잡히지 않음 |
| 화면 메뉴 | 방문자가 연 민원 상세는 위쪽 메뉴의 "민원 게시판"에 표시(전에는 "나의 민원") |

## 5. 한계

- `/public/workspace`는 공개 민원 전체를 한 번에 돌려준다. 시연 규모에서는 문제없지만 민원이 많아지면 페이지 단위 공개 API와 요청 제한이 필요하다.
- 방문자 화면은 처음 불러온 시점의 목록이다. 새로 고치면 최신 목록을 받는다(방문자에게는 실시간 갱신 없음).
