## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: CASE-051·052는 이웃 출력과 모델 전환에 집중했다. 루트 README 다음 단계는 이미 끝난 5,109건 재임베딩을 아직인 일로 적었다. 문장 이웃 조회는 검색 엔진과 달리 HNSW `iterative_scan`을 켜지 않았다.
- 기대 동작 또는 요구사항: 한국어 Google 형식 docstring, 패치와 같은 현재 문서, 이웃 순위가 검색 엔진의 벡터 경로와 같은 HNSW 설정을 쓴다.
- 확인 근거와 시점: 2026-11-06 사용자 요청 「주석 점검, readme/docs 업데이트, readme 디자인 개선, 코드 최적화, 깃헙 업로드」.

## 3. 재현·확인 방법

- 비교한 기존 동작: `vector.tolist()` 뒤 다시 float 변환, 이웃 조회에 `hnsw.ef_search`만 설정, README 「운영 DB 5,109건 재임베딩」을 다음 단계로 표시.
- 판단 근거: ndarray를 바로 순회하면 목록을 한 번만 만든다. 검색 엔진은 `strict_order`로 HNSW 순서를 고정한다. 이 호스트 재임베딩은 CASE-052에서 끝났다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: CASE-051·052는 동작 수정에 집중했고 주석·현재 문서·소규모 최적화를 이 작업으로 넘겼다.
- 검토한 선택지와 결정 이유: 하이브리드 검색을 문장 CMD에 넣지 않는다. 모델 가중치와 dump는 Git에 넣지 않는다.
