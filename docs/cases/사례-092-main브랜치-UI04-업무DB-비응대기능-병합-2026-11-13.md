## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향:
  1. `llm` 브랜치는 응대 검사기(`src/lab_web` `:5010`), `K-EXAONE 2.5`·`GPT-6 Luna`·`Codex CLI` 연동, 네이버 지도 MCP 추적, `PREFIX-00~04`, HTTP 429 완화 등 LLM 파이프라인 중심으로 발전한 반면, `origin/main`에는 팀이 별도로 진행한 두 축의 비응대 기능이 반영되어 `llm`에 누락되어 있었습니다.
  2. `origin/main`의 최신 커밋 `1b96e00`에는 과거 `llm` 검사기를 `main`으로 부분 이식한 코드가 포함되어 있어, 단순 `git merge origin/main`을 수행할 경우 현재 `llm` 브랜치의 최신 LLM·검사기 로직과 충돌하거나 회귀를 일으킬 위험이 있었습니다.
  3. `origin/main`에는 `AGENTS.md` 및 `README.md`의 네이티브 실행 원칙("Docker 없이 수행")과 어긋나는 Docker 파일(`compose.yaml`, `rag/Dockerfile`, `.dockerignore`)도 존재했습니다.
- 기대 동작 또는 요구사항:
  1. `origin/main`의 **업무 DB 실행 설계·생성 칼럼·CHECK 제약·공개 시연 데이터(`db/`, `demo_data.py`, `seed-public-demo`)**와 **시민 UI02~04·담당자 답변 편집기 개선(`/design/ui04`, `ui/src/*`)**은 누락 없이 반영합니다.
  2. `AGENTS.md` 원칙에 따라 Docker 관련 3개 파일(`compose.yaml`, `rag/Dockerfile`, `.dockerignore`)은 제외합니다.
  3. `:5000` SPA의 기본 해시는 `main`과 동일하게 `#/citizen`으로 정렬하되 `/#/lab` 경로는 유지하고, `:5010`(`src/lab_web`), `src/assist/*`, `src/llm/*`, `src/rag/*`, `docs/harness/prompts/*` 등 `llm` 브랜치의 응대 검사기·LLM 로직은 전혀 덮어쓰지 않습니다.

## 3. 원인 분석 또는 결정 근거

- 브랜치 diff 비교 결과(`llm` `HEAD 74f3d74` vs `origin/main` `1b96e00`):
  - **그룹 A (업무 DB·시연 데이터, 커밋 `6283fd2`, `0907a7d`, `b302c7b`, `862fceb`, `cd924f2`):** `complaint_app.complaints` 테이블의 `STORED` 생성 칼럼 5개(`status`, `owner`, `visibility`, `district`, `is_synthetic`), 복합 인덱스 2개, `CHECK` 제약 `_VALUE_CHECKS` 3종, `DEMO-PUB-` 시연 플래그 백필, `PublicComplaint.is_synthetic`, `seed-public-demo` CLI, `db/` 샘플 SQL/JSON 적재 도구 및 `업무DB_실행설계.md`.
  - **그룹 B (시민 UI02~04·편집기 개선, 커밋 `534f30b`, `eef0112`, `78e1dfb`, `d0eb677`, `49a099a`):** `minwon-toktok-ui04.html` + `ui04-adapter.js` (`/design/ui04`), 담당자 답변 편집기(`PHRASES` 문구 바, 글자 수 카운터, `Ctrl+S`/`⌘S` 단축키, `staffPager`, `daysSince`, `#draft-state`, `<details class="history-panel">`), 시민 요약(`nextStepBox`, `foldAnswer`, `scope-tabs`, `origin-badge`).
  - **제외 대상:** `1b96e00`(과거 `llm`의 구버전 검사기 이식), Docker 파일 3종, 이미 `llm`에서 최신화된 검색·환경·MCP·LLM 모듈 전체.
- 선택적 반영 전략: `1b96e00` 직전 UI 커밋 `49a099a`에서 비응대 UI 자산을 가져오고 `origin/main`에서 비응대 DB/목업 파일을 가져온 뒤, `models.py`·`repository.py`·`seed.py`·`app.py`·`pages.py`는 `llm` 최신 파일 위에 해당 기능만 수동 병합했습니다.
- 추가 정비: `49a099a`의 `ui/src/app.js`에서 `nextStepBox`/`foldAnswer`/`staffPager` 삽입으로 인해 `citizenProgress`의 JSDoc 주석이 분리되어 있던 위치를 바로잡고, `ui/scripts/check-syntax.mjs` 검사 대상에 `adapters/`를 추가했습니다.
