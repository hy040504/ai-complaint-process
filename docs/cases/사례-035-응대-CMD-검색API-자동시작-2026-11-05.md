## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 검색 API가 꺼진 상태에서 `민원-응대.cmd`에 민원 문장을 넣으면 `http://127.0.0.1:8007` 연결 실패로 바로 종료됐다.
- 기대 동작 또는 요구사항: localhost 검색 API가 없으면 `python -m rag serve`를 별도 창에서 시작하고, health가 ready가 된 뒤 응대를 이어 간다.
- 확인 근거와 시점: 2026-11-05 사용자 요청.

## 3. 재현·확인 방법

- 비교한 기존 동작: 꺼진 API는 오류 문구만 출력하고 종료.
- 판단 근거: Flask `웹-시작.cmd`와 같이 새 콘솔에서 서버를 유지하고, 이미 ready이거나 포트만 열린 경우에는 중복 기동하지 않는다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: 응대 CMD는 HTTP 클라이언트이며 검색 엔진 프로세스를 스스로 띄우지 않았다.
- 검토한 선택지와 결정 이유: 원격 `RAG_API_URL`은 자동 시작하지 않는다. 검색 실행 파일은 `RAG_PYTHON` 또는 `.venv`(FastAPI·uvicorn 프로브)를 쓰고, Flask용 `.venv-web`은 의존성이 없으면 쓰지 않는다. `--no-start`로 기존처럼 연결만 검사할 수 있다.
