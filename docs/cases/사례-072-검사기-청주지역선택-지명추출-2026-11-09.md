## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 검사기 발생 지역 칸에 4개 구(상당구·서원구·흥덕구·청원구)만 있어 세부 동/읍/면 선택이 불가능했고, 발생 지역을 비우면 본문에 "가경동", "오송읍" 등의 지명이 있어도 SQL 구 필터 없이 텍스트 유사도 검색만 수행되었다.
- 기대 동작 또는 요구사항:
  1. 검사기 작성 양식에서 청주시 4대 구 산하 읍·면·동 세부 지역을 한눈에 선택할 수 있어야 한다.
  2. 발생 지역 칸을 비워두더라도 제목이나 상세 본문에 청주시 지명이 단일하게 감지되면 자동으로 해당 구를 판별하여 검색 API의 `district` 필터로 연결하고 결과 화면에 안내 배지를 띄워야 한다.
  3. 2개 이상의 구가 상충하거나 지명이 없으면 필터를 걸지 않아 검색 누락을 방지해야 한다.
- 확인 근거와 시점: 2026-11-09 사용자 질의 「제목이나 내용에 지역과 장소를 입력해놨다면 그것도 파악해서 찾도록 되어있는 로직이 있나?」 및 추가 요구 「응대검사기에 저런 청주 전체 지역들을 더 선택할 수 있게 추가해줘」.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: `http://127.0.0.1:5010/` 검사기 웹 접속.
- 단계:
  1. 발생 지역 셀렉트를 열면 상당구·서원구·흥덕구·청원구 아래 각 구 산하 읍·면·동들이 `optgroup`으로 표시된다. 세부 지역(예: `흥덕구 복대동`)을 선택하고 전송하면 `effectiveDistrict`에 `흥덕구`가 적용된다.
  2. 발생 지역을 `지정하지 않음 (본문 자동 감지)`으로 두고 본문에 "가경동 터미널 앞 불법주차"를 입력하여 전송하면, 결과 화면에 `📍 발생 지역: 흥덕구 (본문 지명 자동 감지)` 배지가 표시되고 공개 사례 검색 시 흥덕구 필터가 적용된다.
- 비교한 기존 동작: 4개 구 단일 옵션만 존재했으며, 본문 지명은 SQL 필터 없이 단순 유사도로만 매칭되었다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: 청주 민원 검색은 Search-then-LLM 구조로 검색이 LLM 판정보다 먼저 실행된다. 따라서 검색 필터용 지명 인식은 LLM 호출 전에 규칙 기반으로 1ms 내에 결정론적으로 수행되어야 한다.
- 검토한 선택지와 결정 이유:
  1. `PACKET/department_normalization.py`의 현행 행정구역 데이터를 기반으로 `src/assist/district.py`를 신설하여 4개 구 및 모든 관할 읍·면·동(법정동·행정동) 매핑과 정규화기 `normalize_district`, 지명 추출기 `extract_district`를 구현했다.
  2. 명시적 선택을 최우선으로 보존하고(`resolve_complaint_district`), 지명이 없거나 상충(복수 구 감지) 시 `None`을 반환하여 잘못된 필터링에 의한 누락을 방지했다.
  3. `GET /api/v1/lab/fields` 응답에 `districtAreas`를 제공하고, 검사기 프론트엔드가 `<optgroup>`으로 전체 지역을 그룹화하여 표시하도록 했다.
