## 2. 사용자 요구와 기존 문서의 차이

사용자는 두 개발자의 기술 역량을 바탕으로 역할·작업 분담을 요청했고, 이후 실제 게시판 목록·기본 CRUD·담당자 답변 화면·AI 작성 표시·AI 답변 수정·실시간 작업 상황 모니터를 구체화해 달라고 요청했다. 해당 내용과 앞선 제안을 통합한 한국어 Markdown·PDF, 이해를 돕는 그림, GitHub 업로드도 요청했다.

기존 CASE-007과 웹 계획은 등록·조회·답변·저장 중심이었다. 수정·삭제·실시간 상태·게시 전 초안·수정 기원·경쟁 처리의 규칙과 2인 작업 단위가 충분히 구체화되지 않았다.

## 3. 확인 방법

README·AGENTS·하네스·웹/LLM 계획·실행 과제와 CASE-007·008을 읽고 현재 검색 구현과 미구현 범위를 대조했다. 원본 데이터·실행 DB·모델·다른 서비스는 변경하지 않는다. `.config/`는 기존 미추적 사용자 파일로 유지한다.

## 4. 결정 근거

- 1.0~1.1판은 두 사람의 기술 경험을 바탕으로 A/B 역할을 제안했다. 1.2판부터 사용자 요청에 따라 개인별 배정을 빼고 UI·백엔드·AI·DB 네 분야의 구현 작업으로 정리한다. 기존 기능 범위는 유지한다.
- AI 기원·원본과 사람이 수정한 버전을 함께 보존한다. 게시된 답변의 조용한 덮어쓰기를 막고 게시·정정·철회를 구분한다.
- 민원·AI 작업·답변 게시 상태를 분리하고 실제 단계 이벤트로 모니터한다. SSE·작업자·Flask·게시 모드는 구현 제안이며 사용자 확정 기술로 표시하지 않는다.
- 초기 AI 방향은 LLM + RAG이며 Jev·Papago·LoRA는 후속이다. 검토 우선 개발 시연과 검수 FAQ의 제한 자동 안내를 구분한다.

### PDF 재생성

Chrome과 `markdown-it-py`, NanumGothic Regular/Bold 글꼴이 필요하다. 글꼴은 [Google Fonts 원본](https://github.com/google/fonts/tree/main/ofl/nanumgothic)의 `NanumGothic-Regular.ttf`, `NanumGothic-Bold.ttf`를 같은 로컬 폴더에 준비한다. 글꼴 파일 자체는 저장소에 추가하지 않았고 PDF에 사용한 글리프를 포함했다. 글꼴 라이선스는 해당 원본의 `OFL.txt`를 따른다.

저장소 루트에서 아래처럼 실행한다. `--font-dir`에는 준비한 글꼴 폴더를 지정한다. 예시의 `/tmp/complaint-doc-fonts`는 사용자가 파일을 준비할 위치다.

```bash
python3 -m venv /tmp/complaint-docs-venv
/tmp/complaint-docs-venv/bin/pip install -r docs/tools/requirements.txt
/tmp/complaint-docs-venv/bin/python docs/tools/export_design_pdf.py plan/민원_웹_MVP_상세설계와_분야별_작업계획.md --font-dir /tmp/complaint-doc-fonts
```

Markdown의 `<!-- page -->`를 기준으로 페이지를 나누고 HTML 본문과 바닥글이 겹치면 생성을 중단한다. 그림은 PDF에서 벡터로 유지한다. 출력 파일 기본값은 원본과 같은 이름의 `.pdf`다.
