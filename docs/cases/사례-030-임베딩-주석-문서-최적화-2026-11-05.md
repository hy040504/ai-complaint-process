## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: CASE-029에서 e5-small 기본값과 `민원-응대.cmd`를 넣었으나, `connect` 주석이 docstring 위에 남아 있었고 임베딩마다 토크나이저를 한 번 더 돌렸다. 데이터 계약은 여전히 8192토큰 초과 시 적재 중단이라고 적혀 있었다. README 배너·상태 표에 CMD와 e5-small이 빠져 있었다.
- 기대 동작 또는 요구사항: 한국어 Google 형식 docstring, 패치와 맞는 문서, README에서 가벼운 임베딩과 CMD가 바로 보이고, 중복 계산을 줄인다.
- 확인 근거와 시점: 2026-11-05 사용자 요청 「주석 점검, readme/docs 업데이트, readme 디자인 개선, 코드 최적화」.

## 3. 재현·확인 방법

- 비교한 기존 동작: `Models.encode`가 문서마다 `tokenizer.encode`를 호출한 뒤 SentenceTransformer가 같은 입력을 다시 토큰화한다. `schema_sql()`은 호출마다 파일을 읽는다. 차원이 같아도 `SET NOT NULL`을 반복한다.
- 판단 근거: SentenceTransformer가 이미 `max_seq_length`에서 자른다. 원문 저장과 BM25는 호출 측이 유지한다. 차원 열이 바뀐 뒤에만 NOT NULL을 다시 건다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: CASE-029는 동작 변경에 집중했고 주석·문서·중복 경로를 이 작업으로 넘겼다.
- 검토한 선택지와 결정 이유: 긴 본문 경고를 위해 토크나이저를 따로 돌리지 않는다. 경고 대신 데이터 계약에 프로필 한도 절단을 명시한다. 기존 dump의 1024차원 기록은 2026-10-24 스냅샷으로 남긴다.
