## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 민원 CRUD와 응대 LLM·검색 호출이 `src/` 루트와 `rag/assist.py`에 섞여 있어 백엔드 경계를 읽기 어려웠다.
- 기대 동작 또는 요구사항: 민원 웹 서버, RAG, LLM을 각각 두고 둘을 잇는 코드를 명시적으로 구현한다. API 경로와 검색 전용 계약은 유지한다.
- 확인 근거와 시점: 2026-11-05 사용자 요청.

## 3. 재현·확인 방법

- 비교한 기존 동작: `src/assist.py`가 `rag.assist`를 감싸고, LLM 어댑터는 `rag/assist.py`에 있었다.
- 판단 근거: 검색 엔진(루트 `rag/`)은 그대로 두고, 웹 백엔드만 패키지로 나눈다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: 응대 계층이 검색 패키지 안에 있어 Flask 백엔드와 책임이 겹쳤다.
- 검토한 선택지와 결정 이유: 색인·임베딩은 루트 `rag/`에 남긴다. `src/rag`는 검색 API 클라이언트만 둔다. 민원 저장과 검색 색인을 합치지 않는다.

## 5. 조치와 변경 내용

| 파일·계약 | 변경 내용 | 구현·반영 상태 |

## 7. 완료 조건·후속 작업·복구

- 완료: 세 백엔드 패키지와 `src.assist.run_assist`가 검색 다음에 LLM을 호출하고, 기존 API 경로가 유지된다.
- 남은 작업: 시민 챗봇을 `/assist`에 연결, 담당자 작업의 실제 LLM, 실측 평가.
- 되돌림: `src/complaints`·`src/rag`·`src/llm`·`src/assist`를 이전 단일 모듈 배치로 합치면 된다.
