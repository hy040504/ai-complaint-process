## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: CASE-026 분리 뒤 LLM 모듈에 JSON HTTP가 한 벌 더 있었고, 같은 검색 응답을 FAQ·사례·부서·색인으로 여러 번 순회했다. 환경 LLM은 판정과 FAQ 생성마다 설정을 다시 읽었다. README 배너 오른쪽 카드가 영어라 백엔드 네 패키지가 한눈에 보이지 않았다.
- 기대 동작 또는 요구사항: 전송 함수는 한 곳, 검색 조각은 요청당 한 번, LLM 설정은 환경 공급자일 때 한 번. README는 지금 됨·검사기·아직과 네 패키지를 바로 보여 준다.
- 확인 근거와 시점: 2026-11-05 사용자 요청 「readme 디자인 개선이랑 코드 최적화 이어서 해줘」.

## 3. 재현·확인 방법

- 비교한 기존 동작: CASE-027 직후 `src/llm/complete.py`의 자체 `http_json`, `decision_prompt`·`validate_decision`·`build_result`의 각각 `search_parts`/`faq_hits` 호출, README 배너 영어 카드.
- 판단 근거: 검색 색인 로직을 LLM에 넣지 않고 전송만 공유한다. 정책 함수는 `parts`를 생략하면 이전처럼 스스로 만든다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: 패키지 분리 때 전송·히트 추출을 각 모듈에 복사해 경계를 지켰고, README는 CASE-025에서 영문 카드로 맞춰 두었다.
- 검토한 선택지와 결정 이유: `src.rag.http.http_json`을 LLM이 가져오도록 해 테스트의 `src.llm.complete.http_json` 패치를 유지한다. `SearchParts` NamedTuple로 한 번 순회한 결과를 판정·정책·FAQ 생성·결과 조립에 넘긴다.
