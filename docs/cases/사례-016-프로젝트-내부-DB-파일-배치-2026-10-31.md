## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 스키마 SQL은 빈 테이블만 만들고, 검색 원문은 `db/*.json`에 있으며 벡터는 호스트 PostgreSQL에 있다. 파일을 다른 컴퓨터로 옮길 때 SQL만 복사하면 검색 자료를 쓸 수 없다.
- 기대 동작 또는 요구사항: 프로젝트 안에서 실제 데이터 파일 위치를 한곳으로 모으고, 프로그램 경로와 우분투 dump 내보내기·복원 명령을 맞춘다.
- 확인 근거와 시점: 2026-10-31 사용자 요청.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: 저장소 루트의 `db/`, `rag/store.py`, `src/config.py`.
- 버그가 아닌 설계·개선 기록이라면 비교한 기존 동작과 판단 근거: 이전에는 `rag/schema.sql`과 `.web-data/complaints.sqlite3`를 각각 읽었다. JSON은 이미 `db/`에 있었다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: PostgreSQL 데이터 디렉터리와 벡터 dump는 Git에 넣을 수 있는 원문이 아니다. 원문 JSON과 DDL은 저장소에 두고, 벡터 dump는 `db/dumps/`에 두되 Git에서 제외한다.
- 아직 확인하지 않은 가설: 없음.
- 검토한 선택지와 결정 이유: 클러스터 파일(`/var/lib/postgresql`)을 프로젝트에 복사하면 다른 컴퓨터에서 열리지 않는다. 논리 dump와 JSON+ingest를 사용한다.
