## 1. 배경 및 목표

`CASE-110`·`CASE-111`에서 시민 AI 챗봇 실연결, 민원인·담당자 아이디/비밀번호 로그인, PostgreSQL 7테이블 정규화를 완료했으나, 실제 민원 웹(`:5000`) 운영 체험 관점에서 아래 두 영역의 실무 완성도 격차가 남아 있었습니다.

1. **시민 민원 도우미(`#/citizen/assistant`) 단발성 대화 한계:**
   - 이전 턴 문맥을 기억하지 못해 `"그럼 수수료는요?"`, `"오창읍이에요"` 같은 자연스러운 후속 질문이 독립 질의로 취급되고, 새로고침 시 대화 이력이 모두 사라졌습니다.
   - 추가 LLM 호출(질의 재작성 호출)을 붙이면 응답 지연과 비용이 늘어나므로, **추가 LLM 호출 0회(0ms) 규칙 보강 + `PREFIX-00~02` 바이트 동일 유지(Prefix Caching 보존)** 원칙을 지키면서 로그인 민원인 PostgreSQL 영속 저장과 비로그인 시연 시민 탭 임시 저장을 구분해야 했습니다.
2. **담당자 업무 현황 파악·검색·보고서 내보내기 부재:**
   - 담당자 콘솔에 상태·구·분야·AI 판정·배정 부서별 통계와 드릴다운 화면이 없었고, 업무 큐(`ui/src/staff.js` · `service.py:page()`)가 **제목만 검색**하며 `queueRows()` 담당자 배지에 `"김담당"`이 하드코딩되어 있었습니다.
   - 공개 시연 데이터(`DEMO-*`)와 실제 민원을 분리 집계·조회하고, 부서 RBAC 소관 범위가 강제된 **수식 주입 방어 CSV 내보내기**(미게시 초안·순화 본문 제외)가 필요했습니다.

## 2. 조치 내용

### 2.1 시민 다중 턴 챗봇 및 PostgreSQL 영속 저장

- **PostgreSQL 업무 스키마 확장 (`src/complaints/schema/complaint_app.sql`, `src/complaints/repository.py`):**
  - `complaint_app.chat_sessions` (`id`, `user_id REFERENCES users(id) ON DELETE CASCADE`, `title`, `last_district`, `created_at`, `updated_at`) 및 `complaint_app.chat_messages` (`id`, `session_id REFERENCES chat_sessions(id) ON DELETE CASCADE`, `role CHECK ('user'|'assistant')`, `content`, `district`, `outcome CHECK`, `reason_code`, `payload jsonb`, `created_at`) 테이블과 사용자/세션 인덱스를 추가했습니다.
  - 저장 `payload`에는 민감 필드(`staffDraft`, `sanitize`, `codex`, `cases`, `modelRaw`)가 구조적으로 제거된 **`CitizenChatResponse` JSON만** 저장합니다.
- **0ms 다중 턴 문맥 보강 및 Prefix Caching 보존 (`src/complaints/chat.py`, `src/assist/policy.py`, `src/assist/pipeline.py`, `src/assist/__init__.py`):**
  - `build_multiturn_chat_context(message, explicit_district, history)`가 짧은 후속 질문·지명 보완 발화에 직전 사용자 주제와 청주 관할 구를 0ms 규칙으로 보강하고, 명시적 주제 전환(`"다른 질문인데요..."`)이나 타 지자체 언급(`"천안시..."`)·신규 청주 지명(`"오창읍이에요"`) 시에는 이전 문맥 오염을 차단합니다.
  - 최근 8건(4턴 쌍)의 요약 이력 `conversation_history`는 `PREFIX-01`·`PREFIX-02`의 **가변 `user` JSON에만** 주입해 불변 시스템 접두 `PREFIX-00~02`의 바이트 동일성과 Prefix Caching을 그대로 유지합니다(단일 턴 호출 시 키 생략).
- **권한별 저장 경계 및 API (`src/complaints/service.py`, `src/complaints/api.py`, `src/complaints/models.py`):**
  - **로그인 민원인 (`actor.role == "citizen" and not actor.demo`):** `POST /api/v1/citizen/chat(/stream)`에서 `sessionId` 자동 생성·DB 이력 자동 주입·교환 원자 저장(`persisted=True`), `GET /api/v1/citizen/chat/sessions`, `GET /api/v1/citizen/chat/sessions/{session_id}`, `DELETE /api/v1/citizen/chat/sessions/{session_id}` 제공.
  - **엄격한 소유자 격리:** 타 민원인의 세션 조회·이어쓰기·삭제는 `404 not_found`, 담당자 계정의 시민 챗봇 세션 접근은 `403 citizen_required`로 차단합니다.
  - **비로그인 시연 시민 (`actor.demo == True`):** DB에 저장하지 않고(`persisted=False`, `sessionId=None`) 요청 `history` 배열(최대 12건)과 브라우저 `sessionStorage`(`citizen-anon-chat-v1`)로 임시 다중 턴 대화를 이어가며 상단에 `"로그인하면 대화가 저장됩니다"` 배지를 표시합니다.
- **시민 UI (`ui/src/chatbot.js`, `ui/src/app.js`, `ui/src/citizen.css`, `ui/src/themes.css`):**
  - 상단 세션 바(로그인 시 `내 대화 자동 저장`·세션 칩 클릭 복원·`×` 삭제·`새 대화`, 비로그인 시 로그인 유도 배지), 다중 턴 문맥 반영 안내 행, `"이 내용으로 민원 작성"` 클릭 시 세션 내 다중 턴 시민 발화를 민원 본문으로 결합해 `#/citizen/write`로 이관하는 기능을 연동했습니다.

### 2.2 담당자 통계 대시보드(`#/staff/stats`) · 큐 통합 검색/정렬 · 안전 CSV 내보내기

- **RBAC 소관 통계 집계 API (`GET /api/v1/staff/stats`, `src/complaints/service.py`, `api.py`, `models.py`):**
  - `staff_admin`(`actor.department is None`)은 전체 민원(`isAdminScope=True`), 부서 담당자(`staff_seowon`, `staff_heungdeok`)는 **미배정 + 소속 부서 배정 민원만** 집계(`isAdminScope=False`, `_in_staff_scope()` 강제)합니다.
  - `includeSynthetic=1|0` 토글로 공개 시연(`DEMO-*`) 포함/제외를 지원하며, 운영 KPI 11종(`openCount`, `avgOpenDays`, `unassignedCount`, `unpublishedDrafts`, `withFollowups`, `aiFailed`, `aiRunning` 등), 5종 드릴다운 분포(`byStatus`, `byDistrict`, `byCategory`, `byAiOutcome`, `byDepartment`), 정규화 7테이블 `dbSummary`를 반환합니다.
- **안전 CSV 내보내기 API (`GET /api/v1/staff/complaints/export.csv`):**
  - 담당자 RBAC 소관 범위 및 현재 화면 필터(`q`, `status`, `district`, `category`, `assign`, `view`, `aiOutcome`, `sort`, `includeSynthetic`)를 그대로 반영합니다.
  - 한글 엑셀 호환 **UTF-8 BOM (`\ufeff`)**, `_csv_safe_cell()`을 통한 **CSV 수식 주입(`=`, `+`, `-`, `@`, `\t`, `\r` 선두 `'`) 중화**를 적용하고, **업무 메타데이터 15열만 출력**하여 미게시 AI 초안(`draft`/`ai_original`/`staff_draft`)과 직원 보호 순화(`sanitize`) 본문을 원천 제외합니다.
- **담당자 콘솔 UI 업그레이드 (`ui/src/staff-stats.js`, `ui/src/staff.js`, `ui/src/app.js`, `ui/src/icons.js`, `ui/src/staff.css`, `ui/src/themes.css`):**
  - 좌측 `MANAGE` 메뉴·모바일 빠른 메뉴에 `통계 대시보드` (`#/staff/stats`)를 추가하고 6개 KPI 카드, 5개 클릭형 가로 막대 차트(클릭 시 `#/staff/complaints?...`로 해당 필터 + `synthetic` 상태 유지 드릴다운), 정규화 7테이블 요약표를 라이트·다크 테마로 구현했습니다.
  - `#/staff`·`#/staff/complaints` 및 `GET /api/v1/complaints` 검색을 **제목 + 본문 + 민원ID + 배정부서 통합 검색**으로 확장하고, `AI 판정` 필터·`정렬(최신/오래된 미처리/추가 문의 많은순/미게시 초안 우선)`·`공개 시연 포함/제외` 토글·`CSV 내보내기` 버튼을 추가했으며, `queueRows()`의 하드코딩 `"김담당"` 배지를 `c.assigneeName || "담당 지정"`으로 수정했습니다.

## 4. 남은 한계 및 후속 범위

- **첨부파일 업로드·외부 PASS/행정 SSO·다중 워커 브로커·공식 행정 이관:** 사용자 결정에 따라 본 작업 범위에 포함하지 않았으며 후속 범위로 유지합니다.
- **장기 다중 턴 대화 요약 압축:** 현재는 최근 8개 발화(4턴 쌍) 슬라이딩 윈도와 0ms 직전 주제 보강으로 추가 LLM 지연을 0초로 유지합니다. 10턴 이상의 매우 긴 상담을 압축 요약하는 기능은 향후 필요 시 선택 확장으로 둡니다.
- **CSV 대규모 스트리밍:** 현재 시연·중소 규모 운영에 맞춰 메모리 버퍼 CSV로 응답하며, 수만 건 이상 대량 내보내기에는 커서 기반 청크 스트리밍 전환이 필요합니다.
