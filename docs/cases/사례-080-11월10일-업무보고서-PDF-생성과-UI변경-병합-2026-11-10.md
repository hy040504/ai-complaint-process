## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향:
  - 11월 9일 업무보고서에 이어 11월 10일 작업 내용(원클릭 기동, 장소 추적 MCP, 검사기 안정화 등)을 정규 업무보고서로 작성해야 함.
  - 협업 팀원인 기민 님이 오늘 시민·담당자 화면 UI 변경 내역을 6페이지 분량의 "UI 변경 보고서" PDF로 작성하여 전달함.
- 기대 동작 또는 요구사항:
  - 1페이지: `업무보고_20261109.pdf`의 기존 양식(테이블 레이아웃, 연승현 톤, 팀원 '기민 님' 호칭)을 정확히 계승하여 11월 10일의 서버/AI 작업 및 UI 변경 사항 점검 결과를 딱 1페이지로 완결성 있게 작성.
  - 2~7페이지: 기민 님이 작성한 `UI_변경_2026-11-10.pdf`의 원본 6페이지를 서식과 이미지 손실 없이 그대로 병합.
  - 카카오톡 다운로드 폴더 및 프로젝트 내부 `docs/` 폴더에 동시 저장.

## 3. 재현·확인 방법

- PDF 생성 스크립트 실행:
  ```powershell
  .venv-web\Scripts\python.exe scripts/업무보고_20261110_pdf_생성.py
  ```
- 생성된 PDF의 총 페이지 수 및 텍스트 검증:
  - 총 7페이지 (1페이지: 메인 표, 2~7페이지: UI 변경 보고서 원본).
  - 텍스트 추출 검사로 누락이나 잘림 없이 1페이지 표가 단일 페이지에 온전히 렌더링되는지 확인.

## 4. 원인 분석 또는 결정 근거

- 헤드리스 크롬과 pypdf의 결합:
  - HTML/CSS로 구성된 1페이지 메인 표를 헤드리스 크롬의 인쇄 엔진으로 정밀 렌더링(`--print-to-pdf`, `--no-pdf-header-footer`)하여 텍스트 흐름과 표 외곽선 무결성을 확보함.
  - 이후 `pypdf.PdfWriter`를 통해 1페이지 PDF와 기민 님의 원본 PDF 6페이지를 스트림 손실 없이 병합하여 총 7페이지로 완성.
- 경로 탐색 폴백(Fallback) 구조:
  - 로컬 카카오톡 다운로드 폴더에서 파일이 삭제되거나 이동되더라도 스크립트가 중단되지 않도록, 프로젝트 내부 `docs/UI_변경_2026-11-10.pdf`를 보관하고 순차 탐색하도록 방어 로직 구현.
