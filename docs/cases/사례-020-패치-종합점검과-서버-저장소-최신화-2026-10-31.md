## 1. 개요와 상태

기준일·기록일: 2026-10-31. 누적 웹·Flask·테마·DB 경로 패치의 코드·한국어 주석·문서·서버·Git 상태를 점검했다. 로컬 점검은 완료했으며 원격 반영은 후속 이력으로 기록한다.

## 2. 배경

누적 패치는 미커밋 상태였고 원격 main에는 독립 LLM 예제 관련 커밋 두 개가 더 있었다. README 상단이 현재 웹 구현을 예정으로 표시하고, JavaScript JSDoc의 인자·반환 설명이 누락되어 있었다.

## 3. 확인·조치

한국어 JSDoc·Python 초기화 메서드 설명을 보완하고 JS·CSS·HTML 형식을 정리했다. 전체 JS를 자동 수집하는 문법 검사로 신규 테마 모듈의 검사 누락을 방지했다. 브라우저 저장이 차단되면 테마 재전환이 실패하는 문제를 현재 탭의 `getTheme()` 상태로 수정하고 회귀를 추가했다. 공개 DTO의 중복 직렬화·검증을 제거했다. 전체 성능 개선율은 측정하지 않았다.

## 4. 문서·원격 병합

README에 구현 현황·빠른 실행 표·웹 스택 안내를 정리했다. 원격 두 커밋의 예제·문서를 보존해 병합했으며, 원격 CASE-012와 겹치던 CRLF 사례는 [CASE-019](사례-019-검색-테스트-스크립트-CRLF-수정-2026-10-30.md)로 정리했다.

원격 예제의 고정 토큰은 `PUBLIC_LLM_TOKEN` 환경변수로 이동했다. 현재 코드·문서에 기존 토큰이 재포함되지 않았음을 값 출력 없이 확인했다. 실제 외부 모델 호출은 하지 않았다. 과거 Git 이력은 강제로 바꾸지 않았으므로 노출된 토큰의 재발급은 서비스 소유자의 후속 작업이다.

## 5. 서버 최신화·복구

기존 localhost:5000 서버는 이전 `.web-data/complaints.sqlite3`의 27건을 사용했고 새 기본 경로 `db/app/complaints.sqlite3`는 26건이었다. 같은 ID의 내용이 같고 새 DB가 이전 DB의 부분집합인지 확인했다. 해당 Flask만 종료하고 두 DB를 `.web-data/audit-backups-20261031/`에 SQLite backup API로 보존한 뒤 최신 27건을 기본 경로로 옮겼다. 무결성·건수 확인 후 별도 Python 환경과 루트 소스로 숨김 실행했다. 백업으로 이전 두 상태를 복구할 수 있다. 다른 서비스·RAG 원본·색인은 변경하지 않았다.
