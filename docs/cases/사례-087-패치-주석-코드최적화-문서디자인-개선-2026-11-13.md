## 2. 배경·증상과 기대 동작

- **관찰한 사실과 영향:**
  1. **장소 추적 주소 키 불일치 (`src/lab_web/static/app.js`):** `place_tool.py`는 `road_address`/`jibun_address`를 반환하지만 `AssistResponse.inferred_place`는 `dict[str, Any]`여서 Pydantic `to_camel`이 중첩 딕셔너리 키를 변환하지 않으며, 화면의 `showResult`가 `roadAddress || address`만 확인해 주소 표시가 빠졌습니다.
  2. **잠긴 LLM 단추 복원 경쟁 (`src/lab_web/static/app.js`, `styles.css`, `index.html`):** `.disabled` HTML 속성 대신 `aria-disabled="true"`와 `.is-disabled`로 전환해 클릭 시 흔들림 피드백이 울리도록 고쳤으나, `loadFields()` 완료 후 `.finally(bind)`가 호출하는 `initLlmSelector()`가 `localStorage`의 잠긴 공급자를 `!isLocked(btn)` 검사 없이 다시 활성화했습니다.
  3. **네이버 지도 중복·재귀 조회 (`src/assist/district.py`, `pipeline.py`, `place_tool.py`, `lab_web/service.py`):** `pipeline.py`가 `resolve_complaint_district`에 이어 `extract_place_info`를 연달아 부르고, `lookup_navermap_place`가 후보 보완 시 `_allow_fallback` 제한 없이 재귀 호출되어 다수의 불필요한 외부 검색이 발생할 수 있었으며, `district.py`에 `Any` 임포트 누락·`mypy` 반환 타입 경고가 있었습니다.
  4. **OpenAI usage 딕셔너리 호환 회귀 (`src/llm/complete.py`):** `usage_from_openai`가 `reasoning_tokens`가 `None`일 때도 키를 넣어 기존 `test_openai_usage_reads_cached_tokens` 기대값과 어긋났습니다.
  5. **프롬프트·문서 누락 (`PREFIX-01.txt`, `README.md`, `src/README.md`, `docs/`):** `PREFIX-01.txt`에 사전 추적된 `inferred_place` 안내가 없고, `README.md` 상단 배지 24개가 한 줄에 과밀하게 뭉쳐 있으며 `docs/README.md`와 `src/README.md`가 `exaone_api`·장소 추적·잠금 UI 최신 상태를 반영하지 못하고 있었습니다.
- **기대 동작:** 모든 신규·수정 코드가 한국어 Google docstring·JSDoc·엄격한 타입 경계를 지키고, 장소 추적이 1회 통합 조회 및 1단계 후보 상한(`5개`)으로 제한되며, UI 단추 잠금·주소 배지·`usage` 계약이 회귀 없이 동작하고 문서와 README 디자인이 최신 패치와 일치해야 합니다.

## 3. 원인 분석 및 결정 근거

- **중첩 딕셔너리 키 직렬화:** `AssistResponse` 하위 호환(`.rag-cache/lab-runs/*.json`)을 깨지 않기 위해 서버 응답을 임의로 바꾸는 대신 프론트 `showResult`가 `roadAddress || road_address || jibunAddress || jibun_address || address` 모두를 읽도록 방어했습니다.
- **중복 조회 제거:** `src/assist/district.py`에 `resolve_district_and_place()`와 공통 helper(`_find_regex_district`, `_lookup_cheongju_place`)를 두고, `pipeline.py`와 `service.py`가 한 번만 지명·장소를 해석하도록 정리했습니다.
- **재귀 제한과 캐시 보호:** `lookup_navermap_place`에 `_allow_fallback: bool = True`와 `_MAX_FALLBACK_CANDIDATES = 5`를 적용해 보완 검색을 1단계로 제한했고, 보완 실패가 캐시 miss 엔트리를 오염시키지 않도록 캐시 조건을 보강했습니다.
- **사용량 계약 호환:** `CompleteUsage`의 `reasoning_tokens`를 `NotRequired[int | None]`로 두고 값이 있을 때만 딕셔너리에 채워 `openai_api`와 `exaone_api` 계약을 모두 만족시켰습니다.
