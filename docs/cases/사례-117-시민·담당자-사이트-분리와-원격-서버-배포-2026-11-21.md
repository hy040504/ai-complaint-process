## 1. 배경과 결정

시연 웹의 시민·담당자 화면이 `index.html` 하나와 `app.js`(해시 라우팅)에 합쳐져 있고, 로그인 세션도 쿠키 하나에 역할 하나만 담았다. 실제로 쓰려면 주소·로그인·세션·링크가 사이트별로 갈라져야 한다. 사용자 결정은 다음과 같다.

| 결정 | 내용 |
| --- | --- |
| 브랜치 | `main` 기준 개발·배포. `llm` 상태를 1순위로 `origin/main`을 병합 |
| 분리 방식 | 한 서버, 주소 분리(시민 `/`, 담당자 `/staff/`). 포트·프로세스 분리는 SSE 이벤트 브로커가 없어 제외 |

## 2. 조치 내용

| 영역 | 변경 |
| --- | --- |
| 브랜치 | 로컬 `main`을 `llm`에서 다시 만들고 `git merge -s ours origin/main`으로 이력만 연결(`origin/main`의 내용은 CASE-092에서 이미 `llm`에 선택 병합됨). 병합 전 `llm`은 `backup/llm-before-main-20261121`로 보존. 푸시는 하지 않았고 `origin/main`은 fast-forward 가능 |
| 세션 분리 | `sites.py`: 요청 사이트(`X-Cheongju-Site` 헤더 → `/api/v1/staff/*` 경로 → 같은 호스트 Referer → 단일 사이트 쿠키) 판별과 `SiteSessionInterface`(`cj_citizen`·`cj_staff`). 사이트 단서가 없는 기존 클라이언트(curl·테스트·Swagger)는 기존 `session` 쿠키 그대로 |
| 로그인 경계 | 담당자 계정은 시민 사이트에서, 민원인 계정은 담당자 사이트에서 `403`. 담당자 사이트의 가입 시도는 계정 생성 전에 거부(`wrong_site`) |
| 화면 | `index.html`(시민)·`staff.html`(담당자, `noindex`) 분리, `site.js`로 허용 경로·헤더 결정. 시민 사이트는 `#/citizen*`만, 담당자 사이트는 `#/staff*`와 검사기 `#/lab`만 허용(다른 해시는 홈으로 교정). 사이트 간 이동 링크·기본 계정 안내 제거, 실계정 로그인 시 DEMO 표지 숨김 |
| 계정 관리 | 시드 3계정 외에 담당자를 추가·재설정·비활성화할 방법이 없어, `create-staff`·`reset-password`·`deactivate-user`·`activate-user`·`list-users` CLI와 저장소 메서드(`update_user_password`·`set_user_active`) 추가. 비밀번호는 환경변수·숨김 프롬프트로만 받고 출력하지 않음 |
| 서버 | Python 3.12(uv)·PostgreSQL 18·pgvector 설치, 색인 적재, 사용자 서비스 3개 등록, `COMPLAINT_DEMO_LOGIN=0`, 시드 4계정 비밀번호를 무작위로 교체해 서버 파일에만 저장 |
| 배포 | `scripts/ops/deploy-remote.ps1`(main의 `git archive` 전송, 옛 파일 정리, 서비스 재시작, 헬스 확인), `remote/*.sh`(정리·마무리·재시작·운영 설정·검증) |

## 4. 겪은 문제

- 경로 규칙이 헤더 없는 기존 클라이언트를 담당자 사이트로 오판해 기존 테스트 6건이 실패했다. 사이트 쿠키 없이 레거시 쿠키만 있으면 기존 동작을 유지하도록 판별 순서를 고쳤다.
- 헤드리스 Edge의 `--screenshot`은 SSE 연결이 열린 담당자 화면에서 끝나지 않아 CDP로 바꿨다.
- 배포 스크립트 작성 중 중첩 here-string이 일찍 닫혀 `Remove-Item`에 빈 경로가 전달될 뻔했으나 하네스가 막았고 삭제된 것은 없다. 원격 스크립트를 `remote/*.sh` 파일로 분리했다.

## 5. 남은 한계

- 원격 `origin/main` 푸시는 하지 않았다(로컬 `main`이 `origin/main`보다 앞섬).
- 서버에 LLM 키가 없어 `assistLlm=false`이다. 키 복사는 사용자 승인이 필요하다.
- 응대 검사기(`:5010`)에는 로그인이 없다. SSH 터널로만 접근한다.
- 화면 코드는 한 `app.js` 엔진을 공유하고 사이트별로 경로·링크·CSS를 제한한다. 파일 단위 분리(번들 분할)는 하지 않았다.
- 외부 도메인·TLS·역프록시, 다중 프로세스용 SSE 브로커는 미구현이다.
