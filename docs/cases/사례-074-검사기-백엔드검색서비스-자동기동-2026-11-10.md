## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향:
  - 사용자가 `검사기-시작.cmd`만 실행하여 응대 검사기 웹(:5010)을 열었을 때, 백엔드 검색 API(:8007) 또는 PostgreSQL(:5432)이 실행 중이지 않으면 질문 검사 시 `"검색 서버에 연결하지 못했습니다. 검색 API(:8007)를 확인해 주세요."` 오류가 발생함.
  - 또한 이전 세션이 비정상 종료되거나 강제 중단되었을 경우 `.rag-data/postgres/postmaster.pid` 락 파일이 디스크에 남아 있어, 이후 PostgreSQL 구동 명령이 즉시 실패하고 서버가 뜨지 못하는 현상이 발생함.
- 기대 동작:
  - `검사기-시작.cmd` 하나만 실행하더라도 백엔드 검색 서비스(PostgreSQL + RAG 검색 API)의 실행 상태를 자동으로 감지하고, 비정상 잔여 `postmaster.pid`를 안전하게 정리한 뒤 꺼져 있는 백엔드 서비스를 새 창으로 자동 기동하여 사용자가 별도의 검색 기동 절차 없이 즉시 검사기를 사용할 수 있어야 함.

## 3. 재현·확인 방법

1. 포트 8007과 5432를 끈 상태에서 `scripts/웹_시작.py` 또는 `검사기-시작.cmd`를 실행.
2. 검사기 웹 화면에서 질문 검사를 시도하면 8007 연결 실패 500 에러 반환.
3. stale `postmaster.pid`가 남아 있는 상태에서 `start_postgres()`를 호출하면 PID 충돌로 PostgreSQL 즉시 기동 실패.

## 4. 원인 분석 또는 결정 근거

- 기존 구조는 `검색-시작.cmd`(`scripts/검색_시작.py`)와 `검사기-시작.cmd`(`scripts/웹_시작.py`)가 독립적으로 분리되어 있었음.
- 검사기 웹(`src.lab_web`)은 RAG 검색 API(`:8007`)에 HTTP 프록시 질의를 수행하므로 검색 API가 반드시 기동되어 있어야 함.
- 따라서 `scripts/웹_시작.py` 진입 시 백엔드 서비스 기동 유무를 점검하고, 준비되지 않았을 경우 `scripts/검색_시작.py`의 기동 루틴을 자동으로 연계하는 것이 원클릭 운영 경험에 부합함.
- 또한 stale `postmaster.pid` 문제는 5432 포트가 닫혀 있는데도 파일이 디스크에 존재하는 경우를 검사하여 자동으로 언링크하도록 조치함.
