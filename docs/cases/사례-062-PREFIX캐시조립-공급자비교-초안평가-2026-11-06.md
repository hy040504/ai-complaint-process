## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: CASE-061 다음 단계는 PREFIX 캐시 적중 실측과 openai_api 비교였다. `.env`의 `OPENAI_API_KEY`는 비어 있다. `codex_cli`는 호출마다 새 프로세스라 `cached_tokens`를 돌려주지 않는다.
- 기대 동작 또는 요구사항: 불변 접두 조립을 코드로 확인하고, 키가 있으면 Responses `usage.cached_tokens`를 기록하며, `.env` 파일은 쓰지 않는다. 검색 예제 10건의 응대 갈래를 초안 평가로 남긴다.
- 확인 근거와 시점: 2026-11-06 사용자 요청 「남은 범위들도 진행」.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: 검색 API `:8007`, `.venv-web`, 루트 `.env`의 `COMPLAINT_LLM_PROVIDER=codex_cli`.
- 개인정보를 제거한 입력, 단계, 실제 결과:
  - `python -m pytest rag/tests/test_assist.py src/tests -q -p no:cacheprovider` → 105 passed, 2 skipped.
  - `python scripts/응대_비교.py` → 조립 적격 `true`, openai_api `skipped`, `env_file_rewritten=false`.
  - `python scripts/응대_평가.py` → 초안 10건 중 9건 통과, `automatic_transfer` 모두 거짓. `FAQ_성인여권`은 `human_handoff`/`insufficient_evidence`.
- 버그가 아닌 설계·개선 기록이라면 비교한 기존 동작과 판단 근거: 키 없이 openai_api를 호출하거나 `.env`를 바꾸지 않았다. 실패한 초안 문항의 기대값을 바꿔 통과시키지 않았다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: PREFIX-00이 네 시스템 지시의 공통 접두이고 LF만 쓰며 `{today}` 같은 동적 슬롯이 없다. 어림 토큰은 1,024를 넘는다. OpenAI 캐시 적중은 Responses `cached_tokens`가 필요하다.
- 아직 확인하지 않은 가설: 키를 넣은 뒤 두 번째 호출의 `cached_tokens`가 0보다 큰지.
- 검토한 선택지와 결정 이유: Codex 자격 증명으로 Responses API를 우회하지 않는다. 민원 CRUD LLM은 `llm` 브랜치 검사기 범위 밖이다.
