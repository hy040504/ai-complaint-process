## 2. 배경·증상과 기대 동작

사용자는 `ui/예시 html/`의 HTML 중 ‘민원과’ 디자인을 담당자 페이지에 반영하도록 요청했다. 기존 담당자 화면은 녹색 대시보드와 표 중심이었으며 예시의 남색 사이드바·업무 큐·금색 검토 카드와 구성이 달랐다.

## 3. 재현·확인 방법

기존 Flask 서버에서 `/#/staff`에 접속한다. 접수·검토 큐, 담당 업무, 전체 민원, 담당 미지정, AI 모니터, 추가 문의, 게시 답변 메뉴를 확인한다. 목록의 민원을 선택하면 실제 접수·담당 지정·초안·게시 여부와 검토 참고 정보 및 기존 답변 편집기를 확인할 수 있다.

## 4. 결정 근거

예시 원본을 브라우저에서 열어 민원과 메뉴·접수 대기·상세를 직접 캡처하고 CSS·함수를 읽었다. 남색 사이드바와 상태바, 요약 4개, 둥근 필터, 정보 밀도가 높은 민원 행, 금색 참고 카드, 처리 단계를 재구성했다.

원본의 신뢰도·법정기한·자동 배정·전화 감소율·감사 로그·부서 SLA는 현재 계약에 없으므로 복사하지 않는다. 건수는 서버에서 받은 허용된 업무 민원을 집계하고, 원문 발췌는 AI 요약으로 표시하지 않는다. 프로세스는 실제 접수·담당 지정·초안·게시 필드로 구성하며 실제 행정 처리 완료와 구별한다.

## 5. 조치와 변경 내용

| 파일·계약 | 실제 변경 | 상태 |
| --- | --- | --- |
| `ui/src/staff.js` | 전용 화면 틀, 역할별 메뉴·실제 건수, 검색·담당·초안·추가 문의·시연 실패·게시 필터, 목록 페이지, 분야별 검토 현황, 상세 단계·검토 카드 | 구현 |
| `ui/src/staff.css` | 시민 사이트와 같은 Pretendard 글꼴 계열, 남색·파랑·금색 콘솔, 카드·행·태그·답변·작업 모니터 스타일, PC·태블릿·모바일 배치 | 구현 |
| `ui/src/app.js` | 담당자 렌더러 연결, 기존 API 동작과 초안 보존 유지, 모바일 메뉴·업무 안내·키보드 닫기·초점 이동 | 구현 |
| `ui/index.html`, `ui/package.json` | 전용 CSS 연결·모듈 문법 검사 | 적용 |

화면 메뉴는 현재 구현된 업무만 연결한다. 모바일은 가로 빠른 메뉴와 열고 닫는 사이드 메뉴를 제공하며 짧은 화면에서도 메뉴를 스크롤할 수 있다. 시민 CSS와 분리하고 기존 시민 화면·서버 저장·권한 경계는 유지한다.

| 목록·필터 | 담당 업무·추가 문의·미게시 초안·담당 미지정·검색·빈 결과·초기화·페이지 조건 확인 |
| 모바일 메뉴 | 열기·메뉴 선택 시 닫기·Escape 닫기·초점 복귀 확인. 열림 효과 뒤 메뉴 링크로 초점을 옮기도록 보완 |
| 실제 서버 회귀 | 합성 민원 생성 → 담당 지정 → 초안 저장 → 별도 시민 세션 API·화면의 초안 비노출 → 게시 미리보기·게시 → 시민 답변 조회 통과 |
| 시연 작업·편집 보존 | 서버 시연 단계 이벤트 6개 저장·완료 확인, 진행 중 입력과 기존 게시본 보존 확인 |
| JS 검사 | `npm --prefix ui run check`, 기존 API 클라이언트 `npm --prefix ui test` 3개 통과 |

시민과 담당자는 별도 브라우저 시연 세션으로 확인했다. 같은 세션을 외부에서 바꾸는 검증 중 기존 역할 충돌 안내도 동작했으며, 화면 재조회로 해당 역할을 다시 선택했다. 담당 지정·게시 검증은 새로 생성한 합성 민원만 사용했다.

기존 업무 API·DB·RAG·모델을 변경하지 않아 Python·모델 평가를 반복하지 않았다. 실제 AI·법정기한·운영 인증·감사 로그·공식 접수·행정 이관 기능의 완료를 주장하지 않는다. 원격 업로드·운영 배포는 수행하지 않았다.
