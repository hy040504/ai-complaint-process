## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: Swagger와 화면에서 민원 등록이 500을 반환했다.
- 기대 동작 또는 요구사항: 예전 테이블을 지우지 않고 `version`을 채운 뒤 등록이 된다.
- 확인 근거와 시점: 2026-11-06 PostgreSQL 로그.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: `complaint_app.complaints`에 `id`, `created_at`, `payload`만 있는 상태.
- 개인정보를 제거한 입력, 단계, 실제 결과: `INSERT`가 `column "version" of relation "complaints" does not exist`로 실패했다. 같은 날 로그의 업무 오류는 이 문장 3회뿐이다.
- 버그가 아닌 설계·개선 기록이라면 비교한 기존 동작과 판단 근거: 해당 없음.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: 코드와 DDL은 `version`을 넣지만 `CREATE TABLE IF NOT EXISTS`는 이미 있는 테이블에 컬럼을 더하지 않는다.
- 아직 확인하지 않은 가설: 없음.
- 검토한 선택지와 결정 이유: 테이블을 다시 만들지 않고 컬럼을 추가한 뒤 payload의 `version`, 없으면 1을 넣는다. 이전 로그의 `database "user" does not exist`는 이번 500의 원인이 아니다. `python -m src`가 다음 실행부터 `PGDATABASE` 기본값을 채우게 했다. 검색 API 로그에는 이번 구간의 ERROR가 없었다. `complaint_rag.documents` 없음은 2026-11-05 초기 적재 전 기록이라 이번 조치에서 스키마를 다시 만들지 않았다.
