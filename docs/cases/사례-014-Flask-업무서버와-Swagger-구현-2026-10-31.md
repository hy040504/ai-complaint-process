## 2. 배경·증상과 기대 동작

사용자는 서버를 Flask로 구현하고 Swagger 페이지를 제공하며, 서버 소스를 루트 `src/`에 두고 인터페이스·정적 타입을 적용하도록 요청했다. 기존 UI는 브라우저에 모든 업무 자료를 저장했으며 서버 권한과 지속 저장이 없었다.

## 3. 재현·확인 방법

`src/README.md`의 Python 3.12 설치·실행 절차를 따른다. 선택적으로 `flask --app src:create_app seed-demo`를 실행한다. 시민 사이트에서 등록한 글을 담당자 사이트에서 검토·게시하고 시민 상세에서 답변을 확인한다. `/docs`에서 시연 세션 선택 후 API를 실행할 수 있다.

## 4. 결정 근거

기존 RAG 환경을 변경하지 않도록 업무 서버 가상환경과 SQLite를 분리했다. PostgreSQL 업무 스키마는 제안 자료로 남기고, 저장소 `Protocol`을 교체 지점으로 둔다. API·서비스·저장소를 분리하고 Pydantic 모델·`Literal`·`Annotated`·불변 설정과 엄격한 mypy 검사를 적용했다. 실제 AI가 없으므로 단계 시연을 명시하며 폴링과 SSE를 구별한다.

시민 응답에서 초안·원본·내부 이력을 제거하고, 서버가 세션 역할·작성자·기대 버전·게시 기원을 검사한다. 등록 키와 원문 해시, 수정 트랜잭션으로 중복과 충돌을 처리한다. 원문·추가 문의·게시 변경은 맥락 버전을 갱신하며 늦은 시연 후보는 현재 편집·게시본을 바꾸지 않는다.

## 6. 검증 결과와 한계

2026-10-31 수행했다.

| 검증 | 결과·근거 |
| --- | --- |
| `mypy --config-file src/mypy.ini` | 서버 코드 10개 파일 `strict` 통과. 업무 코드에 `Any`·검사 무시 주석 없음 |
| `pytest src/tests -q -p no:cacheprovider` | 18개 통과. 입력·세션·공개 범위·초안 비노출·게시·철회·원문 수정·추가 문의·AI 기원·늦은 작업·동시 저장·롤백·등록 중복·DB 재조회·문서 규격 |
| `npm --prefix ui run check`, `npm --prefix ui test` | JS 문법 검사와 API 클라이언트 회귀 3개 통과 |
| Chrome DevTools MCP 실제 폼·클릭·API 응답 | 등록 → 서버 초안 저장 → 시민 API·HTML 비노출 → 게시 → 시민 답변 조회 → 추가 문의 확인 |
| 서버 시연·UI 조회 | 단계 이벤트 6개 저장, 완료 후에도 편집 중인 답변 유지 확인. 실제 AI는 미실행 |
| Swagger 브라우저 | 문서·로컬 자산 HTTP 200, `Try it out` 실행. OpenAPI 규격 별도 검증 |
| 화면 캡처·콘솔·네트워크 | PC 1440px 대시보드와 모바일 390px 작업 모니터 등을 직접 검사. 모바일 상태 문구 줄바꿈을 보완하고 재캡처. 최종 콘솔 오류·경고 없음, Swagger 실제 `/health` 호출과 정적 자산 HTTP 200 확인 |

검증 중 경로 모델의 camelCase 별칭이 OpenAPI의 `complaint_id`와 달라 규격 검증이 실패했다. 경로 모델에는 별칭 변환을 적용하지 않도록 수정했다. 라이브러리가 기본 422 응답을 배열로 문서화하는 점도 공통 오류 모델을 명시해 수정했다. 손상 JSON은 Flask에서 먼저 검사해 400 오류 계약을 유지한다.

캡처는 MCP 대화에서 확인한다. 전체 페이지 캡처 중 한 호출이 완료되지 않아 중단했으며, 이후 화면 범위 캡처로 재확인한다. 브라우저 확인은 운영 배포나 외부 행정 조치를 포함하지 않는다.

서버는 로컬 시연 역할 선택이며 운영용 본인·담당자 인증이 아니다. SQLite JSON 업무 저장은 PostgreSQL 1차 정규화 스키마 적용과 다르다. UI 전체 스냅샷은 소규모 시연용이다. 실제 LLM·RAG 호출·작업자·SSE·공식 접수·행정 이관은 미구현이다. 기존 RAG 코드·자료·색인·모델을 변경하거나 평가하지 않았다. 원격 업로드·운영 반영도 수행하지 않았다.

## 7. 완료 조건·후속 작업·복구
