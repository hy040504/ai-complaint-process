## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향:
  - `src/__init__.py`가 최상위에서 `from src.app import create_app`을 즉시 import하고 있어, Flask 의존성이 설치되지 않은 순수 RAG 가상환경(`.venv`)에서 `rag.assist`나 `src.assist`를 불러올 때 `ModuleNotFoundError: No module named 'flask_openapi3'` 에러가 발생하며 테스트 컬렉션이 중단됨.
  - `scripts/업무보고_pdf_생성.py` 및 `src/lab_web/app.py` 라우트 핸들러 함수의 docstring에 `Args`, `Returns`, `Raises` 등 Google 형식 표준 항목이 일부 누락되어 있었음.
  - `README.md`에 새롭게 구현된 원클릭 백엔드 자동 기동([CASE-074](사례-074-검사기-백엔드검색서비스-자동기동-2026-11-10.md)) 흐름을 직관적으로 보여주는 시각적 다이어그램과 배지가 부재했음.
- 기대 동작:
  - RAG 환경(`.venv`)에서도 Flask 종속성 없이 `src.assist`를 독립 임포트할 수 있어야 함.
  - 모든 설명 주석과 함수 docstring이 한국어 및 Google 표준 양식을 준수해야 함.
  - README에 원클릭 백엔드 자동 기동 다이어그램과 배지가 추가되어 직관적인 디자인을 갖추어야 함.

## 3. 재현·확인 방법

1. `.venv\Scripts\python.exe -m pytest rag/tests` 실행 시 `src/__init__.py`의 Flask 의존성 임포트로 인한 `ModuleNotFoundError` 확인.
2. `src/lab_web/app.py` 및 `scripts/업무보고_pdf_생성.py` 내 docstring 누락 확인.

## 4. 원인 분석 또는 결정 근거

- Python 패키지 최상위 `__init__.py`에 하위 모듈의 심볼을 직접 import하면, 해당 패키지의 어떤 하위 모듈을 임포트하더라도 최상위 `__init__.py`가 먼저 실행됨.
- Python 3.7+에서 지원하는 모듈 레벨 `__getattr__`을 활용하면, `from src import create_app` 호출 시점에만 `src.app`을 지연 로딩(lazy import)할 수 있어 RAG 환경의 가벼운 독립성을 유지할 수 있음.
