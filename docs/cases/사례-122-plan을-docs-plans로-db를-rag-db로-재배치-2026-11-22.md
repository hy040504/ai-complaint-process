## 1. 요청과 결정

사용자 요청: ① 루트 `plan/`을 `docs/`로 옮기되 내용에 어울리는 이름이 있으면 바꾸기, ② 따로 있는 `db/`와 `rag/`를 한 폴더로 합치기, ③ `bin/`의 역할 설명.

| 대상 | 결정 | 근거 |
| --- | --- | --- |
| `plan/` | `docs/plans/`로 이동 | 내용이 모두 구현 계획·상세설계·제안·로드맵과 초기 기획 자료(archive)라 이름 `plan`이 맞다. 다만 `docs/` 아래 다른 폴더(`harness`·`cases`·`reports`)와 결을 맞춰 복수형 `plans`로 했다 |
| `db/` + `rag/` | `db/`를 `rag/db/`로 합침 | `rag/`가 이미 스키마(`origin/schema/`)·원본·덤프를 갖고 있다. `rag/`는 `python -m rag`로 쓰는 **파이썬 패키지**이고 `rag/origin` 참조만 36개 파일·79곳이라 이름·위치를 바꾸지 않았다. `db/` 참조는 8곳 안팎뿐이라 합치는 쪽이 안전했다 |
| `bin/` | 이동 안 함, 역할만 설명 | 사용자가 바로 실행하는 `.cmd`/`.sh` 진입점 모음이다([`bin/README.md`](../../bin/README.md)) |

`plan/db 설계 1차`는 추적 파일이 0개인 작업 폴더 전용 빈 폴더(같은 내용은 `plans/archive/db 설계 1차/`에 있음)라 삭제했다.

## 2. 조치

1. `git mv plan docs/plans`, `git mv db rag/db`(이력 보존, 34개 항목이 이름 변경으로 기록).
2. **링크 일괄 재계산:** 각 파일의 링크를 "옛 위치 기준으로 해석 → 새 위치 기준 상대 경로로 재계산"해 47개 파일 183개 링크를 고쳤다. 이동한 파일의 바깥 링크와 이동한 대상으로 오는 링크를 모두 처리한다(`ui/mockups`·`ui/예시 html`은 원본 보존을 위해 제외).
3. **본문 속 경로 표기:** 현재 위치를 가리키는 곳(문서 색인, 업무 DB 실행 설계 표 9곳, 구조 개선안, 기술 개요 폴더 트리, `rag/db` README, `load_samples.py` 도움말 3곳, `.gitignore`)만 고쳤다. 사례·CHANGELOG·과거 보고서의 옛 경로 표기는 **그 시점의 기록이라 그대로** 두었다.
4. `rag/README.md`에 폴더 구성 표를 추가해 `origin/`(원본)·`db/`(업무 DB 참고본)·`reports/`·`tests/`의 역할을 구분했다. `rag/db/README`에는 검색 색인과 별개라는 점을 적었다.
5. [구조 개선안](../plans/프로젝트_구조_개선안.md)에 8·9단계와 새 폴더 트리를 반영했다.

## 4. 한계

- 서버 배포 스크립트는 `git archive`와 배포 목록(manifest)을 쓰므로 다음 배포 때 서버의 옛 `plan/`·`db/` 파일이 목록 기준으로 정리된다. 아직 배포하지 않았다.
- `docs/cases`·CHANGELOG의 본문 안 옛 경로는 현재와 다르다(의도).
- `rag/db`에는 업무 DB(`complaint_app`) 자료가 들어 있어 "검색 폴더에 업무 DB 참고본이 있다"는 어색함이 남는다. 폴더 README에 구분을 적었고, 필요하면 후속으로 `src/complaints/schema/` 쪽으로 옮길 수 있다.
