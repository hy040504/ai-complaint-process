## 1. 배경

시민·담당자 화면이 어색하고 정적이라는 지적에 따라 CSS를 측정하고 디자인 시안(Design 캔버스)을 만들어 방향을 정한 뒤 코드에 적용했다. 시안의 순서는 ① 토큰 ② 블록 공통화 ③ 모션 ④ 다크 변수화 ⑤ 검증이다.

## 2. 측정으로 확인한 문제

| 항목 | 적용 전 | 비고 |
| --- | --- | --- |
| 브랜드색 | `:root` 토큰은 청록(`#087F72`), 실제 화면은 파랑(`#2F6FED`, 시민 CSS 42회). 다크는 `--teal`을 파랑으로 덮어써 **라이트와 다크의 브랜드색이 달랐음** | `theme-color` 메타도 청록 |
| 상태 배지 | `styles`·`citizen`·`staff`와 다크용 `themes`에 중복 정의. 종료 3.5:1(시민)·2.5:1(담당자), 접수 대기 4.2:1, 답변 완료 4.4:1로 **4.5:1 미달**. 접수 대기가 회색 | |
| 출처 태그 | 담당자 답변 태그가 검정(`#111`), 기타 태그는 옛 올리브 계열 | |
| 모션 | `@keyframes` 담당자 0개·시민 6개(대부분 챗봇) | |

## 4. 겪은 문제와 수정

- **다크 테마 회귀(제 실수):** 정리 스크립트가 선택자 목록을 쉼표로 단순 분리해 `:is([data-site="citizen"], [data-site="lab"])` 안의 쉼표에서 잘렸다. 괄호가 열린 채 남은 선택자 때문에 브라우저가 뒤의 다크 규칙까지 삼켜 **다크 게시판의 표 머리줄이 흰색, 제목이 어두운색**이 되었다. 스크린샷 전후 비교로 발견해 CSS 5개를 되돌리고 괄호 깊이를 고려한 분리로 다시 적용했다. 재발 방지로 `css-integrity.test.mjs`(괄호 균형·선택자 괄호 검사)를 추가했다.
- 새 행 플래시가 처음에는 재렌더로 사라져 동작하지 않았다. 시작 시각을 기억하도록 고치고 브라우저에서 약 2.7초 지속(중간 재렌더 포함)을 확인했다.
- 측정 중 만든 시험 민원 3건이 로컬 DB에 남아 정리했다(서버에는 영향 없음).
