## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 시연 웹은 민원 CRUD와 단계 시연만 있고, 검색 API의 `requires_gate` 이후 판정이 없었다.
- 기대 동작 또는 요구사항: 기존 시연 웹은 그대로 두고, RAG·LLM을 보여 줄 얇은 응대 계층과 검사기를 추가한다.
- 확인 근거와 시점: 2026-11-01 사용자 결정. 주 대상은 내부 기술 검토.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: 검색 API 준비, Flask `.venv-web`.
- 개인정보를 제거한 입력, 단계, 실제 결과: `python3 -m rag assist --example faq --no-rerank`에서 FAQ 5건을 검색하고 LLM 미설정 시 `human_handoff`/`llm_unavailable`을 반환했다.
- 비교한 기존 동작: 검색 `/search` 계약(`retrieval_only`, `requires_gate`)은 유지한다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: 민원 게시판을 응대 검사기로 개조하면 CRUD가 RAG·LLM을 가린다.
- 검토한 선택지와 결정 이유: 같은 `run_assist`를 CLI와 Flask가 재사용한다. 검색 프로세스는 기존 API를 호출하고, LLM은 환경변수 토큰이 있을 때만 호출한다.

- 완료로 판단할 조건: 검색 계약을 유지한 채 세 갈래 결과와 정책 거부를 코드·CLI·API·검사기에서 확인할 수 있다. 충족.
