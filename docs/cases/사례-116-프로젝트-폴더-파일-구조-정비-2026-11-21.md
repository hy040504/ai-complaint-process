## 1. 증상 및 결정 근거

폴더·파일 구성이 복잡해 구조를 파악하기 어렵다는 요청이 있었고, 다음을 확인했다.

- `src/rag`(검색 클라이언트)와 루트 `rag/`(검색 엔진)의 이름이 같았다.
- 루트에 실행 파일 12개가 흩어져 있었고, `scripts/`는 66개 파일이 평면이며 한글 본체와 영문 `exec` 래퍼가 쌍으로 있었다.
- `db/`와 `rag/origin/`이 같은 원본 JSON(8.7 MB, 해시 동일)을 각각 보관했다.
- `docs/`·`plan/`에서 현행 기준 문서와 일자성 산출물이 섞여 있었다.
- 일부 모듈이 컸다(`repository.py` 2,265줄, `service.py` 약 2,100줄, `place_tool.py` 1,668줄).

사용자 결정: 스크립트 이름만 영문으로 통일하고(문서·사례 이름은 한글 유지), 대형 모듈 분리도 진행하며, `db/` 샘플은 필요하므로 유지하되 배치를 정돈한다.

## 4. 남은 한계 (미구현)

- `swagger_page.py`(993줄)·`assist/pipeline.py`(960줄)는 분리하지 않았다. 전자는 HTML 템플릿, 후자는 핵심 판정 흐름이라 별도 검토가 필요하다.
- `service.py`의 AI 워커(`_run_ai_worker` 등)와 챗봇, `postgres.py`(1,250줄)는 한 클래스에 묶여 있어 믹스인 분리는 하지 않았다(mypy strict와 `self` 의존성 때문에 위험이 크다).
- 가상환경 `.venv`(모델 실행)와 `.venv-web`(웹) 통합은 하지 않았다.
- Linux 셸 스크립트(`bin/*.sh`, `scripts/ops/*.sh`)는 이 Windows 호스트에 `bash`가 없어 **문법·실행 검증을 하지 못했다.** 경로 문자열은 `grep`으로만 확인했다.
- 테스트 파일 이름(`test_검색_시작.py` 등)은 한글 그대로 둔다.
- 과거 사례 문서의 경로는 현재 위치로 치환했으므로, 당시 경로와 다를 수 있다(예: CASE-097의 `docs/test/`).
