## 2. 배경과 기대 동작

명령 옵션을 매번 조합하지 않고 상태·예제·직접 입력·검색 설정을 메뉴에서 확인할 수 있어야 한다. 사용자는 Bash 스크립트와 꾸민 TUI, 변경 문서 정리 및 GitHub 업로드를 요청했다.

## 3. 확인 방법

`bash rag/검색_시험.sh`로 실행한다. FAQ·사례·양쪽 검색을 선택하고, 재정렬·관할·결과 수를 설정한다. 명령형 옵션 `--status`, `--search`, `--json`도 지원한다. 실제 요청은 기존 CLI와 API를 사용한다.

## 4. 결정 근거

Bash는 메뉴·설정·프로세스 실행을 담당하고 Python 표준 라이브러리는 JSON을 해석·표시한다. 별도 TUI 의존성과 모델 프로세스를 추가하지 않는다. 초기 메뉴는 재정렬 끔·3건으로 두며 일반 CLI의 기본 설정은 바꾸지 않는다. FAQ의 조건·주의사항을 생략하지 않고 원본 근거 전체를 표시한다. 문서의 제어 문자는 화면 표시에서 치환한다.

## 6. 검증 결과와 한계

2026-10-28 실행 결과:

- 일반 DB 계정으로 코드·격리 PostgreSQL·화면 테스트 **27개 통과** (`RUN_PG_TESTS=1`, 13.14초).
- 실제 FAQ 검색에서 `1314210` 대형폐기물 배출 방법 1위 확인.
- 실제 사례 재정렬 검색에서 건설교통국 대중교통과가 첫 부서 후보이며 `requires_gate` 유지.
- 실제 터미널에서 메뉴·상태 조회·종료 확인. 비대화형 입력에서 설정 변경·잘못된 값·JSON 보기·EOF 확인.
- API 연결 실패는 종료 코드 1, 옵션 누락은 종료 코드 2. 비터미널 출력에 ANSI 색상 없음.
- 다른 디렉터리에서 실행 성공. 선택 저장 JSON이 권한 600이며 기존 파일을 덮어쓰지 않는지 확인. 시험용 저장 파일은 확인 후 삭제.
- Python 문법·Bash 문법·문서 링크·변경 공백 검사. PDF는 네이티브 전환 수정본 24페이지 유지.

전체 모델 평가나 자동 응답 정확도 평가를 수행한 것은 아니다. 메뉴는 검색 근거 확인 도구이며 LLM 대화·실제 민원 접수·부서 이관은 미구현이다. 모델·검색 엔진·원본 JSON을 변경하지 않았다. 로컬 구현·검증과 원격 업로드는 구별하며, 원격 반영은 이 문서를 포함하는 커밋의 push와 main ref 대조로 확인한다.

## 7. 완료 조건과 복구

요청한 수동 검색 메뉴와 명령형 점검, 현재 운영 문서가 준비됐다. 마지막 응답은 종료 시 임시 파일을 삭제하고 사용자가 저장을 선택한 응답만 Git 제외 경로 `.rag-cache/reports/tui-*.json`에 남긴다. 서비스·원본·색인을 변경하는 메뉴는 없다. 메뉴를 되돌려도 기존 검색 CLI/API는 독립적으로 사용할 수 있다.
