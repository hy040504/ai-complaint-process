## 1. 요청

담당자 통계 대시보드(`#/staff/stats`)가 상태·AI 판정·구·분야·부서별 막대와 KPI만 보여 주었다. 디자인 목업(`ui/예시 html/민원 사이트 목업본.html`)의 관리자 화면 **통계 분석(A-10)** 과 **민원 분류(A-14)** 를 참고해, 현재 저장된 데이터로 만들 수 있는 차트와 기능을 확장한다.

## 2. 결정: 만든 것과 만들지 않은 것

목업은 가짜 샘플 데이터 기반이라 지표를 그대로 옮기지 않고, **실제 민원 데이터에서 계산할 수 있는 것만** 구현했다.

| 목업 항목 | 구현 | 비고 |
| --- | --- | --- |
| 일·주·월 접수·처리 이중 막대 | 구현 | 일 14일·주 8주·월 12개월 |
| 분류 종합 시계열·전월 대비 | 구현 | 분야별 최근 6개월 꺾은선, 증감률 |
| 지역×유형 교차표 | 구현 | 구×분야 히트맵, 지역 이름은 목록으로 이동 |
| 시간대·요일 히트맵 | 구현 | 7행×24열, 시간대별 막대 |
| 처리기간 | 구현 | 구간 분포와 분야별 평균 처리일 |
| 채널·이용자 유형, 만족도, 정책 연계, 특이민원, 계절·반복 분류 | 제외 | 해당 데이터를 저장하지 않음 |

- 시간대 정보가 없는 시각은 UTC로 보고 KST로 바꾼다.

## 5-1. 목업 구성으로 재구성 (후속, 2026-11-23 KST)

첫 구현이 탭 5개를 얹은 수준이라 아쉽다는 의견에 따라, 목업의 관리자 화면 구성과 표현을 더 가져와 화면을 다시 짰다.

| 구역 | 내용 |

| 업무 현황 | 기존 지표 카드(그대로) |
| 통계 분석 | 일자·주간·월별 전환 · 지표 4개(접수·처리 완료·지난 구간 접수·AI 안내 완료율) · 값 라벨이 붙은 접수·처리 막대 · 분야 순위표(비중·건수·평균 처리일·전기 대비) · 시간대별 분포와 야간·주말 비중 · 요일별 막대 · 기간 비교 표(행을 눌러 단위 전환) |

## 6. 한계

- 브라우저 확인은 로컬 시험 서버(메모리 저장소, 시험 민원 160건)에서만 했고, 실제 서버 데이터로는 하지 않았다(5. 브라우저 확인 참고).
- 증감률은 처음에 진행 중인 이번 구간을 끝난 직전 구간과 비교해 주초·월초에 급락처럼 보였다. **후속 수정:** 진행 중인 이번 구간을 비교에서 빼고 끝난 직전 두 구간(지난 일·주·월과 그 전)을 비교하며, 이번 구간 건수는 "진행 중"으로 따로 표시한다. 분야별 증감률(서버 `change_pct`)도 같은 기준이다. 분야 꺾은선의 마지막 점은 여전히 진행 중인 이번 달이다.
- 집계는 요청 시마다 전체 소관 민원을 한 번 훑어 계산한다. 시연 규모에서는 충분하지만 민원이 많아지면 SQL 집계나 캐시가 필요하다.
- 통계 CSV 내보내기는 기존 민원 목록 CSV 그대로이며 분석 탭 데이터는 포함하지 않는다.
