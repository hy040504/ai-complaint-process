## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향:
  - 시민 민원 본문에는 "창신초 앞 도로", "육거리시장 입구", "복대동 지웰시티 부근"과 같이 행정구역(구/동)이 직접 적히지 않고 장소명·상호명만 언급되는 경우가 많음.
  - 네이버 개발자센터는 신규 오픈API 지역 검색 신청이 제한되어 있거나 유료 클라우드 전환이 요구되어 일반 API 키 발급이 까다로움.
  - 패킷 덤프 분석(`Dump-1110-15-20-45`) 결과 네이버 지도 웹 클라이언트의 공개 인스턴트 검색 엔드포인트(`https://map.naver.com/p/api/search/instant-search`)가 로그인 세션/API 키 없이도 `User-Agent`와 `Referer` 헤더만으로 장소의 도로명·지번 주소와 좌표를 완벽히 반환함을 확인.
- 기대 동작 또는 요구사항:
  - 도구명 `lookup_navermap_place`로 구현.
  - 네이버 비로그인 상태에서도 단독 동작해야 함.
  - 청주시청 기준 중심 좌표(`36.6424341,127.4890319`)를 기본값으로 주어 청주 지역 장소를 최우선으로 매칭.
  - 반환 결과에서 청주시 4개 자치구(상당구, 서원구, 흥덕구, 청원구) 및 법정/행정동을 즉시 파싱하여 제공.
  - MCP stdio 서버에 도구 등록 및 Codex 자식 프로세스에서 호출 가능해야 함.

## 3. 재현·확인 방법

- 장소 검색 실행 테스트:
  ```powershell
  .venv\Scripts\python.exe -m src.llm.place_tool "창신초등학교"
  ```
- MCP stdio를 통한 `tools/list` 및 `tools/call`:
  - `tools/list` 응답에 `search_complaint_rag`와 함께 `lookup_navermap_place`가 포함되는지 확인.
  - `tools/call`에 `name: "lookup_navermap_place"`, `arguments: {"query": "창신초등학교"}`를 전송하여 도로명 주소와 `gu: "서원구"`, `dong: "사창동"`이 정상 반환되는지 확인.

## 4. 원인 분석 또는 결정 근거

- 네이버 지도 인스턴트 검색 API의 특징:
  - `GET https://map.naver.com/p/api/search/instant-search?query=...&coords=...`
  - 표준 라이브러리 `urllib.request`로 브라우저 헤더를 전송하여 외부 무거운 라이브러리(Docker, Selenium 등) 없이 가볍고 빠르게 호출 가능.
  - 지번 주소에 자치구와 법정동(예: `충청북도 청주시 서원구 사창동 351`)이 명시되어 별도의 Reverse Geocoding 없이도 관할 구청 배정에 필요한 정보를 100% 특정 가능.
- 중복 호출 방지 및 안정성:
  - 동일한 장소에 대해 불필요한 네트워크 호출을 막기 위해 프로세스 수명 내 인메모리 LRU 캐시(최대 256건) 적용.
  - 네트워크 단절이나 원격 API 장애 시에도 서버가 중단되지 않도록 안전한 `error` 객체 반환 구조 채택.
