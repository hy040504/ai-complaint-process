## 1. 배경 및 목적

`CASE-110`으로 담당자 실시간 SSE 푸시(`BE07`·`UI08`)와 시민 AI 챗봇 실연결까지 완료된 상태에서, 사용자 지시(**"1, 3 만 패치 진행하고 검사까지"** — 다중 워커 이벤트 브로커와 `EXAONE Tabular` 제외)에 따라 남은 핵심 기반 두 가지를 일괄 구현하고 실서버·PostgreSQL·브라우저 수준까지 검증했습니다.

1. **운영 본인·담당자 인증 (`#1`):** 기존 시연용 원클릭 세션(`POST /api/v1/session` → `citizen-demo` / `staff-demo`)만으로는 다중 시민 비공개 민원 격리, 담당자 소속 부서별 권한 통제, 실명 처리자 이력 보존이 불가능했습니다.
2. **PostgreSQL 7테이블 정규화 (`#3`):** 기존 `complaint_app`은 `complaints.payload` JSONB 1개 테이블(+보조 3테이블)에 추가 문의·답변 버전·AI 작업·AI 분석 결과·진행 이벤트를 몰아 넣고 있어 관계형 SQL 집계, 외래 키 무결성, DB 차원의 `automatic_transfer=false` 강제가 불가능했습니다.

## 2. 주요 구현 내용

### 2.1 운영 본인·담당자 인증 (`src/complaints/auth.py` · `models.py` · `http.py` · `service.py` · `api.py`, `ui/src/auth.js` · `store.js` · `citizen.js` · `staff.js` · `app.js`)

- **안전한 비밀번호 해싱 및 브루트포스 방어 (`auth.py`):**
  - `werkzeug.security`의 `scrypt` 해시(`hash_password`/`verify_password`)와 비밀번호 강도 정책(`validate_password_strength`: 8자 이상·영문+숫자 조합)을 적용했습니다.
  - `LoginRateLimiter`로 동일 `login_id` 기준 연속 5회 실패 시 60초 잠금(`429 auth_locked`)을 걸고, 성공 시 카운터를 초기화합니다.
  - `set_session_actor()`가 로그인·가입 시 기존 세션을 `session.clear()`로 회전하고, `actor()`는 세션의 `user_id`를 `users` 저장소와 재대조해 비활성·삭제 계정을 차단합니다.
- **시민 2단계 본인확인 가입 (로컬 OTP 챌린지):**
  - `POST /api/v1/auth/citizen/verify-request`: 성명·휴대전화 형식 검증 후 암호학적으로 안전한 6자리 OTP(`secrets.randbelow`)를 5분 TTL로 발급합니다. 전화번호 원문은 저장하지 않고 SHA-256 해시와 마스킹 문자열(`010-****-1234`)만 사용하며, `COMPLAINT_SMS_MODE != "external"`인 로컬 검증 환경에서만 `demoCode`를 노출합니다.
  - `POST /api/v1/auth/citizen/register`: `hmac.compare_digest`로 6자리 코드를 검증(5회 오입력 시 잠금·1회용 소비로 재사용 차단)한 뒤 `users` 테이블에 `verified=True`, `auth_mode="verified_account"` 시민 계정을 생성·로그인합니다.
  - `COMPLAINT_DEMO_LOGIN=0` 설정 시 기존 `POST /api/v1/session` 시연 전환은 `403`으로 거부하고 실인증 경로만 허용합니다.
- **담당자 실계정 및 부서 범위 RBAC (`service.py`):**
  - 초기 부트스트랩 시 시연 2계정(`citizen-demo`, `staff-demo`)과 실계정 담당자 3계정(`staff_admin` 청주시 민원과 총괄, `staff_seowon` 서원구 건설과, `staff_heungdeok` 흥덕구 환경위생과; 초기 비밀번호 `COMPLAINT_STAFF_INIT_PASSWORD`, 로컬 기본값 `cheongju-staff-2026!`)을 `users` 테이블에 멱등 시드합니다.
  - `_require_department_scope(actor, row)`를 도입해 소속 부서가 지정된 담당자(`staff_seowon` 등)가 타 부서에 배정된 민원의 초안 저장·게시·철회·배정 변경·작업 취소 등을 시도하거나 임의로 타 부서에 배정할 경우 `403 department_scope_forbidden`으로 차단합니다(민원과 총괄 `department=None`은 전 부서 권한 보유).
  - 담당자 배정·초안·게시 이력에 실제 로그인 계정의 `assignee_id`·`assignee_name`을 기록합니다.
- **프론트엔드 인증 모달 및 다중 사용자 격리 (`ui/src/auth.js` · `store.js` · `app.js`):**
  - 3탭 모달(`시민 로그인`, `시민 본인확인·가입` 2단계 OTP, `담당자 로그인`)과 인증 상태 배지(`본인확인 완료` · `담당자 인증` · `시연 계정`), 라이트·다크 WCAG 스타일(`.auth-*`)을 구현했습니다.
  - `store.js`의 `ensureRoleSession(role)`이 이미 로그인된 실계정 세션을 페이지 새로고침·화면 이동 시 시연 세션으로 덮어쓰지 않고 보존하며, `visible()` 및 `app.js` 소유권 판별의 하드코딩 `"citizen-demo"`를 현재 세션 `getActor()?.id` 기준으로 교체했습니다.

### 2.2 PostgreSQL 7테이블 정규화 (`src/complaints/schema/complaint_app.sql` · `src/complaints/repository.py` · `api.py`)

- **7개 핵심 정규화 테이블 + 기존 호환성 100% 유지:**
  1. `users`: `id`, `login_id`(UNIQUE), `password_hash`, `role`(`citizen`/`staff` CHECK), `display_name`, `department`, `phone_hash`, `masked_phone`, `verified`, `is_demo`, `is_active`, `created_at`, `updated_at`
  2. `complaints`: 기존 `payload jsonb`·5개 `STORED` 생성 칼럼(`status`·`owner`·`visibility`·`district`·`is_synthetic`)·`CHECK` 제약·`DEMO-PUB-` 마이그레이션을 100% 보존하면서, 정규화 칼럼(`owner_user_id` FK→`users`, `assignee_user_id` FK→`users`, `title`, `body`, `category`, `department`, `context_version`, `updated_at`)을 추가
  3. `messages`: 시민 추가 문의·답변 메시지(`complaint_id` `ON DELETE CASCADE`, `author_user_id` FK→`users`)
  4. `message_versions`: 초안 저장·게시·철회·수정 전 답변 버전 이력(`message_id`·`complaint_id` `ON DELETE CASCADE`, `actor_user_id` FK→`users`, `origin` CHECK)
  5. `ai_jobs`: AI 분석 작업 실행 이력(`complaint_id` `ON DELETE CASCADE`, `status`·`stage`·`provider`·`context_version`·`attempt`)
  6. `ai_results`: 판정 결과·권고 사유·추천 부서·근거(`job_id`·`complaint_id` `ON DELETE CASCADE`, **DB 레벨 `CHECK (automatic_transfer = false)`**, `complaint_rag.department_directory` 존재 시 조건부 교차 스키마 FK `fk_ai_results_department`)
  7. `job_events`: 작업 단계별 타임라인 이벤트(`job_id`·`complaint_id` `ON DELETE CASCADE`, `seq`·`stage`·`visibility`)
  - 기존 운영 보조 3테이블(`idempotency`, `answer_templates`, `app_meta`)도 그대로 유지해 총 10테이블 구성을 이룹니다.
- **원자적 동기화 및 무손실 자동 백필 (`PostgresRepository`):**
  - 민원 생성(`create`) 및 변경(`change`) 시 동일 PostgreSQL 트랜잭션 안에서 `_sync_normalized_children()`을 실행해 `complaints`와 하위 5개 테이블을 원자적으로 동기화합니다.
  - 서버 기동 `ensure_schema()` 시 기존 `complaints` 행을 자동 스캔해 정규화 자식 테이블로 멱등 백필하며, 레거시 마이그레이션 테스트의 최소 스텁 payload는 `ValidationError` 예외 처리로 안전하게 건너뜁니다.
  - 담당자 전용 `GET /api/v1/staff/db-summary`로 7테이블 실시간 행 수·역할별 사용자 수·AI 판정 결과 분포를 직접 SQL 집계해 반환합니다.

## 4. 경계 및 남은 범위

- **외부 본인확인·행정 SSO와의 구별:** 이번 구현은 로컬 서버 완결형 2단계 OTP 챌린지·`scrypt` 비밀번호·부서 RBAC이며, 실제 이동통신사 PASS/공동인증서·청주시 행정 SSO·SMS 게이트웨이 연동은 외부 기관 계약·인가가 필요한 별도 배포 단계입니다.
- **의도적 제외 범위 (사용자 지시):** 다중 워커/멀티 인스턴스 이벤트 브로커(Redis / PostgreSQL `LISTEN/NOTIFY`)와 `EXAONE Tabular`는 이번 범위에서 명시적으로 제외했습니다.
- **기타 후속 범위:** 청주시 공식 접수·외부 부서 행정 이관 연동, `openai_api` `cached_tokens` 실측, 첨부 파일 업로드는 후속 과제로 유지합니다.
