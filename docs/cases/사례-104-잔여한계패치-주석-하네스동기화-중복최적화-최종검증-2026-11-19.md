## 2. 배경·증상과 기대 동작

- **관찰한 사실과 영향:**
  - `src/assist/district.py`에서 `resolve_district_and_place()`가 `has_external_residence_context(text)`를 최대 2회, `_strip_external_residence_clause(text)`를 1회 별도 호출해 동일한 `_EXTERNAL_CODE_REJECT_RE`·`_RESIDENCE_AFTER_RE` 탐색을 반복했고, `extract_external_jurisdiction(..., cheongju_area_found=True)`는 `cheongju_area_found is True`를 검사하기 전에 `_EXTERNAL_CODE_REJECT_RE`·`_DISTRICT_PATTERN`·`_CHEONGJU_SUBJECT_RE`를 먼저 실행했습니다.
  - `src/assist/pipeline.py` `iter_assist()`는 `resolve_district_and_place()` 안에서 이미 `normalize_district(district)`를 적용했음에도 이후 조기 타지역 분기에서 `normalize_district(district)`를 다시 계산했습니다.
  - `CASE-103`으로 추가된 테스트 내부 헬퍼(`fake_lookup`, `fail_search`, `track_llm`, `san_only_llm`, `oos_llm`, `fake_run`, `mock_complete_result`, `should_not_call`)에 한국어 docstring이 비어 있었고, `docs/harness/`(`LLM_완충지대_하네스.md`·`AI_정보전달과_응답_하네스.md`·`시스템_프롬프트와_프리픽스_캐싱_지침.md`·`architecture.md`·`prompts/README.md`·`docs/harness/README.md`)에는 `"CRUD LLM 미연결"`이나 `PREFIX-03` 단일 직렬 설명 등 이전 문구가 남아 있었습니다.
- **기대 동작:** 모든 중복 정규식·정규화 호출을 단일 헬퍼·단일 패스로 축소하고, 신규 코드/테스트 docstring을 한국어 Google 규칙에 맞추며, 하네스·README·사례 색인을 실제 구현과 100% 일치시킨 뒤 재기동한 실서버까지 최종 검증합니다.

## 3. 재현·확인 방법

- `ast` 순회 스크립트로 수정 대상 Python 11개 파일의 모듈·함수·클래스 docstring 존재 여부를 점검했습니다.
- `docs/harness/` 6개 문서와 `README.md`의 상대 링크 유효성을 스크립트로 검사하고, `:5000`·`:5010` 데몬을 최종 코드로 재기동한 뒤 실요청과 전체 테스트 스위트를 실행했습니다.

## 4. 원인 분석 또는 결정 근거

- **중복 정규식 단일화:** `has_external_residence_context()`의 `+28` 슬라이스 길이 제한은 `_RESIDENCE_AFTER_RE`의 `^[^\n.!?]{0,24}`와 일부 중첩되면서 긴 결합 서술(`출퇴근하는데` 등)이 잘릴 소지가 있었고, `_strip_external_residence_clause()`와 거의 같은 루프를 중복 유지하고 있었습니다. 공통 내부 함수 `_split_external_residence_clause()`가 `tail = text[match.end() :]`에 대해 `_RESIDENCE_AFTER_RE.search(tail)`을 1회만 수행해 `(matched, remainder)`를 돌려주도록 통합하면 의미 일관성과 실행 속도를 함께 얻을 수 있습니다.
- **하네스 동기화 범위:** `CASE-093`(CRUD 비동기 AI)과 `CASE-103`(`early_external_reject`, `out_of_scope` `PREFIX-03` 생략, `PREFIX-03∥04` 병렬, EXAONE `high`/`low`, `codex_cli` `_disable_mcp`, `lookup_navermap_place` MCP)의 동작 차이가 하네스 6종과 `README.md`에 모두 반영되어야 다음 작업자가 잘못된 전제(`max` 일괄 추론, CRUD 미연결 등)로 수정하는 문제를 막을 수 있습니다.
