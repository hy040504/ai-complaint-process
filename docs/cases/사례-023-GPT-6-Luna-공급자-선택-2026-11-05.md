## 2. 배경과 결정 근거

- 기존 응대 검사기는 기존 OpenAI 호환 공급자 환경변수만 읽어 GPT-6 Luna를 명시적으로 선택하거나 Codex CLI를 호출할 수 없었습니다.
- OpenAI 공식 문서에서 `gpt-6-luna`는 Responses API와 `reasoning.effort="medium"`을 지원함을 확인했습니다.
- 민원 원문과 검색 근거는 외부 모델에 전달되므로, 공급자 선택과 인증 정보를 서버 환경변수에 한정하고 API 키를 저장소·응답·로그에 넣지 않습니다.

## 4. 검증과 한계

- OpenAI API 요청 본문, 인증 헤더, 기본 모델·추론 설정과 Codex CLI 인수를 검증하는 단위 테스트를 추가했습니다.
- 2026-11-05 Windows / Python 3.12.10 `.venv-web`에서 `pytest rag/tests/test_assist.py src/tests -q -p no:cacheprovider` 35개가 통과했습니다.
- 실제 API 키·Codex 로그인 상태·모델 접근 권한과 실측 품질·비용 평가는 이 변경에서 실행하지 않았습니다.
- Codex CLI 모드는 코드 에이전트이므로 응대 처리 전용의 안정된 일반 생성 API가 아닙니다. 운영 환경에서는 API 방식의 사용량·오류·개인정보 보존 정책을 별도로 확정해야 합니다.
- 2026-11-05 Windows에서 검색 근거가 붙은 프롬프트가 `The command line is too long`으로 실패했다. 프롬프트는 표준 입력으로 보내고, npm `codex.cmd`는 `node`로 실행한다. [CASE-038](사례-038-Windows-Codex-명령줄-길이-2026-11-05.md)
