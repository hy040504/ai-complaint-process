## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향:
  1. `CASE-090`에서 `.llm-engine-badge[data-provider="exaone_api"|"codex_cli"|"openai_api"]` 스타일을 추가했으나, 기존 기본/레거시 공급자(`data-provider="legacy"`)용 강조 스타일이 빠져 있었습니다.
  2. `src/lab_web/static/app.js`의 `updateLlmAvailability()`는 `.env 기본` 버튼(`data-provider=""`)에 대해 `/api/v1/lab/fields`가 내려주는 `resolvedProvider`를 JSDoc `@param`과 버튼 부제(`<small>`)에 반영하지 않아, 기본 버튼만 누른 상태에서는 어느 엔진으로 해석됐는지 버튼 단계에서 바로 보기 어려웠습니다.
  3. `showResult()` 내부에서 `#codex-data-*`와 `#codex-prompt-*`의 제목·엔진 칩·안내 문구 갱신 코드가 비슷한 패턴으로 반복되고 있었습니다.
  4. 루트 `README.md`와 `src/README.md`, `docs/README.md` 일부에 `🤖 판정 엔진`, `Codex stdin` 위주 문구와 CASE-089·090 반영 누락이 남아 있었습니다.
