## 1. 배경 및 목표

민원 작성 화면(`#/citizen/write`)에 `"첨부파일은 후속 지원 예정입니다."`로 남아 있던 **현장 사진(포트홀·가로등 고장·불법 주정차·쓰레기 적치 등) 및 증빙 PDF 첨부 기능**을 안전하게 구현하기 위해 아래 보안·운영 경계를 기준으로 설계했습니다.

1. **확장자 위조·대용량 공격 차단:** 클라이언트 `Content-Type`이나 파일 확장자를 신뢰하지 않고 실제 **매직바이트**로 `JPG`·`PNG`·`WebP`·`PDF`만 허용하며, 파일당 최대 `5 MiB`·민원당 최대 `5개`로 제한하되 **첨부 업로드 외 모든 일반 JSON API의 기존 `64 KiB` 본문 한도(`413`)는 그대로 유지**합니다.
2. **개인정보(EXIF 위치·기기 정보) 자동 제거:** 외부 이미지 라이브러리 의존성 추가 없이 표준 라이브러리만으로 JPEG(`APP1`/`APP2`/`APP12~14`/`COM`), PNG(`eXIf`/`tEXt`/`iTXt`/`zTXt`/`tIME`), WebP(`EXIF`/`XMP ` 및 `VP8X` 플래그 비트) 메타데이터를 자동 제거합니다.
3. **비공개 접근 격리 및 고아 파일 방지:** 정적 디렉터리 직접 노출 대신 인증 경로(`GET /api/v1/complaints/{id}/attachments/{att_id}`)에서 민원 열람 권한을 검사해 비공개 민원 첨부에 대한 타 시민 접근을 `404`로 차단하고, CSP 샌드박스·`nosniff` 헤더 및 민원 영구 삭제 시 디스크 연쇄 삭제를 강제합니다.

## 2. 조치 내용

### 2.1 매직바이트 검증 · EXIF 제거 · 안전 저장소 (`src/complaints/attachments.py`, `config.py`, `http.py`, `src/app.py`)

- **무의존성 파일 검증·정제 (`validate_and_sanitize_upload`):**
  - `JPG`(`\xff\xd8\xff`)·`PNG`(`\x89PNG\r\n\x1a\n`)·`WebP`(`RIFF....WEBP`)·`PDF`(`%PDF-` + `%%EOF`)만 허용하고 위조 확장자·손상 구조를 `422`로 차단합니다.
  - JPEG·PNG·WebP의 EXIF/GPS/코멘트 청크를 제거해 `exif_stripped` 플래그로 기록하며, 파일명 경로 문자(`/`, `\`, `..`, 제어문자)를 정제하고 실제 형식에 맞는 확장자로 보정합니다.
- **저장소 계층 (`DiskAttachmentStorage` · `MemoryAttachmentStorage`):**
  - 운영 기본은 `.web-data/uploads/`(Git 제외, `COMPLAINT_UPLOAD_DIR`로 변경 가능)에 추측 불가능한 평면 키(`{uuid4 hex}{ext}`)로 임시파일 후 원자 교체(`os.replace`) 저장하며 `Path.resolve().is_relative_to()`로 경로 탈출을 차단합니다. 단위 테스트(`testing=True` 또는 `backend="memory"`)는 `MemoryAttachmentStorage`를 사용해 디스크 잔여물을 남기지 않습니다.
- **요청 크기 분리 보호 (`src/app.py`, `src/complaints/http.py`):**
  - `MAX_CONTENT_LENGTH`를 `6 MiB`로 설정하되 `protect_api()`에서 `POST /api/v1/complaints/<id>/attachments` 외 모든 요청은 기존과 동일하게 `64 KiB` 초과 시 `413 payload_too_large`를 반환합니다.

### 2.2 PostgreSQL 스키마 · API · 권한 경계 (`schema/complaint_app.sql`, `models.py`, `repository.py`, `service.py`, `api.py`)

- **`complaint_app.attachments` 테이블 추가:** `complaint_id REFERENCES complaints(id) ON DELETE CASCADE`, `uploaded_by REFERENCES users(id)`, `content_type CHECK`, `size_bytes CHECK (1..5242880)`, `sha256`, `storage_key UNIQUE`, `exif_stripped`. `storage_key`는 응답 모델(`AttachmentItem`)에 포함하지 않습니다.
- **신규 3개 오퍼레이션 (OpenAPI `36경로 · 44오퍼레이션`):**
  - `POST /api/v1/complaints/{complaint_id}/attachments`: 작성자 본인만(`403`), 미종료·5개 미만(`409`)일 때 업로드. DB 커밋 실패 시 저장소 파일 즉시 롤백.
  - `GET /api/v1/complaints/{complaint_id}/attachments/{attachment_id}`: `service.get()` 권한 통과 필수(비공개 타 시민 `404`), 이미지 `inline`(`?download=1`이면 `attachment`), PDF 항상 `attachment`, `Content-Security-Policy: default-src 'none'; sandbox` · `Cache-Control: private, no-store` · `X-Content-Type-Options: nosniff`.
  - `DELETE /api/v1/complaints/{complaint_id}/attachments/{attachment_id}`: 작성자 본인만·답변 게시 전(`409 already_published`) 삭제 가능.
- **민원 영구 삭제 연쇄 정리:** `delete_complaint()`가 DB 삭제 전 `list_attachment_keys()`를 확보해 삭제 직후 저장소 바이트 파일까지 모두 정리합니다.

### 2.3 프론트엔드 UI (`ui/src/attachments.js`, `app.js`, `staff.js`, `icons.js`, `styles.css`, `themes.css`)

- **민원 작성·수정 화면(`#/citizen/write`):** 클릭·드래그 앤 드롭 업로드 영역, 클라이언트 사전 검증(형식·5MB·최대 5개), 로컬 썸네일 미리보기·개별 제거, 수정 모드 기존 서버 첨부 표시·삭제, 민원 등록/수정 직후 자동 첨부 업로드(부분 실패 시에도 민원 본문 보존 및 안내).
- **민원 상세·담당자 목록 (`#/citizen/detail`, `#/staff/detail`, `#/staff/complaints`):** 이미지 썸네일 그리드(클릭 시 확대 라이트박스 모달 + `EXIF 제거` 배지), PDF 문서 카드·다운로드, 작성자 본인의 상세 화면 추가 첨부·(게시 전) 삭제, 담당자 큐 행의 `첨부 N` 배지 및 라이트·다크 테마 스타일을 적용했습니다.

## 4. 남은 한계 및 후속 범위

- **멀티모달 AI 이미지 분석:** 현재 첨부파일은 담당자·시민 검토용 증빙 보관이며, RAG+LLM 파이프라인(`src.assist`)에 이미지를 직접 입력하는 멀티모달 분석은 별도 후속 확장 범위입니다.
- **악성코드 실시간 스캔(AV) · 객체 스토리지(S3):** 로컬 시연 서버는 `.web-data/uploads/` + 매직바이트·CSP 샌드박스로 보호하며, 운영 배포 시 사내 스토리지·백신 스캐너 연동이 필요합니다.
