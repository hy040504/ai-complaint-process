## 1. 배경

"민원웹을 더 다듬고, 게스트·민원인·담당자의 차이를 표와 그림으로 README에 소개하며, README가 길고 기술적이니 쉽게 고쳐 달라"는 요청이었다. 감으로 고치지 않기 위해 먼저 화면 전체의 글자 대비를 측정했다.

## 3. 조치

**글자 대비(구현)**
- 대비 미달 요소에 **실제로 적용된 CSS 규칙만** 찾아 고쳤다(요소→규칙 역추적, 상속 포함). 어두운 배경 위 글자를 건드리지 않기 위해서다. 라이트 규칙 78개(1차 65 + 모바일 13), `--muted` 토큰 2곳, 사이드바 그룹 제목·알림 배지·쪽 번호·푸터 5곳을 접근 가능한 색으로 바꿨다.
- 라이트 보정이 다크를 깨지 않도록 다크 측정(기준선 4건)을 따로 하고, 악화된 곳만 `themes.css`에 다크 전용 색 5개를 추가했다.
- 활성 단계 숫자를 흰색으로 고쳤다.

**홈·헤더(구현)**
- 마크업 변경 없이 `design.css`에서 홈 보이는 순서를 인사말 → **질문·접수 입력창** → 내 민원 현황(모바일) → 소식 → 서비스로 바꿨다.
- ≤1100px에서 로그인 버튼을 다시 보이게 하고, ≤600px에서는 작은 버튼으로 헤더 오른쪽에 배치했다.

**문서(구현)**
- 이전 README 전체를 [`docs/기술_개요.md`](../기술_개요.md)로 옮기고(상대 링크 보정) 새 [README](../../README.md)를 152줄·약 5천 자로 다시 썼다. 용어를 쉬운 말로 풀고 "안전을 위해 지키는 약속"·"지금 상태와 한계"를 따로 두었다.
- 게스트·민원인·담당자를 비교하는 그림([`roles.svg`](../assets/roles.svg))·표, 이용 흐름 그림([`flow.svg`](../assets/flow.svg)), 실제 화면 캡처 8장([`screens/`](../assets/screens/))을 넣었다. 그림은 체크·엑스 모양과 글자로도 구분되어 색에만 의존하지 않는다.
- 같은 내용을 Design 캔버스(역할 한눈에·권한 비교표·이용 흐름 3장)로도 만들어 비공개 아티팩트로 두었다.

## 4. 겪은 문제와 수정

- 1차 규칙 수집은 요소 자신에게 붙은 규칙만 보아 **푸터처럼 상위에서 색을 물려받는 글자**를 놓쳤다. 부모 요소까지 거슬러 찾도록 보강했다.
- 라이트 규칙을 어둡게 하자 **다크에서 시민 홈이 0→3건으로 악화**됐다(다크에는 덮어쓰는 규칙이 없던 곳). 다크 모드로 수집기를 다시 돌려 5곳만 보정했다.
- 보정으로 활성 단계 숫자가 오히려 1.18:1이 되어 기존 버그가 드러났고, 활성 규칙에 흰 글자를 명시했다.
- 수집 스크립트가 페이지 안에서 노드 변수(`DARK`)를 참조해 한 번 실패했다. 값을 주입하도록 고쳤다.
- 줄바꿈이 CRLF인 파일에서 여러 줄 문자열 치환이 일치하지 않아 정규식으로 바꿨다. 일부는 규칙 앞에 다른 속성이 있어 패턴이 빗나가 블록 안 어디서나 잡도록 고쳤다.
- 이전에 커밋한 시연 계정(`abcd` / (시연 비밀번호))과 공개 주소가 **공개 저장소**에 올라갈 수 있어 README에는 계정 값을 쓰지 않았다(아래 한계 참고).

## 6. 한계

- 대비 측정은 **단색 배경 위 글자**만 대상이다. 그라디언트·이미지 위 글자, 마우스를 올린 상태·비활성 상태, 담당자 홈(`/staff/`)·API 화면의 최종 재측정은 하지 않았다(1차 수집에는 포함).
- 접근 가능한 색은 규칙마다 계산한 값이라 색 이름 없이 값이 흩어져 있다. 토큰으로 묶는 정리는 후속이다(`--muted`만 토큰 수정).
- README 화면 캡처는 로컬 시연 데이터(합성 민원 2건)다. 공개 서버 화면과 데이터가 다르다.
- **공개 저장소에 시연 계정 노출 위험:** 담당자 `abcd` / (시연 비밀번호)가 코드·배포 문서에 있고 공개 도메인이 문서에 적혀 있다. 아직 푸시하지 않았으며, 푸시 전에 비밀번호를 환경변수로 옮기거나 계정을 끄는 결정이 필요하다.
- 서버 배포와 푸시는 하지 않았다.
