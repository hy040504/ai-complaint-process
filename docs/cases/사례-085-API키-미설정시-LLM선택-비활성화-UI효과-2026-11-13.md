## 2. 배경과 요구사항

- **배경:**
  - CASE-084에서 응대 검사기 상단에 4개 LLM 공급자(기본 설정, K-EXAONE 2.5, Codex CLI, GPT-6 Luna API) 세그먼트 버튼을 추가했습니다.
  - 하지만 `.env`에 `OPENAI_API_KEY`나 `EXAONE_API_KEY`가 입력되어 있지 않은 상태에서도 해당 버튼이 활성화되어 있어, 사용자가 클릭해 민원을 보냈을 때 백엔드에서 인증 토큰 누락으로 오류가 발생하거나 사용자에게 혼선을 줄 수 있었습니다.
- **요구사항:**
  - API 키로 작동하는 LLM의 경우 `.env`에 키가 입력되어 있지 않으면 버튼이 선택되지 않도록 비활성화하고 시각적인 UI 효과(흐림, '키 미설정' 배지, 안내 툴팁, 클릭 시 흔들림 애니메이션)를 제공합니다.

## 3. 조치 내용

1. **공급자 가용성 판별 로직 추가 (`src/llm/settings.py`):**
   - `check_provider_availability(provider)`: 각 공급자(`exaone_api`, `openai_api`, `codex_cli`, 기본 설정)의 환경변수/키/CLI 설치 여부를 확인하여 `(available, reason)` 튜플을 반환.
   - `provider_availability_map()`: 전체 공급자의 상태 맵 반환.
2. **검사기 양식 API 계약 확장 (`src/lab_web/models.py`, `src/lab_web/app.py`):**
   - `ProviderStatus` Pydantic 모델 정의(`available`, `reason`).
   - `LabFields` 모델에 `providers: dict[str, ProviderStatus]` 필드 추가.
   - `/api/v1/lab/fields` 응답에 각 공급자의 가용 상태를 포함하여 화면 초기화 시점에 즉시 전달.
3. **비활성화 및 시각 효과 스타일링 (`src/lab_web/static/styles.css`):**
   - `.llm-choice-btn:disabled`, `.llm-choice-btn.is-disabled`: `opacity: 0.52`, `cursor: not-allowed`, 점선 테두리(`border-style: dashed`), 회색 톤(`filter: grayscale(0.5)`).
   - `.badge-disabled`: 붉은색 계열 경고 배지 스타일 (`#fee2e2`, `#b91c1c`).
   - `@keyframes llm-shake`: 비활성화 버튼 클릭 시 좌우 흔들림 애니메이션 효과 적용.
4. **프론트엔드 연동 및 Fallback 처리 (`src/lab_web/static/app.js`):**
   - `updateLlmAvailability(root, providerStatus)` 함수 구현:
     - 키가 없는 공급자 버튼에 `disabled`, `is-disabled`, `aria-disabled="true"` 속성 부여.
     - 배지 문구를 `미설정` 또는 `키 미설정`으로 변경하고 설명 텍스트를 `API 키 미설정 (.env)`로 갱신.
     - 마우스 호버 시 `[선택 불가] .env에 OPENAI_API_KEY가 설정되지 않았습니다.` 툴팁 표시.
     - 비활성화된 버튼 클릭 시 `shake` 애니메이션을 트리거하여 시각적 피드백 제공.
     - 이전에 `localStorage`에 저장된 선택지가 현재 비활성화 상태인 경우, 사용 가능한 첫 번째 엔진(기본 설정 등)으로 자동 fallback 전환.
   - `loadFields()`에서 `value.providers` 수신 시 `updateLlmAvailability` 즉시 호출.
5. **단위 테스트 추가 (`src/tests/test_llm_env.py`, `src/tests/test_lab_web.py`):**
   - 공급자 가용성 맵 생성 검증 (`test_provider_availability_map`).
   - `/api/v1/lab/fields` 응답의 `providers` 필드 검증.
