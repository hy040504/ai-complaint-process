## 2. 배경·증상과 기대 동작

사용자는 `ui/예시 html/`과 전체 프로젝트를 참고해 시민·담당자 사이트를 각각 구현하도록 요청했다. 기존 구현은 검색 CLI/API까지이며 웹 업무 계층은 설계만 있었다. 역할별 화면을 이동하고 등록·답변 교환을 직접 체험할 UI가 필요했다.

## 3. 재현·확인 방법

저장소 루트에서 `npm --prefix ui run dev`를 실행한 뒤 `http://127.0.0.1:5173`에 접속한다. 시민 민원을 작성하고 상단에서 담당자 사이트로 전환한다. 민원 관리에서 초안을 저장하고 시민 사이트에서 비노출을 확인한 후, 담당자 미리보기에서 게시하고 시민 상세의 답변을 확인한다.

## 4. 결정 근거

이번 요청은 UI 구현이므로 기존 검색·모델·DB 환경을 변경하지 않고 외부 의존성 없는 HTML/CSS/JavaScript와 정적 파일 서버로 구성했다. 브라우저 저장은 화면을 연결하는 시연 수단이며 통합 설계의 업무 DB 구현 완료로 해석하지 않는다. 미연동 상태에서 실제 검색 근거·정책·부서 확정·AI 진행률을 만들지 않는다.

초기 검증에서 미리보기의 대상 민원 참조 누락을 발견해 고쳤다. AI 시연 종료 후 편집 화면 버튼이 비활성 상태로 남는 문제도 수정하고 재실행·입력 보존을 다시 검증했다.

보안 권한은 서버에서 구현해야 한다. 시민 HTML에 초안을 렌더링하지 않지만 로컬 저장소 자체에는 초안이 있으므로 운영상 비밀 보호를 보장하지 않는다. 낙관적 버전 비교도 실제 서버의 탭 간 원자적 트랜잭션을 대체하지 않는다. 실제 검색·DB·모델 평가와 공식 행정 연동은 이번 변경 대상이 아니므로 실행하지 않았다. 원본·색인·운영 서비스는 변경하지 않았다. 원격 업로드·배포는 수행하지 않았다.

## 7. 완료 조건·후속 작업·복구

시민·담당자 UI를 로컬에서 체험하고 주요 교환 동작을 확인하는 범위는 완료했다. 후속으로 [통합 설계](../../plan/민원_웹_MVP_상세설계와_분야별_작업계획.md)의 서버 인증·업무 DB·작업자·SSE·AI 어댑터와 연결해야 한다. UI 계약과 서버 최종 검증을 맞춘 뒤 통합 인수 검증을 수행한다. 개발 데이터만 초기화할 때는 `cheongju-ui-v1` 키만 삭제한다.
