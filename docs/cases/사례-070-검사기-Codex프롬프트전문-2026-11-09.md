## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: `#codex-json`은 사용자 JSON과 PREFIX 이름만 보여 주어, 실행 래퍼와 PREFIX 본문이 빠진 채 전달된 것처럼 보였다.
- 기대 동작 또는 요구사항: Codex CLI `exec -` 표준 입력과 같은 문자열을 호출마다 보여 준다.
- 확인 근거와 시점: 2026-11-09 사용자 요청 「진짜로 codex에게 보낸 프롬프트를 보여주는 란」.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: `http://127.0.0.1:5010/`에서 민원을 새로 보낸다. 예전 기록 JSON에는 `prompt`가 없을 수 있다.
- 단계: 결과의 `Codex에 보낸 프롬프트`에서 1차 판정·담당자 초안 칸을 연다. `[시스템 지시]`, PREFIX 본문, `[사용자 입력]`, 검색 후보 JSON이 이어진다. `프롬프트 복사`로 그 호출 본문만 복사한다.
- 비교한 기존 동작: CASE-059는 사용자 JSON만 표시하고 PREFIX 전문은 넣지 않았다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: `complete_codex_cli`는 `codex_tool_instruction()` + `[시스템 지시]` + PREFIX 조립본 + `[사용자 입력]` + 사용자 JSON을 stdin으로 넣는다.
- 검토한 선택지와 결정 이유: 화면에서 PREFIX를 다시 조립하지 않고, `format_codex_stdin` 한 함수를 CLI 호출과 `assist.codex[].prompt`가 같이 쓴다. `user_json`은 `chat`에 넣은 문자열을 그대로 기록한다.
