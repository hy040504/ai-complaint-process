## 2. 배경·증상과 기대 동작

사용자는 `ui/예시 html/`의 HTML에서 시민 웹 부분의 디자인·효과를 더 가깝게 구현하도록 요청했다. 이전 시민 UI는 녹색 대형 소개 영역과 일반 웹 메뉴여서 예시의 파란색 모바일 접수 경험과 달랐다.

## 3. 재현·확인 방법

기존 Flask 서버로 `/#/citizen`에 접속한다. 소식 카드를 눌러 바텀시트를 열고, 문의 버튼 또는 가로 서비스 메뉴로 시연 대화를 시작한다. 타이핑 점·말풍선·안내 카드 표시를 확인한 뒤 원문 보완 화면으로 이동해 시연 민원을 등록한다. 하단 메뉴에서 내 민원·게시 답변 알림·프로필을 확인한다.

## 4. 결정 근거

참고 HTML을 파일 URL로 브라우저에서 열어 홈·안내 바텀시트·상담을 직접 확인하고 해당 CSS·함수를 읽었다. ‘시민특별시’·CI, 소식 → 서비스 → 말하듯 접수 순서, 파란 강조색, 둥근 카드와 가운데 접수 버튼을 재사용·재구성했다. 원본은 수정하지 않았고, 포함된 CI PNG를 로컬 CSS에 추출해 외부 통신 없이 사용한다.

예시의 행정 공지·일정·신뢰도·자동 배정·종결·문자 발송 문구는 현재 구현된 사실과 다르므로 복사하지 않는다. 소식은 시연 서비스 이용 안내, 알림은 실제 게시된 본인 답변이며 상담은 고정 응답 시연으로 표시한다. 기존 서버 저장·권한·초안 비노출 경계는 유지한다.

## 5. 조치와 변경 내용

| 파일·계약 | 변경 | 상태 |

| `ui/src/citizen.css`, `citizen-brand.css` | 예시 색·간격·카드·CI, 반응형 하단 메뉴, 바텀시트·타이핑·호버·등장·모션 감소 | 구현 |

PC는 본문·민원 요약의 두 열로 확장하고 모바일은 예시와 같은 순서로 배치한다. 모바일 하단 메뉴는 고정하며 PC 하단 메뉴는 문서 흐름에 배치해 접수 영역을 가리지 않는다. 담당자 화면에는 시민 CSS가 적용되지 않도록 범위를 제한했다.

처음 PC 캡처에서 하단 고정 메뉴가 접수 영역과 겹쳐 PC에서는 흐름 배치로 수정하고 재캡처했다. 좁은 화면의 지역·분야 필터 화살표 여백도 보완했다. 기존 서버 코드가 바뀌지 않아 Python·모델 평가를 반복하지 않았다. 실제 AI·문자·자동 마스킹·공식 이관 기능의 완료를 주장하지 않는다. 신규 시연 안내와 답변 알림 화면은 공식 행정 공지·외부 알림 연동이 아니다.

## 7. 완료 조건·후속 작업·복구

예시의 디자인·상호작용을 반영하면서 실제 서버 등록·게시·추가 문의를 확인했다. 후속 AI·운영 인증·SSE 범위는 [서버 안내](../../src/README.md)를 따른다. 원본 HTML·RAG 자료·다른 기존 작업을 변경하지 않았다. 변경은 로컬 코드·문서에만 적용했으며 원격 업로드·운영 배포는 수행하지 않았다.
