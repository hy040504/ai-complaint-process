## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 두 CMD를 실행하면 창이 바로 닫혀 성공·실패를 읽기 어렵다.
- 기대 동작 또는 요구사항: 기동 상태가 창에 남고, 문장 임베딩은 인자 없이 실행해도 문장을 받을 수 있다.
- 확인 근거와 시점: 2026-11-06 이 호스트에서 더블클릭과 같은 `Start-Process`로 확인했다.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: 5432·8007이 이미 열려 있는 Windows 저장소 루트.
- 개인정보를 제거한 입력, 단계, 실제 결과: `검색-시작.cmd`는 약 2초 안에 종료 코드 0으로 끝났다. `문장-임베딩.cmd`는 문장 없이 실행하면 `[오류] 임베딩할 문장을 인자로 넣어 주세요.` 뒤 `pause`로 창이 남았다.
- 버그가 아닌 설계·개선 기록이라면 비교한 기존 동작과 판단 근거: 검색 기동 성공 경로에는 `pause`가 없었다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: `검색_시작.py`는 포트가 이미 열려 있으면 안내만 출력하고 0으로 끝난다. PostgreSQL과 검색 API는 별도 콘솔에 있고, 기동 CMD 성공 시에는 키 대기가 없었다. 문장 임베딩은 위치 인자가 없으면 모델 로드 전에 종료 코드 2로 끝난다.
- 아직 확인하지 않은 가설: 편집기에서 표준 입력이 바로 닫히는 실행은 `pause`도 즉시 반환할 수 있다. 그 경로는 다시 재현하지 않았다.
- 검토한 선택지와 결정 이유: 서버 프로세스를 기동 CMD 안에 붙이면 그 창을 닫을 때 DB가 죽을 수 있다. 별도 창은 유지하고, 기동 CMD만 키 입력까지 남긴다.

| 수행일·환경 | 확인 방법·명령 | 실제 결과 | 증거 파일·커밋 |

- 데이터·모델 평가일과 문서 작성일이 다르면 각각 표시: 해당 없음.
