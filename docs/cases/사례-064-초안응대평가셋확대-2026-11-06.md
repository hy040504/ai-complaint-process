## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 초안 평가가 검색 예제 10건에 머물렀고, 제안된 여섯 묶음(FAQ 적용·조치·부서·범위 밖·복합·오용)이 비어 있었다.
- 기대 동작 또는 요구사항: 검색 Hit를 안내 정답으로 복사하지 않고, 같은 원문 그룹은 개발/보류에 나누지 않으며, 보류 문항은 기본 러너가 돌리지 않는다.
- 확인 근거와 시점: 2026-11-06 사용자 요청 「평가셋 확대부터」. CRUD LLM은 하지 말 것.

## 3. 재현·확인 방법

- 재현 환경·선행 조건: 검색 API `:8007`, `.venv-web`.
- 개인정보를 제거한 입력, 단계, 실제 결과:
  - `pytest src/tests/test_eval_set.py rag/tests/test_assist.py src/tests/test_prompts.py`
  - `python scripts/응대_평가.py --missing` 후 `--only FAQ_생활쓰레기시간`
  - 개발셋 26/26. 보류 3/3(`--split holdout --output rag/reports/assist-eval-holdout.json`). `automatic_transfer` 모두 거짓.
- 설계 근거: 400문항은 사람 검수 전 제안이다. 이번은 초안 29건이다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: `FAQ_생활쓰레기시간` FAQ는 홈페이지 링크만 있고 배출 시각이 없다. 모델이 `faq_answer`와 `condition_unclear`를 같이 냈다. 코드가 안내를 막지 않으면 평가가 실패한다.
- 아직 확인하지 않은 가설: 400문항 검수.
- 결정: 조건 부족 사유는 FAQ 안내로 남기지 않는다. 평가 라벨을 바꿔 통과시키지 않는다.
