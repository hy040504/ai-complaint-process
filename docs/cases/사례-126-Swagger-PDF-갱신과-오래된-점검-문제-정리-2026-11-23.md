## 1. 요청

정적 Swagger PDF에 빠진 `/visibility`를 반영하고, 그동안 미뤄 둔 문제(적재 스크립트의 옛 DB 라이브러리, 웹용 가상환경의 부족한 패키지, mypy 오류)를 조치한다.

## 2. 조치

| 문제 | 원인 | 조치 |
| --- | --- | --- |
| Swagger PDF에 `visibility` 없음 | CASE-124 이후 다시 만들지 않음 | `export_swagger_pdf.py`로 재생성. **38경로**(이전 36), `/api/v1/complaints/{complaint_id}/visibility` 포함. 표지의 날짜는 고정 글자(2026-11-05)여서 만든 날짜로 바꿈 |

## 4. 한계

- `rag/tests`의 PostgreSQL 격리 테스트 3건은 이 Windows PC에서는 여전히 실행하지 못하고(PostgreSQL 없음), 서버에서 돌려 확인했다. 첫 실행에서 3건이 오류였으나 같은 조건 재실행에서 통과해 일시적 현상으로 보며 원인은 확정하지 못했다.
- `test_windows_codex_cmd_wrapper_runs_node_entry`는 Windows 경로를 쓰는 테스트라 리눅스에서 실패했고, Windows에서만 실행하도록 조건을 붙였다.
- 테스트 폴더(`src/tests`)는 mypy 검사 대상이 아니다(기존 설정 유지). 테스트 타입을 정리하려면 `Response.json`의 `None` 처리 등 약 230곳을 손봐야 한다.
- `.venv-web`의 패키지 설치는 개발 PC의 환경 변경이며 저장소 파일이 아니다.
