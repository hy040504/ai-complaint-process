## 1. 요청

정적 Swagger PDF에 빠진 `/visibility`를 반영하고, 그동안 미뤄 둔 문제(적재 스크립트의 옛 DB 라이브러리, 웹용 가상환경의 부족한 패키지, mypy 오류)를 조치한다.

## 2. 조치

| 문제 | 원인 | 조치 |
| --- | --- | --- |
| Swagger PDF에 `visibility` 없음 | CASE-124 이후 다시 만들지 않음 | `export_swagger_pdf.py`로 재생성. **38경로**(이전 36), `/api/v1/complaints/{complaint_id}/visibility` 포함. 표지의 날짜는 고정 글자(2026-11-05)여서 만든 날짜로 바꿈 |
| `rag/db/load_samples.py`가 `psycopg2` 사용 | 저장소 나머지는 `psycopg` 3인데 이 스크립트만 옛 라이브러리 | `psycopg`(3)로 이전. jsonb 칸은 `Jsonb`로 넣음. 다른 코드·요구 사항 변경 없음 |
| `rag/tests/test_postgres.py`가 웹용 가상환경에서 수집 오류 | `numpy`·`pgvector` 없음 | `.venv-web`에 설치(`numpy`, `pgvector==0.5.1`). 이제 수집되고 `RUN_PG_TESTS`가 없으면 3건 건너뜀 |
| "mypy 오류 229건" | **잘못 잡은 기준.** `mypy src`로 돌리면 설정의 `exclude`가 무시되어 테스트 폴더까지 검사됨 | 프로젝트 설정(`--config-file src/mypy.ini`, 테스트 제외)으로 돌리면 실제 오류는 **3건**. 모두 해결: ① `http.py` 반환 타입 명시 ② `api.py`의 `FileStorage`를 정의된 모듈(`flask_openapi3.models.file`)에서 가져옴(werkzeug 클래스와 다른 하위 클래스라 바꿔 쓰면 안 됨) ③ 런타임에 경로를 더하는 `start_console`을 `mypy.ini`에서 예외 처리 |

## 4. 한계

- `load_samples.py`는 **실제 PostgreSQL에 적재해 보지 못했다**(이 PC에 PostgreSQL이 없다). 라이브러리만 바꾼 이식이며, 서버나 PostgreSQL이 있는 곳에서 `--create` 적재를 한 번 돌려 확인해야 한다.
- `rag/tests`의 PostgreSQL 격리 테스트 3건은 여전히 이 Windows PC에서 실행하지 못한다.
- 테스트 폴더(`src/tests`)는 mypy 검사 대상이 아니다(기존 설정 유지). 테스트 타입을 정리하려면 `Response.json`의 `None` 처리 등 약 230곳을 손봐야 한다.
- `.venv-web`의 패키지 설치는 개발 PC의 환경 변경이며 저장소 파일이 아니다.
