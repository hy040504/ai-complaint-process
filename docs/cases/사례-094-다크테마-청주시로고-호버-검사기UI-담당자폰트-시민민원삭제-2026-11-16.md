## 2. 배경·증상과 기대 동작

- **관찰한 사실과 영향:**
  1. **다크 테마 부자연스러운 밝은 요소:** `.citizen-city-logo`가 라이트용 흰 배경 이미지를 감싼 `#fff` 박스 위에 올라가 인트로·시민 헤더·`#/lab`에서 도드라졌고, 서비스 SVG 아이콘 12종의 `<rect>` 배경(`#f0f5ff`)·`.guide-step .quick-icon`·favicon 등이 어두운 화면과 이질적이었습니다.
  2. **다크 테마 호버 시 과도한 밝아짐:** `.citizen-shell`이 자체적으로 `--teal-soft: #edf3ff`를 재정의하고 `staff.css`가 `.icon-btn:hover`에 `#edf2fb`를 직접 고정해, 도움말(`?`)·테마 전환·알림·초기화 단추·`.citizen-update-row`·`.citizen-bottom-nav > a` 등에 마우스를 올리면 순간적으로 하얗게 번쩍였습니다. 단독 검사기(`:5010`)에도 다크 모드가 없었습니다.
  3. **담당자 부서 메타 표기 및 검사기 UI 차이:** 담당자 상세 화면에 `(업무분장: unverified, 관할: inferred_from_name · 자동 이관 아님)` 원시 문구가 그대로 노출되었고, `#/lab` 및 `:5010` 검사기 UI 정돈과 담당자 화면 글자 크기 확대가 필요했습니다.
  4. **시민 본인 민원 영구 삭제 부재:** 기존 `DELETE /api/v1/complaints/<id>`는 이력을 남기는 논리 철회(`withdrawn`) 전용이어서, 시민이 내 민원 목록·상세 화면에서 작성 민원을 완전히 삭제할 수 없었습니다.
- **기대 동작 또는 요구사항:**
  - 라이트/다크 테마 각각에 어울리는 투명 배경 청주시 로고와 어두운 아이콘 배경·파비콘을 적용하고, 전체 웹(`:5000`·`:5010`)의 `:hover` 배경 휘도를 어두운 slate-blue 계열로 통일합니다.
  - `(업무분장: ..., 관할: ... · 자동 이관 아님)` 원시 상태 표기는 응대 검사기(`#/lab`, `:5010`) 테스트 환경에만 유지하고 담당자 사이트에서는 추천 안내 라벨로 분리합니다.
  - 담당자 콘솔 텍스트 크기 전반을 키우고, `#/lab`과 `:5010` UI를 시민 사이트 디자인 기준으로 정리합니다.
  - 기존 논리 철회(`DELETE /api/v1/complaints/<id>`)와 계약을 깨지 않고 작성자 본인 영구 삭제(`POST /api/v1/complaints/<id>/delete`) API와 상세·목록 UI를 추가합니다.

## 3. 재현·확인 방법

- **다크 테마 대비·로고·호버 점검:** `http://127.0.0.1:5000/` 및 `http://127.0.0.1:5010/`에서 다크 테마(`minwon-ui-theme="dark"`) 전환 후 전 화면 텍스트 대비(`>= 4.5:1`), 밝은 표면 여부(`lum <= 0.45`), 실제 마우스 `mouseMoved` 상태의 `:hover` 배경 휘도 검증.
- **시민 영구 삭제 E2E:** `#/citizen/write`에서 임시 합성 민원 2건 등록 → 상세(`민원 삭제`)와 `#/citizen/mine`(행 `삭제`) 각각으로 삭제 확인 모달 제출 → DOM 제거 및 `GET /api/v1/complaints/<id>` `404` 확인(기존 사용자 민원 보존 확인).

## 4. 원인 분석 또는 결정 근거

- **청주시 로고 다크 자산 분리:** 어두운 배경에서도 글자(`청주시 CHEONGJU CITY`)와 녹색 잎 심볼이 깨짐 없이 보이도록 투명 알파 채널을 가진 `300x121` 다크 PNG를 생성해 `ui/src/citizen-brand.css`의 `body[data-theme="dark"] .citizen-city-logo`로 분기하고, `ui/src/themes.css`에서 로고 뒤 불필요한 흰 배경 박스를 제거했습니다.
- **호버 번쩍임 근본 원인:** `citizen.css`의 `.citizen-shell` 지역 변수 재정의(`--teal-soft`)와 `staff.css`의 하드코딩된 `:hover` 색상을 `themes.css`의 `body[data-theme="dark"]` 규칙으로 덮어쓰고, `.inline-actions :is(a, button)` / `.danger-link`의 배경·테두리까지 다크 전용 색상을 명시했습니다.
- **영구 삭제 경로 설계(`POST /complaints/<id>/delete` + FK 선삭제):** 기존 `DELETE /complaints/<id>`는 이력 보존형 논리 철회(`withdraw`)로 API·테스트 계약이 고정되어 있으므로, 버전 확인(`VersionInput`)과 소유자 검증(`actor.role == "citizen"` 및 `row.owner == actor.id`, 트랜잭션 잠금 안 재검증)을 거치는 `POST /api/v1/complaints/<complaint_id>/delete` (`204 No Content`)를 추가했습니다. PostgreSQL에서는 `idempotency.complaint_id`가 `complaints.id`를 참조하므로 `DELETE FROM idempotency`를 먼저 실행한 뒤 `DELETE FROM complaints`를 수행합니다.
