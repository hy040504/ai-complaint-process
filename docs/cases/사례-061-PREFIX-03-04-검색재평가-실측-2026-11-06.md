## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: PREFIX-03/04는 파일만 있었고 판정 파이프라인은 00~02만 썼다. e5-small-ko 재임베딩 뒤 검색 예제 10건을 다시 돌리지 않았다. 공급자 실측도 기록으로 남지 않았다.
- 기대 동작: FAQ가 아니면 PREFIX-03 초안을 만들고, 원문 힌트가 있으면 PREFIX-04 순화를 만든다. 시민 안내와 `automatic_transfer`는 그대로다. 검색 예제는 상위 5개 포함과 `requires_gate`를 확인한다.
- 확인 근거: 2026-11-06 사용자 요청 「남은 범위들도 진행」.

## 3. 재현·확인 방법

- PREFIX-03/04는 판정 갈래를 바꾸지 않는다. 초안은 `staff_draft`, 순화는 `sanitize`다.
- 검색: `python -m rag.evaluate --output rag/reports/retrieval-e5-small-ko.json`
- 실측: `python scripts/응대_실측.py`

## 4. 원인 분석 또는 결정 근거

- PREFIX-03/04를 1차 판정 시스템 지시에 넣지 않는다. 웹 CRUD 초안 저장과도 섞지 않는다.
- PREFIX-04는 모든 민원에 호출하지 않고 원문 힌트가 있을 때만 켠다.
- openai_api 비교는 `.env`를 바꾸지 않아 이번 기록에 넣지 않는다. 운영 모델은 미정이다.
