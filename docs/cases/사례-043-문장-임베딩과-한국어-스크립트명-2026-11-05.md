## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: 검색 API·PostgreSQL 없이 한 문장의 e5-small 벡터 숫자만 보는 스크립트가 없었다. 실행 파일명은 영문이라 한국어 작업 안내와 어긋났다.
- 기대 동작 또는 요구사항: 한 문장을 인자로 넣으면 숫자만 출력할 수 있고, 기존 스크립트도 한국어 파일명으로 각각 동작한다.
- 확인 근거와 시점: 2026-11-05 사용자 요청 「한 문장을 벡터로 찍어서 숫자만 보여주는 독립 스크립트」·「지금 있는 스크립트들도 파일 이름을 한국어로」·「전부 각각 작동하는지 테스트」.

## 3. 재현·확인 방법

- 비교한 기존 동작: 벡터는 `python -m rag ingest`·검색 API 내부 `Models.encode`에만 있었고, CLI로 한 문장 숫자를 뽑지 못했다.
- 판단 근거: 임베딩은 RAG `.venv`의 같은 모델·접두(`query:` / `passage:`)를 쓰고, DB·검색 API·LLM은 열지 않는다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: 독립 출력기가 없었고, Windows `cmd.exe`는 UTF-8 BOM 배치의 `@echo off`를 명령으로 읽는다.
- 검토한 선택지와 결정 이유: CMD는 UTF-8(무 BOM)·CRLF로 두고, ASCII로 `.venv` 경로를 정한 뒤 `chcp 65001` 다음에 한국어 `.py` 경로를 둔다. Python 모듈 식별자(`ask_assist` 테스트 로드 이름)는 유지하고 파일명만 한국어로 둔다. `PACKET/` 수집기·`ui/scripts`·`rag/*.py` 엔진은 실행 바로가기가 아니므로 이름을 바꾸지 않는다.

## 7. 완료 조건·후속 작업·복구

- 완료: 한 문장 `--raw` 벡터 숫자 출력, 한국어 파일명 스크립트·CMD가 이 호스트에서 동작, 문서가 현재 이름을 가리킴.
- 남은 작업: 우분투에서 `bash -n`과 네이티브 스크립트 실실행, Git 커밋·업로드.
- 되돌림: `git mv`로 영문 파일명 복구. CMD는 UTF-8 무 BOM을 유지한다. 원본 JSON 복구 대상은 없다.
