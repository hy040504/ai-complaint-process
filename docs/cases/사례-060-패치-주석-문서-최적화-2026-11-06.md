## 2. 배경·증상과 기대 동작

- 관찰한 사실과 영향: CASE-057~059는 검색·판정 연결과 MCP 핸드셰이크, Codex 입력 표시에 집중했다. 루트 README 다음 단계는 이미 끝난 검사기 RAG+LLM 응답을 아직인 일로 적었다. `docs/README.md` 시작점은 `:5000/#/lab`이었다. MCP 본문 객체 검사가 줄 단위와 Content-Length에 나뉘어 있었다.
- 기대 동작 또는 요구사항: 한국어 Google 형식 docstring, 패치와 같은 현재 문서, MCP JSON 본문을 한 경로에서 검사한다.
- 확인 근거와 시점: 2026-11-06 사용자 요청 「주석 점검, readme/docs 업데이트, readme 디자인 개선, 코드 최적화, 깃헙 업로드」.

## 3. 재현·확인 방법

- 비교한 기존 동작: NDJSON·Content-Length가 각각 `isinstance(..., dict)`를 했다. `_decode_json_line`은 공백을 먼저 지운 뒤 BOM을 봤다. 검사기 `app.js`는 결과 채우기가 제출 처리 안에 있었고, `sendComplaint` JSDoc이 비어 있었다. README 「이 브랜치에서 검사기 RAG+LLM 응답」을 다음 단계로 표시.
- 판단 근거: `_as_rpc_object` 한 함수로 본문 형태를 맞춘다. UTF-8 BOM은 공백보다 앞에 온다. 검사기 검색·판정은 CASE-057·058에서 끝났다.

## 4. 원인 분석 또는 결정 근거

- 확인된 원인·근거: CASE-057~059는 동작 수정에 집중했고 주석·현재 문서·소규모 최적화를 이 작업으로 넘겼다.
