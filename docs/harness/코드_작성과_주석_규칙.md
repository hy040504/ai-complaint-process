# 코드 작성·주석·커밋 규칙

[작업 지침](../../AGENTS.md) · [하네스 안내](README.md) · [사례 색인](../cases/README.md)

2026-10-25 사용자 지침: **모든 설명 주석과 docstring, 새로 작성하는 커밋 메시지의 제목·본문은 한국어**로 작성합니다. 기술명·변수명·API 이름·명령은 원래 표기를 사용합니다. 인코딩 선언·shebang·타입 검사 지시처럼 도구가 읽는 표기는 필요한 문법을 유지합니다.

## 주석과 docstring 형식

현재 수집 코드가 사용하는 Google 형식을 새 Python 코드의 기본으로 합니다. NumPy 배열을 사용한다는 이유만으로 docstring 형식을 바꾸지 않습니다. 기존 모듈이 NumPy 형식이면 `Parameters`, `Returns` 등 기존 구성을 유지하고 설명은 한국어로 작성합니다. 형식 참고: [Google 공식 안내](https://google.github.io/styleguide/pyguide.html#38-comments-and-docstrings), [numpydoc 공식 안내](https://numpydoc.readthedocs.io/en/latest/format.html).

- 모듈은 책임, 클래스는 역할과 필요한 공개 속성, 함수·메서드는 동작과 계약을 설명합니다.
- Google 형식의 `Args:`, `Returns:`, `Yields:`, `Raises:`, `Attributes:` 같은 표준 제목은 유지합니다. 각 항목의 설명은 한국어로 작성합니다.
- 인자 이름은 실제 시그니처와 맞추며 키워드 전용 인자·가변 인자도 포함합니다. `self`·`cls`는 반복 설명하지 않습니다.
- 반환값이 튜플이면 각 구성 요소를 설명하고, 값이 없으면 불필요한 `Returns:`를 만들지 않습니다. 제너레이터·컨텍스트 관리자는 실제 산출값에 맞는 `Yields:`를 씁니다.
- 중요한 입력 제약, 원본 변경, 트랜잭션·파일 교체 같은 부작용과 호출자가 처리할 예외를 설명합니다. 실제로 검사하지 않는 조건을 검사한다고 적지 않습니다.
- 단순한 무인자 진입점·테스트에는 한국어 요약 한 줄을 사용할 수 있습니다. 테스트의 주석은 보장하려는 계약을 설명합니다.
- 인라인 주석은 조건 보존·안전한 실패·순위 계산 등 코드만으로 드러나지 않는 이유를 설명합니다. 변경할 때 낡은 주석도 함께 고칩니다.

Google 형식 예시:

```python
def find_evidence(query: str, limit: int = 5) -> list[dict]:
    """질문에 대한 검색 근거를 반환합니다.

    Args:
        query: 검색할 민원 원문입니다.
        limit: 반환할 근거 수의 상한입니다.

    Returns:
        검색 순위순 원문·출처 목록입니다.
    """
```

위 예시는 문서 형식만 보여주며 구현된 검색 함수가 아닙니다.

## 최적화 점검

중복 계산, 필요 이상으로 가져오는 원문·JSON, 반복 연결·모델 로드, 무제한 목록·배치 생성, 미사용 import를 확인합니다. 실제 데이터 규모·호출 경로에서 이득이 있는 변경을 우선합니다.

검색 변경은 FAQ·사례 분리, 순위·후보 수, 관할 필터, 원문 보존, `requires_gate` 계약을 확인합니다. DB·모델을 바꿀 때는 [평가 기준](evaluation.md)을 추가로 따릅니다. 조회량 감소와 사용자 체감 시간 단축을 구별하고, 측정하지 않은 전체 성능 개선율을 작성하지 않습니다.

## 커밋 메시지

제목은 `개선: 재정렬 제외 검색의 후보 조회량 축소`처럼 한국어로 변경과 목적을 표현합니다. 본문이 있으면 변경 이유·검증·한계도 한국어로 작성합니다. 모델명·코드 경로·커밋 해시·명령은 그대로 적을 수 있습니다.

커밋 전에는 변경 파일과 실제 메시지의 제목·본문을 확인합니다. 자동 생성된 영문 메시지는 프로젝트에 새 커밋을 만들기 전에 한국어로 정리합니다.

## 변경 완료 시 확인

1. 변경한 Python의 문법과 설명 주석·docstring의 한국어 여부를 확인합니다.
2. 인자·반환·예외 설명과 실제 코드의 일치를 확인합니다. 기존 Google·NumPy 형식을 보존합니다.
3. 실행 코드가 바뀌면 해당 회귀를 실행하고 결과와 미검증 범위를 남깁니다. 주석만 고친 파일은 실행 동작 변경 여부를 대조합니다.
4. [프로젝트 사례](../cases/README.md)와 기준 문서·CHANGELOG를 갱신하고, 한국어 커밋 메시지로 반영합니다.

현재 이 규칙은 작업 지침과 검토 기준입니다. 커밋 훅·CI의 한국어 자동 강제 검사는 아직 구성되어 있지 않습니다.
