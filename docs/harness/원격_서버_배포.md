# 원격 서버 배포와 운영 (navy2025)

[프로젝트 소개](../../README.md) · [서버·API 안내](../../src/README.md) · [네이티브 운영](네이티브_운영.md) · [스크립트 안내](../../scripts/README.md) · [CASE-117](../cases/사례-117-시민·담당자-사이트-분리와-원격-서버-배포-2026-11-21.md)

Ubuntu 서버에 민원 웹을 올려 쓰는 절차입니다. 개발과 배포는 **`main` 브랜치** 기준입니다. 접속 정보는 저장소에 두지 않고 사용자 PC의 접속용 배치 파일(`navy2025-ssh.bat`)에서만 읽습니다.

## 구성

| 항목 | 내용 |
| --- | --- |
| 위치 | `~/ai-complaint-process` (Git 저장소가 아니라 `git archive` 결과를 풉니다. 배포 커밋은 `.deploy-rev`) |
| Python | `uv`로 설치한 3.12 → `~/.local/bin/python3.12`, 가상환경 `.venv`(검색)·`.venv-web`(웹) |
| DB | 시스템 PostgreSQL 18 + pgvector, `complaints_native` (`complaint_rag`·`complaint_app`), 소켓 peer 인증 |
| 서비스 | systemd **사용자** 서비스 `cheongju-rag`(:8007)·`cheongju-web`(:5000)·`cheongju-lab`(:5010), linger 켜짐 |
| 바인딩 | 모두 `127.0.0.1`. 외부에서는 SSH 터널로만 접근 |
| 시민 / 담당자 | 같은 `:5000` 프로세스의 `/` (시민) · `/staff/` (담당자). 세션 쿠키는 `cj_citizen`·`cj_staff`로 분리 |
| 운영 설정 | `~/.config/cheongju/web.env`(`COMPLAINT_DEMO_LOGIN=0`), 계정 비밀번호는 `~/.config/cheongju/accounts.txt`(권한 600) |

## 배포

```powershell
# 저장소 루트(Windows). main 브랜치의 커밋된 내용을 올립니다.
powershell -File scripts/ops/deploy-remote.ps1
```

1. 이전 배포 목록(`.deploy-manifest`)의 파일만 지웁니다. 가상환경·모델 캐시·업로드·`.env`는 보존됩니다.
2. `git archive main`을 SSH로 전송해 풀고 새 목록·`.deploy-rev`를 기록합니다.
3. `cheongju-rag` → `cheongju-web`·`cheongju-lab` 순으로 재시작하고 헬스·두 화면(`/`, `/staff/`)을 확인합니다.

`-Branch`, `-RemoteDir`, `-SkipRestart`로 조정합니다. 커밋하지 않은 변경은 올라가지 않습니다.

## 최초 설치 (이미 완료)

`setup.sh`가 쓰는 `python3.12`가 apt에 없어 `uv`로 설치했습니다. 설치 순서는 `python3-venv` → `uv` → Python 3.12 → `postgresql-18`·`postgresql-18-pgvector` → `./setup.sh` → `python -m rag ingest`(5,109건, 약 3분) → 사용자 서비스 등록입니다.

## 운영 계정

```bash
# 서버에서. 비밀번호는 인자가 아니라 환경변수 또는 숨김 프롬프트로 받습니다.
cd ~/ai-complaint-process && export PGHOST=/var/run/postgresql PGDATABASE=complaints_native PGUSER=$(id -un)
COMPLAINT_NEW_PASSWORD='새비밀번호8자이상' .venv-web/bin/python -m flask --app src:create_app create-staff --login-id staff_kim --name "김담당" --department "서원구 건설과"
.venv-web/bin/python -m flask --app src:create_app reset-password --login-id staff_admin     # 프롬프트로 입력
.venv-web/bin/python -m flask --app src:create_app deactivate-user --login-id staff_kim
.venv-web/bin/python -m flask --app src:create_app list-users
```

- `--department`를 비우면 전 부서를 다루는 총괄 담당자입니다. 부서는 현행 부서 디렉터리에 있어야 합니다.
- 시연 계정(`citizen-demo`·`staff-demo`)은 변경할 수 없습니다. 비활성 계정은 로그인과 기존 세션이 모두 거부됩니다.
- 시드 계정 비밀번호를 다시 발급하려면 `bash scripts/ops/remote/harden-web.sh --rotate`를 서버에서 실행합니다.

## 접속

서버 포트는 외부에 열려 있지 않습니다. 접속용 배치 파일에 터널 옵션을 붙여 실행합니다.

```bat
navy2025-ssh.bat -N -L 5000:127.0.0.1:5000 -L 5010:127.0.0.1:5010
```

그 뒤 `http://127.0.0.1:5000/`(시민), `http://127.0.0.1:5000/staff/`(담당자), `http://127.0.0.1:5010/`(응대 검사기)로 접속합니다.

## 점검

```bash
bash scripts/ops/remote/verify-sites.sh        # 사이트 분리·로그인 경계를 상태 코드로 검증(비밀번호 비출력)
systemctl --user status cheongju-rag cheongju-web cheongju-lab   # 비로그인 SSH는 XDG_RUNTIME_DIR=/run/user/$(id -u) 필요
```

## 한계

- 응대 검사기(`:5010`)는 로그인이 없습니다. 터널로만 접근하는 것을 전제로 하며 외부에 노출하지 않습니다.
- LLM 키(`EXAONE_API_KEY` 등)는 서버에 두지 않았습니다. `/health`의 `assistLlm`이 `false`이면 AI 응답은 담당자 검토로 넘어갑니다.
- Swagger 포털(`/docs`)은 사이트 세션이 아니라 기존 단일 쿠키(`session`)를 씁니다.
- 외부 도메인·TLS·역프록시는 구성하지 않았습니다. 외부 공개 시 `SESSION_COOKIE_SECURE` 설정과 함께 별도로 구성해야 합니다.
- 다중 프로세스로 나누면 SSE 이벤트가 프로세스 사이로 전달되지 않습니다(이벤트 브로커 미구현).
