# 청주톡톡 웹 UI

시민 사이트와 담당자 업무 포털을 연결한 **Flask 서버 기반 시연 UI**다. 서버 소스는 프로젝트 루트의 [`src/`](../src/README.md)에 있다. 민원 CRUD는 `src/complaints`, 검사기 응대는 `src/assist`가 `src/rag`와 `src/llm`을 잇는다. [프로젝트 소개](../README.md)·[통합 설계](../plan/민원_웹_MVP_상세설계와_분야별_작업계획.md)·`예시 html/`의 흐름을 참고했다. 예시 원본은 보존한다.

2026-10-31 시민 화면은 사용자가 지정한 예시 HTML의 디자인에 맞춰 파랑·남색, 원본 CI 이미지, 소식 카드, 가로 서비스 메뉴, 모바일 하단 5개 메뉴와 접수 버튼으로 개편했다. 후속 요청에 따라 헤더는 **왼쪽 청주시 로고 + ‘민원톡톡’**으로 정리했으며 이름의 ‘톡톡’은 파란색으로 강조한다. 소식·안내는 바텀시트로 열리며, 서비스 선택 → 시연 상담 → 원문 보완 → 서버 등록으로 이어진다. [CASE-015](../docs/cases/사례-015-예시-시민-화면-디자인과-효과-반영-2026-10-31.md)

담당자 사이트는 같은 예시 HTML의 **민원과** 구성을 반영했다. 남색 업무 사이드바·상단 상태바, 접수/검토/초안/게시 요약, 필터 칩과 민원 행 목록, 처리 단계·금색 검토 참고 카드·답변 편집기를 제공한다. 화면의 건수·담당·초안·게시 상태는 서버 자료를 사용하며, 예시에만 있는 신뢰도·법정기한·전화 감소율·감사 로그는 생성하지 않는다. [CASE-017](../docs/cases/사례-017-민원과-담당자-화면-디자인-개편-2026-10-31.md)

## 실행

[서버 설치 안내](../src/README.md)에 따라 Python 3.12의 `.venv-web` 환경과 의존성을 준비한 뒤 저장소 루트에서 실행한다. Docker는 필요 없다.

```powershell
.\.venv-web\Scripts\python.exe -m src
```

Windows에서는 저장소 루트의 [`웹-시작.cmd`](../웹-시작.cmd)를 실행하면 Flask 서버를 별도 창에서 시작하고, 준비가 끝나면 기본 브라우저의 응대 검사기를 연다. `llm` 브랜치의 기본 화면은 검사기다.

- 응대 검사기: http://127.0.0.1:5000/#/lab
- 시민·담당자 해시(`/citizen`, `/staff`)는 이 브랜치에서 `/lab`으로 보낸다.
- Swagger: http://127.0.0.1:5000/docs · 인쇄본 [Swagger PDF](../docs/청주톡톡_민원_업무_API_Swagger.pdf)
- Node.js가 있으면 `npm --prefix ui run dev`도 같은 Flask 서버를 실행한다.
- 포트 변경은 `$env:COMPLAINT_PORT = '5001'`을 설정한다.
- `index.html`을 직접 열지 않고 Flask 주소로 접속한다.

## 구현한 화면과 연결

| 사이트 | 기능 |
| --- | --- |
| 시민 | 홈·분야별 작성 진입, 게시판·검색·지역/분야/상태 필터·페이지, 내 민원, 작성·수정·철회·임시 입력 저장, 상세·게시 답변·처리 이력, 추가 문의·재검토·이용 안내 |
| 담당자 | 접수·검토 업무 큐, 실제 건수 요약·분야별 검토 현황, 제목·지역·분야·담당·초안·추가 문의·시연 실패·게시 필터, 담당 지정, 답변 초안 저장·재열기·원문/이력 비교·미리보기·게시·철회 |
| AI 시연 | 고정 상담 응답과 작성 연결, 서버에 저장한 시연 단계·재실행·취소·이력. 시민 챗봇은 실제 LLM 미연동 |
| 응대 검사기 | `/#/lab`. 시민 직접 작성 양식, 짧은 실시간 진행 안내, 안내 결과와 처리 사유. 민원 CRUD와 분리 |
| 공통 | 반응형 화면, 레이블·키보드 초점·상태 안내, 빈 결과·서버 로딩·연결/저장 실패·중복 제출 처리 |

시민 하단의 **홈·나의 민원·접수·알림·내 정보**를 연결했다. 알림은 실제 서버에서 게시한 본인 민원 답변을 모아 보여 주며 문자 발송을 뜻하지 않는다. 첫 방문 인사, 카드·말풍선 등장, 상담 입력 중 점, 바텀시트, 호버·누름, 실제 등록 성공 확인 효과를 적용했다. `prefers-reduced-motion` 설정에서는 모션을 줄인다. 예시의 배정 신뢰도·가짜 진행률·자동 종결·자동 마스킹·문자 발송은 복사하지 않는다.

시민·담당자 헤더의 해·달 버튼으로 라이트/다크 테마를 바꾸며, 선택은 같은 브라우저의 두 사이트에서 공유하고 새로고침 뒤에도 유지한다.

자주 찾는 서비스의 12개 버튼은 이모지 대신 직접 제작한 SVG를 사용한다. 도안은 `src/service-icons.js`, 개별 재사용 SVG 파일과 갱신 방법은 [서비스 아이콘](assets/service-icons/README.md)에 있다. 홈의 가로 메뉴와 서비스 전체보기는 같은 도안을 공유한다.

업무 저장은 Flask API만 사용하고 PostgreSQL `complaint_app`에 영속화한다. UI 전체 스냅샷은 소규모 시연용이며 일반 목록 API는 서버 검색·필터·페이지를 지원한다. 합성 민원 24건은 서버의 `seed-demo` 명령을 명시적으로 실행할 때 비어 있는 DB에만 생성한다.

## 저장·역할·게시 경계

- 기존 `localStorage`의 `cheongju-ui-v1` 자료를 삭제하거나 서버로 자동 업로드하지 않는다. 새 업무 자료를 브라우저에 지속 저장하지 않는다. 작성 전 임시 입력만 `sessionStorage`를 사용한다.
- 시연 역할 선택은 서버 서명 세션 쿠키를 설정한다. 서버가 역할·작성자·공개 범위를 검사하며 시민 응답에서는 담당자 초안·AI 원본·후보·내부 작업·편집 이력을 제거한다.
- 같은 브라우저 탭은 세션을 공유한다. 다른 탭에서 역할을 바꾸면 현재 화면을 다시 불러온다. 역할이 맞지 않는 응답은 기존 캐시에 적용하지 않는다.
- 원문·추가 문의·철회·게시 변경은 서버 맥락 버전을 올린다. 재실행 후보는 별도로 보존하고 사람이 작성 중인 답변·게시본을 자동 교체하지 않는다.
- 서버가 트랜잭션에서 기대 버전을 검사한다. 충돌은 409로 거부하며 UI는 입력을 보존한다. 등록 재전송은 같은 멱등성 키로 중복을 방지한다.
- 단계 시연 이벤트·시작 시각은 서버에 저장하며 UI가 1.5초마다 조회한다. 실제 추론·작업자·SSE와 구별한다. AI 성공을 답변 게시·민원 해결 완료로 표시하지 않는다.
- 연결 실패를 브라우저 저장 성공으로 대체하거나 기존 업무 DB를 초기화하지 않는다. 실제 행정 접수·이관을 수행하지 않는다.

**남은 범위:** 운영 본인·담당자 인증, PostgreSQL 업무 스키마·마이그레이션, 실제 AI·작업자·SSE, 첨부 업로드, 공식 접수·외부 이관, 운영 배포. 상단 역할 선택은 로컬 시연용이며 운영 계정 인증이 아니다.
