# 청주톡톡 웹 UI

시민 사이트와 담당자 업무 포털을 연결한 **Flask 서버 기반 시연 UI**다. 서버 소스는 프로젝트 루트의 [`src/`](../src/README.md)에 있다. 민원 CRUD는 `src/complaints`, 검사기 응대는 `src/assist`가 `src/search_client`와 `src/llm`을 잇는다. [프로젝트 소개](../README.md)·[통합 설계](../docs/plans/민원_웹_MVP_상세설계와_분야별_작업계획.md)·`예시 html/`의 흐름을 참고했다. 예시 원본은 보존한다.

2026-10-31 시민 화면은 사용자가 지정한 예시 HTML의 디자인에 맞춰 파랑·남색, 원본 CI 이미지, 소식 카드, 가로 서비스 메뉴, 모바일 하단 5개 메뉴와 접수 버튼으로 개편했다. 후속 요청에 따라 헤더는 **왼쪽 청주시 로고 + ‘청주톡톡’**(2026-11-23 서비스 이름을 ‘민원톡톡’에서 ‘청주톡톡’으로 통일, CASE-132)으로 정리했으며 이름의 ‘톡톡’은 파란색으로 강조한다. 소식·안내는 바텀시트로 열리며, 서비스 선택 → 시연 상담 → 원문 보완 → 서버 등록으로 이어진다. [CASE-015](../docs/cases/사례-015-예시-시민-화면-디자인과-효과-반영-2026-10-31.md)

담당자 사이트는 같은 예시 HTML의 **민원과** 구성을 반영했다. 남색 업무 사이드바·상단 상태바, 접수/검토/초안/게시 요약, 필터 칩과 민원 행 목록, 처리 단계·금색 검토 참고 카드·답변 편집기를 제공한다. 화면의 건수·담당·초안·게시 상태는 서버 자료를 사용하며, 예시에만 있는 신뢰도·법정기한·전화 감소율·감사 로그는 생성하지 않는다. [CASE-017](../docs/cases/사례-017-민원과-담당자-화면-디자인-개편-2026-10-31.md)

## 실행

[서버 설치 안내](../src/README.md)에 따라 Python 3.12의 `.venv-web` 환경과 의존성을 준비한 뒤 저장소 루트에서 실행한다. Docker는 필요 없다.

```powershell
.\.venv-web\Scripts\python.exe -m src
```

Windows에서는 저장소 루트의 [`bin/start-web.cmd`](../bin/start-web.cmd) 또는 [`bin/start-lab.cmd`](../bin/start-lab.cmd)를 실행하면 추출한 응대 검사기(`:5010`)를 연다. 민원 웹(`python -m src`, `:5000`) SPA의 기본 화면은 시민 화면(`#/citizen`)이며, `/#/lab` 해시와 `/design/ui04` 목업도 제공한다.

- 추출한 응대 검사기 웹: http://127.0.0.1:5010/
- 시민·담당자 민원 웹 (기본): http://127.0.0.1:5000/#/citizen
- ui04 목업 + 서버 어댑터: http://127.0.0.1:5000/design/ui04
- 기존 SPA 검사기: http://127.0.0.1:5000/#/lab
- Swagger: http://127.0.0.1:5000/docs · 인쇄본 [Swagger PDF](../docs/api/청주톡톡_민원_업무_API_Swagger.pdf)
- Node.js가 있으면 `npm --prefix ui run dev`도 같은 Flask 서버를 실행한다.
- 포트 변경은 `$env:COMPLAINT_PORT = '5001'`을 설정한다.
- `index.html`을 직접 열지 않고 Flask 주소로 접속한다.

시민 하단의 **홈·나의 민원·접수·알림·내 정보**를 연결했다. 알림은 실제 서버에서 게시한 본인 민원 답변을 모아 보여 주며 문자 발송을 뜻하지 않는다. 첫 방문 인사, 카드·말풍선 등장, 상담 입력 중 점, 바텀시트, 호버·누름, 실제 등록 성공 확인 효과를 적용했다. `prefers-reduced-motion` 설정에서는 모션을 줄인다. 예시의 배정 신뢰도·가짜 진행률·자동 종결·자동 마스킹·문자 발송은 복사하지 않는다.

시민·담당자 헤더의 해·달 버튼으로 라이트/다크 테마를 바꾸며, 선택은 같은 브라우저의 두 사이트에서 공유하고 새로고침 뒤에도 유지한다.

자주 찾는 서비스의 12개 버튼은 이모지 대신 직접 제작한 SVG를 사용한다. 도안은 `src/service-icons.js`, 개별 재사용 SVG 파일과 갱신 방법은 [서비스 아이콘](assets/service-icons/README.md)에 있다. 홈의 가로 메뉴와 서비스 전체보기는 같은 도안을 공유한다.

업무 저장은 Flask API만 사용하고 PostgreSQL `complaint_app`에 영속화한다. UI 전체 스냅샷은 소규모 시연용이며 일반 목록 API는 서버 검색·필터·페이지를 지원한다. 합성 민원 24건은 `seed-demo` 명령으로, 마스킹된 공개 시연 민원 56건은 `seed-public-demo` 명령으로 비어 있는 DB에 생성한다. UI04 목업(`minwon-toktok-ui04.html`)은 `/design/ui04` 경로에서 `ui04-adapter.js`로 `/api/v1`에 연결한다.

## 저장·역할·게시 경계

- 기존 `localStorage`의 `cheongju-ui-v1` 자료를 삭제하거나 서버로 자동 업로드하지 않는다. 새 업무 자료를 브라우저에 지속 저장하지 않는다. 작성 전 임시 입력만 `sessionStorage`를 사용한다.
- 시연 역할 선택은 서버 서명 세션 쿠키를 설정한다. 서버가 역할·작성자·공개 범위를 검사하며 시민 응답에서는 담당자 초안·AI 원본·후보·내부 작업·편집 이력을 제거한다.
- 같은 브라우저 탭은 세션을 공유한다. 다른 탭에서 역할을 바꾸면 현재 화면을 다시 불러온다. 역할이 맞지 않는 응답은 기존 캐시에 적용하지 않는다.
- 원문·추가 문의·철회·게시 변경은 서버 맥락 버전을 올린다. 재실행 후보는 별도로 보존하고 사람이 작성 중인 답변·게시본을 자동 교체하지 않는다.
- 서버가 트랜잭션에서 기대 버전을 검사한다. 충돌은 409로 거부하며 UI는 입력을 보존한다. 등록 재전송은 같은 멱등성 키로 중복을 방지한다.
- AI 진행 단계·시작 시각은 백그라운드 워커가 서버 메모리와 담당자 SSE 브로커(`GET /api/v1/staff/events`)로 실시간 푸시하고 완료 시 DB에 커밋하며, SSE 단절 시 UI가 3초 폴링으로 자동 전환합니다(`realtime.js`). AI 성공을 답변 게시·민원 해결 완료로 표시하지 않으며, 이미 작성된 초안을 덮어쓰지 않습니다. [CASE-093](../docs/cases/사례-093-민원웹-CRUD-검사기-LLM-RAG-실시간통합-2026-11-15.md) · [CASE-110](../docs/cases/사례-110-담당자-실시간-SSE-푸시와-시민-AI-챗봇-실연결-구현-2026-11-20.md)
- 연결 실패를 브라우저 저장 성공으로 대체하거나 기존 업무 DB를 초기화하지 않는다. 실제 행정 접수·이관을 수행하지 않는다.

**남은 범위:** 외부 이동통신사 PASS/행정 SSO 연동, 다중 워커 이벤트 브로커(Redis/PG · 현 단계 제외), 멀티모달 이미지 분석, 공식 접수·외부 이관, 운영 배포. 상단 역할 선택은 로컬 시연 편의용이며, 실계정 로그인(`auth.js` 모달) 후에는 새로고침·이동 시에도 실계정 세션이 시연 세션으로 덮이지 않고 유지됩니다.

## 시민·담당자 화면 분리 (`CASE-117`)

| 진입 화면 | 주소 | 허용 해시 경로 | 로그인 |
| --- | --- | --- | --- |
| [`index.html`](index.html) | `/` | `#/citizen*` | 민원인 |
| [`staff.html`](staff.html) | `/staff/` | `#/staff*`, 응대 검사기 `#/lab` | 담당자 |

- 두 HTML은 `<html data-site="citizen|staff">`로 사이트를 선언하고 [`src/site.js`](src/site.js)가 요청 헤더(`X-Cheongju-Site`)와 허용 경로를 결정한다. 다른 사이트의 해시로 들어오면 현재 사이트 홈으로 교정한다.
- 시민 화면에는 `staff.css`·`lab.css`를 싣지 않는다. 사이트 사이의 이동 링크와 기본 계정 안내는 없다.
- `app.js`(공유 엔진)와 화면 모듈은 두 사이트가 함께 쓴다. 파일 단위 번들 분할은 하지 않았다.

## 방문자·게스트 모드 (`CASE-119`)

- 비로그인 방문자도 시민 사이트의 홈·민원 작성·AI 도우미·소식·서비스·이용 안내를 본다. "나의 민원·게시판·알림·내 정보·상세"는 로그인·게스트 접수 안내(`citizenVisitorGate`)로 대신한다.
- 민원을 접수하거나 AI 도우미 메시지를 보내는 순간 `ensureGuestSession()`이 게스트 세션을 시작한다. 게스트 접수는 공개로만 받으며(2026-11-22 변경, 작성 폼에 개인정보 주의 안내), 접수 후 상세에 게스트 안내가 나온다.
- 로그인 모달은 탭이 하나뿐이면 탭 막대를 그리지 않고 제출 버튼은 "로그인"이다. `isRealAccount(actor)`는 시연·게스트·방문자를 실계정과 구별한다.

## 접근성 보정 (`CASE-121`)

- 글자 대비는 라이트·다크 × 1280·390px에서 측정해 미달 0을 유지한다. 보조 글자색은 `--muted`(시민·담당자 `#5f6b82`)를 쓰고, 새 연한 회색 글자를 직접 쓰지 않는다. `tests/a11y.test.mjs`가 토큰 대비를 검사한다.
- 홈의 질문·접수 입력창은 `design.css`에서 인사말 바로 아래로 보이는 순서를 바꿨다(마크업 순서는 그대로). 작은 화면에서도 헤더에 로그인 버튼이 보인다.

## 디자인 토큰과 동적 효과 (`CASE-120`)

- [`src/tokens.css`](src/tokens.css): 색·상태 5색·모서리 4단계·그림자 3단계·간격·모션(120/220/420ms) 토큰. 기존 `--teal` 등은 이 토큰에 연결돼 있다. 모든 글자·배경 조합의 대비는 `tests/tokens.test.mjs`가 검사한다.
- [`src/design.css`](src/design.css): 상태 칩(`.badge.*`)과 출처 태그(`.origin-badge`)의 **유일한 색 정의**와 모션 규칙. 다른 CSS에 상태 칩 색을 다시 정의하지 않는다(테스트가 막는다).
- [`src/motion.js`](src/motion.js): 숫자 카운트업(`data-countup`·`data-ck`), 경로 전환 시 진입 효과, 새 민원 행 플래시(`row-flash`). 화면이 실시간으로 통째로 다시 그려져도 반복 재생되지 않는다.
- 제목 3종(페이지·섹션·눈썹)의 글자 규격은 `tokens.css`의 `--ty-*`와 `design.css`의 블록 공통 규칙에서만 정의한다. 다른 CSS에서 `font-size` 등을 다시 쓰면 테스트가 막는다.
- 모든 움직임은 운영체제의 "동작 줄이기"를 켜면 꺼진다. 새 CSS를 고칠 때는 `tests/css-integrity.test.mjs`(괄호·선택자 무결성)를 통과해야 한다.
